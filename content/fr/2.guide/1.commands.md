## Vue d'ensemble

Les commandes dans glyria.js sont basées sur les fichiers. Chaque fichier présent dans `src/commands/` est automatiquement chargé et enregistré sur Discord au démarrage — aucune inscription manuelle nécessaire.

Chaque fichier de commande exporte une instance de commande par défaut :

```ts
// src/commands/ping.ts
export default new GlyriaCommand()
  .setName("ping")
  .setDescription("Pong!")
  .execute(async (ctx) => {
    await ctx.g.reply.success("Pong!")
  })
```

::tip{title="Auto-import"}
`GlyriaCommand`, `GlyriaUserCommand` et `GlyriaMessageCommand` sont disponibles globalement — aucun import nécessaire.
::

## Contexte automatique

Les handlers reçoivent l'interaction déjà enveloppée. `ctx` **est** la `ChatInputCommandInteraction` — chaque méthode discord.js fonctionne comme d'habitude — plus une propriété `ctx.g` avec réponses stylisées, confirmations, pagination, le store intégré et plus encore :

```ts
export default new GlyriaCommand()
  .setName("ping")
  .setDescription("Pong!")
  .execute(async (ctx) => {
    // le discord.js classique fonctionne toujours :
    // await ctx.reply({ content: "Pong!" })

    // le one-liner glyria :
    await ctx.g.reply.success("Pong!")
  })
```

Aucun appel manuel à `createReplyableContext` nécessaire — le framework enveloppe l'interaction avant d'invoquer votre handler. Voir le [guide Replyable Context](/guide/replyable-context) pour tout ce que `ctx.g` peut faire.

## Commandes slash

### Options

Ajoutez des options typées à votre commande avec les méthodes `add*Option` :

```ts
export default new GlyriaCommand()
  .setName("hello")
  .setDescription("Say hello to someone")
  .addUserOption((option) =>
    option
      .setName("user")
      .setDescription("The user to greet")
      .setRequired(true)
  )
  .addStringOption((option) =>
    option
      .setName("message")
      .setDescription("A custom message")
      .setRequired(false)
  )
  .execute(async (ctx) => {
    await ctx.reply({ content: "Hello!" })
  })
```

#### Types d'options disponibles

| Méthode            | Type             |
| ------------------ | ---------------- |
| `addStringOption`  | Saisie de texte  |
| `addIntegerOption` | Nombre entier    |
| `addNumberOption`  | Nombre décimal   |
| `addBooleanOption` | Vrai / Faux      |
| `addUserOption`    | Utilisateur Discord |
| `addRoleOption`    | Rôle Discord     |

Chaque option expose :

| Méthode                 | Description                              |
| ----------------------- | ---------------------------------------- |
| `.setName(name)`        | Nom de l'option (minuscules, sans espaces) |
| `.setDescription(desc)` | Description de l'option                  |
| `.setRequired(bool)`    | Si l'option est requise                  |

### Sous-commandes

Regroupez des actions liées sous une seule commande avec `.addSubCommand()` :

```ts
export default new GlyriaCommand()
  .setName("moderation")
  .setDescription("Moderation commands")
  .addSubCommand((cmd) =>
    cmd
      .setName("ban")
      .setDescription("Ban a user")
      .addUserOption((option) =>
        option
          .setName("user")
          .setDescription("User to ban")
          .setRequired(true)
      )
      .addStringOption((option) =>
        option
          .setName("reason")
          .setDescription("Reason of the ban")
          .setRequired(false)
      )
      .execute(async (ctx) => {
        // gérer le ban
      })
  )
  .execute(async (ctx) => {
    // gérer la commande de base
  })
```

### Groupes de sous-commandes

Pour une organisation plus profonde, regroupez les sous-commandes avec `.addSubCommandGroup()` :

```ts
export default new GlyriaCommand()
  .setName("moderation")
  .setDescription("Moderation commands")
  .addSubCommand((cmd) =>
    cmd
      .setName("ban")
      .setDescription("Ban a user")
      .addUserOption((option) =>
        option
          .setName("user")
          .setDescription("User to ban")
          .setRequired(true)
      )
      .addStringOption((option) =>
        option
          .setName("reason")
          .setDescription("Reason of the ban")
          .setRequired(false)
      )
      .execute((ctx) => {
        console.log("ban command")
      })
  )
  .addSubCommandGroup((group) =>
    group
      .setName("config")
      .setDescription("Configuration commands")
      .addSubCommand((cmd) =>
        cmd
          .setName("logs")
          .setDescription("Configure logs")
          .addBooleanOption((option) =>
            option
              .setName("enabled")
              .setDescription("Enable logs")
              .setRequired(true)
          )
          .execute(async (ctx) => {
            // gérer la config des logs
          })
      )
  )
  .execute((ctx) => {
    ctx.reply({ content: "Moderation command executed!" })
  })
```

Cela génère la structure de commande Discord suivante :

```text
/moderation ban <user> [reason]
/moderation config logs <enabled>
```

## Menus contextuels

Les menus contextuels apparaissent lorsqu'un utilisateur fait un clic droit sur un utilisateur ou un message, dans la section **Apps**. Ils n'ont ni description, ni options, ni sous-commandes.

### Menu contextuel utilisateur

Déclenché par un clic droit sur un utilisateur. Le handler reçoit une `UserContextMenuCommandInteraction` — l'utilisateur ciblé est disponible via `ctx.targetUser`.

```ts
// src/commands/profile.ts
export default new GlyriaUserCommand()
  .setName("View profile")
  .execute(async (ctx) => {
    const user = ctx.targetUser
    await ctx.g.reply.info(`Profile of ${user.username}`).ephemeral()
  })
```

### Menu contextuel de message

Déclenché par un clic droit sur un message. Le handler reçoit une `MessageContextMenuCommandInteraction` — le message ciblé est disponible via `ctx.targetMessage`.

```ts
// src/commands/translate.ts
export default new GlyriaMessageCommand()
  .setName("Translate")
  .execute(async (ctx) => {
    const message = ctx.targetMessage
    await ctx.g.reply.info(`Translating: "${message.content}"`).ephemeral()
  })
```

## Cooldowns déclaratifs

Limitez n'importe quelle commande avec `.setCooldown()`. Une simple chaîne de durée applique un cooldown **par utilisateur** :

```ts
export default new GlyriaCommand()
  .setName("daily")
  .setDescription("Claim your daily reward")
  .setCooldown("5s")
  .execute(async (ctx) => {
    await ctx.g.reply.success("Reward claimed!")
  })
```

Passez un objet pour combiner les portées :

```ts
.setCooldown({ user: "5s", guild: "2s", global: "1s" })
```

| Portée | S'applique à |
|---|---|
| `user` | L'utilisateur qui invoque la commande |
| `guild` | Tout le monde dans le serveur courant |
| `global` | Tout le monde, partout |

Les durées acceptent les suffixes `ms`, `s`, `m`, `h`, `d` (`"500ms"`, `"5s"`, `"2m"`, `"1h"`, `"1d"`) ou un nombre brut de millisecondes.

`.setCooldown()` est disponible sur `GlyriaCommand`, `GlyriaSubCommand`, `GlyriaUserCommand` et `GlyriaMessageCommand`. Un cooldown défini sur une sous-commande remplace celui de la commande parente pour cette sous-commande.

Quand un utilisateur est en cooldown, glyria refuse l'exécution avec une erreur éphémère stylisée indiquant le temps restant :

> ❌ You're on cooldown — try again in **3s**.

::tip{title="Les guards s'exécutent dans l'ordre"}
Le cooldown n'est consommé qu'une fois tous les autres guards passés — une exécution refusée par `setOwnerOnly()` ou `setPermissions()` ne déclenche jamais de cooldown.
::

## Permissions déclaratives

Passez des noms de permissions à `.setPermissions()` et glyria fait deux choses :

1. Définit `default_member_permissions` côté Discord, pour que la commande soit masquée aux membres qui ne les ont pas.
2. Vérifie à l'exécution les permissions de l'invoquant et refuse avec une erreur éphémère stylisée listant ce qui manque.

```ts
export default new GlyriaCommand()
  .setName("ban")
  .setDescription("Ban a user")
  .setPermissions(["BanMembers"])
  .execute(async (ctx) => {
    // seuls les membres avec Ban Members peuvent exécuter ceci
  })
```

> ❌ You need the following permission(s) to use this command: **Ban Members**

Les noms de permissions sont les clés de `PermissionFlagsBits` de discord.js (`"BanMembers"`, `"ManageGuild"`, `"Administrator"`, ...), entièrement typés.

::note{title="Forme legacy"}
La forme bitfield brute fonctionne toujours — `setPermissions(8n)` définit uniquement `default_member_permissions`, sans la vérification à l'exécution.
::

### Commandes réservées au propriétaire

`.setOwnerOnly()` restreint une commande au propriétaire de l'application. Le propriétaire est résolu depuis l'application Discord — les bots appartenant à une **Team** acceptent chaque membre de l'équipe.

```ts
export default new GlyriaCommand()
  .setName("eval")
  .setDescription("Owner only")
  .setOwnerOnly()
  .execute(async (ctx) => {
    // seul le propriétaire du bot (ou les membres de la team) arrive ici
  })
```

## Autocomplétion typée

Attachez un handler d'autocomplétion directement sur l'option avec `.setAutocomplete()` — pas de fichier de handler séparé :

```ts
export default new GlyriaCommand()
  .setName("play")
  .setDescription("Play a song")
  .addStringOption((o) =>
    o
      .setName("query")
      .setDescription("Song to search")
      .setAutocomplete(async (query, interaction) => {
        const results = await searchSongs(query)
        return results.map((song) => ({ name: song.title, value: song.id }))
      })
  )
  .execute(async (ctx) => {
    const id = ctx.options.getString("query", true)
    // ...
  })
```

Le handler reçoit la chaîne `query` courante et l'`AutocompleteInteraction` brute, et retourne des choix sous l'une de ces trois formes :

| Retour | Envoyé à Discord comme |
|---|---|
| `"rock"` | `{ name: "rock", value: "rock" }` |
| `42` | `{ name: "42", value: 42 }` |
| `{ name: "Rock", value: "genre_rock" }` | tel quel |

Au maximum **25** choix sont envoyés (les surnuméraires sont ignorés). `.setAutocomplete()` est disponible sur les options string, integer et number — y compris dans les sous-commandes et les groupes de sous-commandes.

## Métadonnées

Attachez des données personnalisées à une commande avec `.setMetaData()`. Fonctionne sur `GlyriaCommand`, `GlyriaUserCommand` et `GlyriaMessageCommand`. Glyria les stocke telles quelles et ne les interprète jamais — c'est entièrement à vous de décider.

```ts
export default new GlyriaCommand()
  .setName("ban")
  .setDescription("Ban a user")
  .setMetaData({
    category: "moderation",
    cooldown: 5000,
    premium: false,
    guildOnly: true,
  })
  .execute(async (ctx) => {
    // votre logique ici
  })
```

### useCommands()

`useCommands()` retourne la liste complète des commandes chargées avec leurs métadonnées. Elle est disponible globalement et reflète toujours l'état courant du bot.

```ts
const commands = useCommands()
// [
//   { name: "ban", description: "Ban a user", meta: { category: "moderation", cooldown: 5000 } },
//   { name: "ping", description: "Pong!", meta: {} },
//   { name: "View profile", description: "", meta: {} },
// ]
```

Un cas d'usage courant est la construction d'une commande `/help` organisée par catégorie :

```ts
export default new GlyriaCommand()
  .setName("help")
  .setDescription("List all commands")
  .execute(async (ctx) => {
    const commands = useCommands()

    const byCategory = commands.reduce((acc, cmd) => {
      const cat = (cmd.meta.category as string) ?? "general"
      acc[cat] ??= []
      acc[cat].push(cmd)
      return acc
    }, {} as Record<string, typeof commands>)

    // construisez votre embed à partir de byCategory
  })
```

## Organisation des fichiers

Les sous-dossiers de `src/commands/` servent uniquement à l'organisation — chaque fichier, quelle que soit sa profondeur, est chargé automatiquement.

```text
src/commands/
  ping.ts
  moderation/
    ban.ts
    kick.ts
  config/
    advanced/
      logs.ts
  context-menus/
    profile.ts
    translate.ts
```

::tip{title="Une commande par fichier"}
Gardez une instance de commande par fichier. Utilisez les sous-commandes et les groupes de sous-commandes pour regrouper des actions liées dans une `GlyriaCommand`.
::
