## Vue d'ensemble

Les composants dans glyria.js sont basés sur les fichiers, comme les commandes et les events. Chaque fichier dans `src/components/` est automatiquement chargé au démarrage — exportez un composant en `default`, ou plusieurs en exports nommés.

Un composant déclare un **pattern de customId** et un handler. Les placeholders entre `{accolades}` deviennent des params typés :

```ts
// src/components/vote.ts
export default new GlyriaButton("vote:{pollId}:{choice}")
  .execute(async (ctx, params) => {
    // params est inféré depuis le pattern : { pollId: string; choice: string }
    await registerVote(params.pollId, params.choice, ctx.user.id)
    await ctx.g.update.success(`Vote counted for **${params.choice}**!`)
  })
```

`ctx` est la `ButtonInteraction` enveloppée — `ctx.g.update.*` édite le message qui porte le bouton, `ctx.g.reply.*` en envoie un nouveau.

::tip{title="Auto-import"}
`GlyriaButton`, `GlyriaSelect` et `GlyriaModal` sont disponibles globalement — aucun import nécessaire.
::

## Params typés

Les types des params sont inférés au niveau des types depuis la chaîne du pattern (`PatternParams`). Renommez un placeholder et chaque accès `params.xxx` se met à jour — ou casse à la compilation :

```ts
new GlyriaButton("role_picker:{roleId}:{userId}")
  .execute(async (ctx, params) => {
    params.roleId // string ✅
    params.userId // string ✅
    params.other  // ❌ erreur de type
  })
```

::warning{title="Pas de deux-points dans les params"}
`:` est le séparateur du pattern — une valeur de param contenant `:` lève une erreur lors de la construction de l'id. Limitez les params à de simples ids (snowflakes, slugs, nombres).
::

## Rendre un composant

Appelez `.id({...})` sur le composant pour construire un customId concret au moment du rendu. Importez le composant depuis son fichier — le pattern reste défini en un seul endroit :

```ts
// src/components/vote.ts
export const voteButton = new GlyriaButton("vote:{pollId}:{choice}")
  .execute(async (ctx, params) => {
    await ctx.g.update.success(`Vote counted for **${params.choice}**!`)
  })
```

```ts
// src/commands/poll.ts
import { voteButton } from "../components/vote.js"

export default new GlyriaCommand()
  .setName("poll")
  .setDescription("Start a poll")
  .execute(async (ctx) => {
    const embed = new EmbedV2Builder()
      .container({ accentColor: 0x5865f2 })
      .textDisplay("**Tabs or spaces?**")
      .actionRow()
      .button({ label: "Tabs", customId: voteButton.id({ pollId: "42", choice: "tabs" }), style: "primary" })
      .button({ label: "Spaces", customId: voteButton.id({ pollId: "42", choice: "spaces" }), style: "secondary" })
      .end()
      .end()
      .build()

    await ctx.g.reply.raw(embed)
  })
```

`.id()` est lui aussi entièrement typé — les params manquants ou en trop sont des erreurs de compilation, et un param manquant à l'exécution lève une erreur mentionnant le nom du pattern.

## Selects et modals

Même API, type d'interaction différent :

```ts
// src/components/color-select.ts
export const colorSelect = new GlyriaSelect("color_select:{userId}")
  .execute(async (ctx, params) => {
    await ctx.g.update.success(`Color saved: ${ctx.values[0]}`)
  })

// src/components/feedback-modal.ts
export const feedbackModal = new GlyriaModal("feedback:{topic}")
  .execute(async (ctx, params) => {
    const text = ctx.fields.getTextInputValue("body")
    await ctx.g.reply.success(`Feedback on **${params.topic}** received!`).ephemeral()
  })
```

| Builder | Gère | Type de `ctx` |
|---|---|---|
| `GlyriaButton` | Clics de boutons | `ButtonInteraction` |
| `GlyriaSelect` | Tout menu de sélection | `AnySelectMenuInteraction` |
| `GlyriaModal` | Soumissions de modals | `ModalSubmitInteraction` |

## Règles de correspondance

- Chaque interaction est confrontée aux patterns chargés du même type ; le **premier** composant correspondant la gère.
- Les patterns sont ancrés : `"vote:{pollId}:{choice}"` correspond exactement à trois segments séparés par `:` commençant par `vote`.
- Les handlers lents bénéficient du même defer automatique que les commandes.

::warning{title="Préfixe réservé"}
Les customIds commençant par `glyria:` sont réservés au framework (les boutons de `ctx.g.confirm` et `ctx.g.paginate`). N'utilisez jamais ce préfixe dans vos propres patterns.
::

## Organisation des fichiers

Les sous-dossiers de `src/components/` servent uniquement à l'organisation. Les composants au sein des [modules](/guide/modules) vivent dans le dossier `components/` du module lui-même.

```text
src/components/
  vote.ts
  roles/
    picker.ts
  modals/
    feedback.ts
```

En dev (`glyria dev`), les fichiers de composants sont rechargés à chaud à la sauvegarde — aucun redémarrage nécessaire.
