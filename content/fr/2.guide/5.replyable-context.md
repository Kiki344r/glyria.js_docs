## Vue d'ensemble

glyria.js enveloppe chaque objet Discord répondable (interactions, messages) avec une propriété `g` avant l'exécution de votre handler. `ctx` reste l'objet discord.js brut — `ctx.g` y ajoute une boîte à outils de réponse complète :

```ts
export default new GlyriaCommand()
  .setName("ban")
  .setDescription("Ban a user")
  .execute(async (ctx) => {
    await ctx.g.reply.success("User banned successfully!")
  })
```

L'enveloppement est automatique dans les handlers de commandes, d'events et de composants — aucune configuration nécessaire.

## One-liners stylisés

Chaque variante construit un Embed V2 avec la couleur d'accentuation correspondante :

| Méthode | Couleur | Préfixe |
|---|---|---|
| `ctx.g.reply.primary(content)` | `#5865F2` (blurple) | aucun |
| `ctx.g.reply.secondary(content)` | `#4F545C` (gris) | aucun |
| `ctx.g.reply.success(content)` | `#57F287` (vert) | ✅ |
| `ctx.g.reply.warning(content)` | `#FEE75C` (jaune) | ⚠️ |
| `ctx.g.reply.error(content)` | `#ED4245` (rouge) | ❌ |
| `ctx.g.reply.info(content)` | `#5DADE2` (bleu) | ℹ️ |

Remplacez les couleurs du thème dans `glyria.config.ts` :

```ts
// glyria.config.ts
export default defineGlyriaConfig({
  theme: {
    embedV2: {
      primaryColor: "#7289DA",
      secondaryColor: "#747F8D",
      successColor: "#43B581",
      warningColor: "#FAA61A",
      errorColor: "#F04747",
      infoColor: "#00B0F4",
    },
  },
})
```

::tip{title="defineGlyriaConfig"}
Le helper de configuration est `defineGlyriaConfig` — auto-importé, entièrement typé. Les couleurs sont des chaînes hexadécimales ; glyria les convertit en interne.
::

## Chaînage fluide

Chaque envoi stylisé retourne une chaîne que vous pouvez enrichir avant l'envoi :

```ts
await ctx.g.reply
  .success("Backup complete")
  .description("All 3 databases were exported.")
  .field("Duration", "42s")
  .field("Size", "18 MB")
  .file(backupBuffer, "backup.zip")
  .ephemeral()
  .send()
```

| Méthode | Effet |
|---|---|
| `.description(text)` | Ajoute un bloc de texte sous le titre |
| `.field(name, value)` | Ajoute un bloc `**name**` + valeur |
| `.file(data, name)` | Attache un `Buffer` ou un chemin de fichier |
| `.ephemeral(bool?)` | Marque cette réponse comme éphémère (défaut `true`) |
| `.send()` | Envoie et retourne le message |

La chaîne est **thenable** — un simple `await` l'envoie, donc `.send()` est optionnel :

```ts
await ctx.g.reply.success("Done").field("Took", "3s")
```

## Routage intelligent

`ctx.g` choisit toujours le bon transport selon l'état courant de l'interaction — vous n'avez jamais à penser à `reply` vs `editReply` vs `followUp` :

| État | Envoyé via |
|---|---|
| Rien envoyé pour l'instant | `reply()` |
| Différé, rien envoyé pour l'instant | `editReply()` |
| Quelque chose a déjà été envoyé | `followUp()` |

```ts
.execute(async (ctx) => {
  await ctx.g.reply.info("Working on it...")   // → reply()
  await ctx.g.reply.success("First step done") // → followUp(), automatiquement
  await ctx.g.reply.success("All done")        // → followUp()
})
```

## Confirmations

`ctx.g.confirm()` envoie un message avec des boutons Confirmer/Annuler et se résout en booléen :

```ts
.execute(async (ctx) => {
  const confirmed = await ctx.g.confirm("Delete all 250 messages?", {
    timeout: "30s",
    confirmLabel: "Delete",
    cancelLabel: "Keep them",
    ephemeral: true,
  })

  if (!confirmed) return ctx.g.followUp.secondary("Cancelled.")
  // ... action destructrice
})
```

| Option | Défaut | Description |
|---|---|---|
| `timeout` | `"30s"` | Délai d'inactivité — se résout à `false` à expiration |
| `confirmLabel` | `"Confirm"` | Libellé du bouton vert |
| `cancelLabel` | `"Cancel"` | Libellé du bouton rouge |
| `ephemeral` | `false` | Envoyer la demande en éphémère |

Seul l'**utilisateur invoquant** peut cliquer sur les boutons — les clics des autres utilisateurs sont ignorés. Une fois résolue (clic ou timeout), les boutons sont désactivés.

## Pagination

`ctx.g.paginate()` transforme un tableau de chaînes en navigateur ◀ `1/N` ▶ :

```ts
.execute(async (ctx) => {
  const pages = chunks.map((c, i) => `**Page ${i + 1}**\n${c}`)
  await ctx.g.paginate(pages, { timeout: "2m" })
})
```

| Option | Défaut | Description |
|---|---|---|
| `timeout` | `"2m"` | Délai d'inactivité — les boutons sont désactivés à expiration |
| `ephemeral` | `false` | Envoyer les pages en éphémère |

Seul l'invoquant peut naviguer. Un tableau d'une seule page est envoyé sans boutons.

## Différer (defer)

Discord vous donne 3 secondes pour répondre à une interaction. glyria arme un **defer automatique** à ~1,5s : si votre handler n'a pas répondu d'ici là, il appelle `deferReply()` pour vous et votre `ctx.g.reply.*` ultérieur devient une édition — les handlers lents fonctionnent, tout simplement.

Différez manuellement quand vous savez que ce sera lent :

```ts
.execute(async (ctx) => {
  await ctx.g.defer() // ou ctx.g.defer({ ephemeral: true })
  const stats = await crunchNumbers() // prend 10s
  await ctx.g.reply.success(`Crunched ${stats.total} rows`)
})
```

`ctx.g.defer()` est un no-op si l'interaction est déjà différée ou répondue.

## États de chargement

`ctx.g.reply.loading()` affiche un message ⏳, attend votre promesse, puis édite le message en succès ou en erreur. Il se résout avec le résultat de la promesse (et relance l'erreur en cas d'échec) :

```ts
.execute(async (ctx) => {
  const results = await ctx.g.reply.loading("Searching...", searchApi(query), {
    done: (r) => `Found ${(r as Result[]).length} results`,
    fail: "The search service is down.",
  })
  // `results` est la valeur résolue de searchApi(query)
})
```

`done` et `fail` acceptent une chaîne ou une fonction du résultat/de l'erreur. Défauts : `"Done"` / `"Something went wrong"`.

## Édition

`ctx.g.edit()` édite le **dernier message envoyé via ce contexte**, en conservant le style de sa variante sauf si vous le remplacez :

```ts
await ctx.g.reply.info("Processing 0/100...")
await ctx.g.edit("Processing 50/100...")            // reste stylisé info
await ctx.g.edit("All 100 processed", { variant: "success" })
```

Elle lève une erreur si rien n'a encore été envoyé via le contexte.

## Follow-ups et payloads bruts

`ctx.g.followUp.*` expose les mêmes six variantes stylisées, toujours envoyées en follow-up :

```ts
await ctx.g.followUp.warning("Heads up: this expires in 24h")
```

Quand vous avez besoin d'un contrôle total, `raw()` contourne le style Embed V2 et envoie n'importe quel payload discord.js (le routage intelligent s'applique toujours) :

```ts
await ctx.g.reply.raw({ content: "plain text", files: [attachment] })
await ctx.g.followUp.raw({ embeds: [legacyEmbed] })
```

## Éphémère par défaut

Définissez un défaut pour tout le contexte une seule fois, ou activez-le par appel :

```ts
ctx.g.ephemeral(true)                       // chaque envoi est désormais éphémère
await ctx.g.reply.success("Only you see this")

await ctx.g.reply.info("Just this one", { ephemeral: true })  // par appel
```

Les messages (par exemple dans les handlers `messageCreate`) ne peuvent pas être éphémères — le flag est silencieusement ignoré pour eux.

## Utilisateur, membre et config de serveur

| Propriété | Valeur |
|---|---|
| `ctx.g.user` | L'utilisateur invoquant (`interaction.user` / `message.author`) |
| `ctx.g.member` | Le membre de serveur invoquant, quand disponible |
| `ctx.g.guildConfig` | Namespace de configuration par serveur sur le [store](/guide/store) — lève une erreur en DM |

```ts
await ctx.g.guildConfig.set("welcomeChannel", channel.id)
const welcome = await ctx.g.guildConfig.get<string>("welcomeChannel")
```

`ctx.g.store` (portées guild/user/global) et `ctx.g.canvas` (rank cards, leaderboards) sont couverts dans les guides [Store](/guide/store) et [Canvas](/guide/canvas).

## Historique et hooks d'envoi

Tout ce qui est envoyé via le contexte est enregistré :

```ts
ctx.g.onSend((entry) => {
  console.log(`sent ${entry.variant} via ${entry.via}`)
})

const entries = ctx.g.history()
// [{ variant: "success", via: "reply", payload, message, timestamp }, ...]
```

Chaque `SentEntry` possède `variant` (`"primary"` ... `"info"` ou `"raw"`), `via` (`"reply"`, `"followUp"`, `"edit"`, `"update"`), le `payload` brut, le `message` résultant et un `timestamp`.

## Logging

`ctx.g.log()` écrit dans la console et — quand `logChannel` est défini dans `glyria.config.ts` — poste un message stylisé dans ce salon Discord :

```ts
await ctx.g.log(`${ctx.user.username} purged #general`, "warn")
```

```ts
// glyria.config.ts
export default defineGlyriaConfig({
  logChannel: "123456789012345678",
})
```

Niveaux : `"info"` (défaut), `"warn"`, `"error"` — associés aux styles info/warning/error sur Discord.

## Mises à jour de composants

Pour les interactions de boutons, de selects et de modals, `ctx.g.update.*` re-style le message d'origine sur place au lieu d'en envoyer un nouveau :

```ts
export default new GlyriaButton("vote:{pollId}:{choice}")
  .execute(async (ctx, params) => {
    await ctx.g.update.success(`Vote counted for **${params.choice}**!`)
  })
```

Voir le [guide Components](/guide/components) pour les customIds typés.

::note{title="Typage conditionnel"}
`ctx.g` s'adapte à sa source : `ctx.g.defer()` n'existe dans les types que lorsque la source supporte `deferReply()` (interactions, pas messages), et `ctx.g.update.*` uniquement quand la source supporte `update()` (interactions de composants). Votre éditeur ne proposera pas ce qui ne peut pas fonctionner.
::

## Enveloppement manuel

Pour les cas particuliers — un message récupéré via une API, un fake de test — `createReplyableContext` (auto-importé) enveloppe n'importe quel objet répondable à la main :

```ts
const target = await channel.messages.fetch(id)
const ctx = createReplyableContext(target)
await ctx.g.reply.info("Wrapped manually")
```

Elle est idempotente : envelopper un objet déjà enveloppé le retourne inchangé.
