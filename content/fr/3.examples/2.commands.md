## Commande de base

Créez un fichier dans `src/commands/` — il sera automatiquement chargé et enregistré sur Discord.

```ts
// src/commands/ping.ts
export default new GlyriaCommand()
  .setName("ping")
  .setDescription("Pong!")
  .execute(async (ctx) => {
    await ctx.g.reply.success("Pong!")
  })
```

::tip{title="Auto-import"}
`GlyriaCommand` est disponible globalement — aucun import nécessaire. Le handler reçoit l'interaction déjà enveloppée avec [`ctx.g`](/guide/replyable-context).
::

## Commande avec options

```ts
// src/commands/hello.ts
export default new GlyriaCommand()
  .setName("hello")
  .setDescription("Say hello to someone")
  .addUserOption((option) =>
    option
      .setName("user")
      .setDescription("The user to greet")
      .setRequired(true)
  )
  .addStringOption((option) =>
    option
      .setName("message")
      .setDescription("A custom message")
      .setRequired(false)
  )
  .execute(async (ctx) => {
    const message = ctx.options.getString("message") ?? "Hello!"
    await ctx.g.reply.primary(message)
  })
```

## Types d'options disponibles

| Méthode            | Type Discord |
| ------------------ | ------------ |
| `addStringOption`  | String       |
| `addIntegerOption` | Integer      |
| `addNumberOption`  | Number       |
| `addBooleanOption` | Boolean      |
| `addUserOption`    | User         |
| `addRoleOption`    | Role         |

## Autocomplétion

Les options string, integer et number supportent l'autocomplétion inline — pas de fichier de handler séparé :

```ts
// src/commands/tag.ts
export default new GlyriaCommand()
  .setName("tag")
  .setDescription("Show a tag")
  .addStringOption((option) =>
    option
      .setName("name")
      .setDescription("Tag name")
      .setRequired(true)
      .setAutocomplete(async (query) => {
        const tags = ["rules", "welcome", "faq", "support"]
        return tags.filter((tag) => tag.startsWith(query))
      })
  )
  .execute(async (ctx) => {
    await ctx.g.reply.info(`Tag: ${ctx.options.getString("name")}`)
  })
```

Retournez des chaînes, des nombres ou des objets `{ name, value }` — glyria.js les normalise et les limite au plafond Discord de 25.

## Cooldowns

Déclarez les cooldowns directement sur la commande — la réponse de refus est stylisée, éphémère et automatique :

```ts
export default new GlyriaCommand()
  .setName("daily")
  .setDescription("Claim your daily reward")
  .setCooldown("24h")                             // par utilisateur par défaut
  .execute(async (ctx) => { /* ... */ })
```

Cooldowns par portée :

```ts
.setCooldown({ user: "5s", guild: "2s", global: "1s" })
```

Les durées acceptent `ms`, `s`, `m`, `h`, `d` (`"500ms"`, `"5s"`, `"2m"`, `"1h"`, `"1d"`) ou un nombre brut de millisecondes. Les sous-commandes peuvent remplacer le cooldown du parent avec leur propre `.setCooldown()`.

## Permissions

Passez des noms de permissions pour obtenir le filtrage côté Discord **et** une vérification à l'exécution avec une erreur stylisée listant ce qui manque :

```ts
export default new GlyriaCommand()
  .setName("ban")
  .setDescription("Ban a user")
  .setPermissions(["BanMembers"])
  .addUserOption((option) =>
    option
      .setName("user")
      .setDescription("User to ban")
      .setRequired(true)
  )
  .execute(async (ctx) => {
    // seuls les membres avec la permission BanMembers arrivent ici
  })
```

La forme bitfield legacy fonctionne toujours : `.setPermissions(djs.PermissionsBitField.Flags.BanMembers)`.

Restreignez une commande au propriétaire du bot (Teams supportées) :

```ts
.setOwnerOnly()
```

## Métadonnées

Attachez des données personnalisées à une commande avec `.setMetaData()`. Glyria stocke ces données telles quelles et ne les interprète jamais.

```ts
export default new GlyriaCommand()
  .setName("ban")
  .setDescription("Ban a user")
  .setMetaData({
    category: "moderation",
    premium: false,
    guildOnly: true,
  })
  .execute(async (ctx) => {
    // votre logique ici
  })
```

### useCommands()

`useCommands()` retourne la liste complète des commandes chargées avec leurs métadonnées.

```ts
const commands = useCommands()

// [
//   {
//     name: "ban",
//     description: "Ban a user",
//     meta: {
//       category: "moderation"
//     }
//   }
// ]
```

Exemple d'une commande `/help` organisée par catégorie, avec pagination :

```ts
export default new GlyriaCommand()
  .setName("help")
  .setDescription("List all commands")
  .execute(async (ctx) => {
    const commands = useCommands()

    const byCategory = commands.reduce((acc, cmd) => {
      const category = (cmd.meta.category as string) ?? "general"

      acc[category] ??= []
      acc[category].push(cmd)

      return acc
    }, {} as Record<string, typeof commands>)

    const pages = Object.entries(byCategory).map(
      ([category, cmds]) =>
        `# ${category}\n${cmds.map((c) => `**/${c.name}** — ${c.description}`).join("\n")}`
    )

    await ctx.g.paginate(pages)
  })
```

## Sous-commandes

```ts
// src/commands/moderation.ts
export default new GlyriaCommand()
  .setName("moderation")
  .setDescription("Moderation commands")
  .setPermissions(["ModerateMembers"])
  .addSubCommand((cmd) =>
    cmd
      .setName("ban")
      .setDescription("Ban a user")
      .setPermissions(["BanMembers"])            // remplace le parent pour cette sous-commande
      .addUserOption((option) =>
        option
          .setName("user")
          .setDescription("User to ban")
          .setRequired(true)
      )
      .addStringOption((option) =>
        option
          .setName("reason")
          .setDescription("Reason for the ban")
      )
      .execute(async (ctx) => {
        // gérer le ban
      })
  )
  .addSubCommand((cmd) =>
    cmd
      .setName("kick")
      .setDescription("Kick a user")
      .execute(async (ctx) => {
        // gérer le kick
      })
  )
```

## Groupes de sous-commandes

```ts
export default new GlyriaCommand()
  .setName("config")
  .setDescription("Configuration commands")
  .addSubCommandGroup((group) =>
    group
      .setName("logs")
      .setDescription("Logs configuration")
      .addSubCommand((cmd) =>
        cmd
          .setName("enable")
          .setDescription("Enable logs")
          .execute(async (ctx) => {
            // gérer l'activation des logs
          })
      )
      .addSubCommand((cmd) =>
        cmd
          .setName("disable")
          .setDescription("Disable logs")
          .execute(async (ctx) => {
            // gérer la désactivation des logs
          })
      )
  )
```

Cela génère une structure de commandes similaire à :

```txt
/config logs enable
/config logs disable
/moderation ban <user> [reason]
/moderation kick <user>
```

## Organisation des commandes

Les sous-dossiers de `src/commands/` servent uniquement à l'organisation — chaque fichier, quelle que soit sa profondeur, est chargé automatiquement.

```txt
src/commands/
  ping.ts
  moderation/
    ban.ts
    kick.ts
  config/
    advanced/
      logs.ts
```

Gardez une commande par fichier. Utilisez les sous-commandes et les groupes de sous-commandes pour organiser les fonctionnalités liées.
