## Vue d'ensemble

Cette page présente un module complet construit avec le [SDK de modules](/guide/modules) — un module `economy` avec sa propre commande, une API publique pour les autres modules et un middleware global.

Générez le squelette avec :

```bash
npx glyria module create economy
```

## Le manifeste

```ts
// src/modules/economy/index.ts
export default defineModule({
  name: "economy",
  version: "1.0.0",
  description: "Coins, balances, and daily rewards",

  setup(ctx) {
    ctx.logger.info("economy loaded")

    // l'objet retourné est l'API publique du module
    return {
      async getBalance(userId: string): Promise<number> {
        return (await ctx.store.get<number>(`balance:${userId}`)) ?? 0
      },
      async addBalance(userId: string, amount: number): Promise<number> {
        const balance = ((await ctx.store.get<number>(`balance:${userId}`)) ?? 0) + amount
        await ctx.store.set(`balance:${userId}`, balance)
        return balance
      },
    }
  },

  hooks: {
    onReady(ctx) {
      ctx.logger.info("bot is ready — economy online")
    },
  },
})
```

`ctx.store` est automatiquement scopé au module (`module:economy:`) — aucune collision de clés avec les autres modules.

## Une commande de module

Les commandes dans un dossier de module sont chargées automatiquement comme les commandes classiques :

```ts
// src/modules/economy/commands/balance.ts
export default new GlyriaCommand()
  .setName("balance")
  .setDescription("Check your balance")
  .setCooldown("3s")
  .execute(async (ctx) => {
    const coins = await ctx.g.store.user.get<number>("balance") ?? 0
    await ctx.g.reply.primary(`💰 You have **${coins}** coins`)
  })
```

## Consommer le module depuis un autre module

```ts
// src/modules/shop/index.ts
export default defineModule({
  name: "shop",
  dependsOn: ["economy"],          // garantit l'ordre de chargement

  setup(ctx) {
    const economy = ctx.modules.get("economy")

    return {
      async buy(userId: string, price: number) {
        await economy.addBalance(userId, -price)
      },
    }
  },
})
```

### Typer l'API inter-modules

Augmentez l'interface `GlyriaModules` pour que `ctx.modules.get("economy")` soit entièrement typé :

```ts
// src/modules/economy/types.d.ts
declare module "@glyria/bot" {
  interface GlyriaModules {
    economy: {
      getBalance(userId: string): Promise<number>
      addBalance(userId: string, amount: number): Promise<number>
    }
  }
}
```

## Un middleware global

Un module peut observer (ou annuler) chaque commande du bot :

```ts
// src/modules/audit/index.ts
export default defineModule({
  name: "audit",

  hooks: {
    async beforeCommand(ctx, meta, next) {
      console.log(`[audit] /${meta.name.replaceAll(":", " ")}`)
      await next()                 // omettez next() pour annuler la commande
    },
  },
})
```

## Tester le module

`createTestContext()` exécute n'importe quel handler sans Discord :

```ts
// test/balance.test.ts
import "@glyria/bot/globals" // installe les globales du runtime (GlyriaCommand, ...) sous vitest pur
import { describe, it, expect } from "vitest"
import { createTestContext } from "@glyria/bot"
import balance from "../src/modules/economy/commands/balance.js"

describe("/balance", () => {
  it("replies with the balance", async () => {
    const ctx = createTestContext({ userId: "42" })

    await balance.getHandlers()[0]!.handler(ctx as never)

    expect(ctx.repliesText()[0]).toContain("coins")
  })
})
```

## Publier sur npm

Un module est un package npm normal — `npm publish` suffit. Livrez la même structure (`glyria.module.ts` ou `index.ts` dans le dossier `src/` du package ou dans son `dist/` build — pas à la racine nue du package — plus les dossiers optionnels `commands/`, `events/`, `components/`), et les consommateurs l'activent dans leur config :

```ts
// glyria.config.ts
export default defineGlyriaConfig({
  modules: ["glyria-module-economy"],
  moduleConfig: {
    economy: { startingBalance: 100 },
  },
})
```
