Après avoir exécuté `npx glyria init`, votre projet ressemblera à ceci :

```txt
your-bot/
  src/
    commands/
    events/
    components/
    modules/
    composables/
    utils/
    index.ts
  .glyria/
    imports.d.ts
  .env
  .gitignore
  tsconfig.json
  glyria.config.ts
  package.json
```

## src/

Le dossier principal contenant le code source de votre bot.

### src/commands/

Toutes vos commandes slash se trouvent ici. glyria.js analyse récursivement ce dossier au démarrage et enregistre automatiquement chaque fichier.

```txt
src/commands/
  ping.ts
  moderation/
    ban.ts
    kick.ts
  config/
    logs.ts
```

::tip{title="Sous-dossiers comme catégories"}
Les sous-dossiers servent uniquement à l'organisation — chaque fichier `.ts`, peu importe sa profondeur, est chargé comme une commande.
::

### src/events/

Les listeners d'événements Discord. Chaque fichier gère un ou plusieurs événements discord.js. Les arguments répondables (messages, interactions) arrivent déjà enveloppés avec `ctx.g`.

### src/components/

Les handlers de composants interactifs — boutons, menus de sélection et modals avec des [customIds typés](/guide/components) :

```ts
// src/components/vote.ts
export default new GlyriaButton("vote:{pollId}:{choice}")
  .execute(async (ctx, params) => {
    await ctx.g.update.success(`Voted ${params.choice}!`)
  })
```

### src/modules/

Modules de fonctionnalités autonomes construits avec le [SDK de modules](/guide/modules). Chaque dossier de module possède un manifeste `index.ts` et peut embarquer ses propres `commands/`, `events/` et `components/` — tous chargés automatiquement.

```txt
src/modules/
  economy/
    index.ts        # defineModule({ ... })
    commands/
      balance.ts
```

Générez-en un avec `glyria module create <name>`.

### src/composables/

La logique métier et les utilitaires avec état. Les fichiers placés ici sont automatiquement disponibles globalement grâce aux auto-imports — aucun import nécessaire. La convention est de préfixer les fonctions avec `use`.

```ts
// src/composables/useModeration.ts
export const useModeration = () => {
  // logique de ban, logique de kick, etc.
}

// src/commands/ban.ts — aucun import requis
const moderation = useModeration()
```

### src/utils/

Fonctions pures sans dépendances ni effets de bord. Les fichiers placés ici sont également auto-importés globalement.

```ts
// src/utils/formatDate.ts
export const formatDate = (date: Date) => {
  // ...
}

// src/commands/ping.ts — aucun import requis
const formatted = formatDate(new Date())
```

::tip{title="composables/ vs utils/"}
`utils/` est destiné aux fonctions pures sans dépendances — formatage, parsing, calculs. `composables/` est destiné à la logique qui interagit avec la base de données, Discord ou d'autres services.
::

### src/index.ts

Le point d'entrée de votre bot. Minimaliste par conception :

```ts
const client = new GlyriaClient({
  intents: [GatewayIntentBits.Guilds]
})

await client.login()
```

## .glyria/

Généré et géré par glyria.js à l'exécution :

| Chemin | Rôle |
|---|---|
| `imports.d.ts` | Déclarations TypeScript pour les auto-imports |
| `store.json` | Données persistées du store (quand `store.adapter` vaut `"json"`) |
| `interactions/` | Interactions enregistrées pour [`glyria replay`](/cli/replay) |
| `commands.snapshot.json` | Snapshot des commandes utilisé par le [changelog automatique](/guide/production) |
| `bot.pid` | Fichier pid utilisé par [`glyria reload`](/cli/reload) |
| `last-good/` | Dernier build stable, utilisé par le [superviseur auto-réparant](/cli/start) |

::warning{title="Ne pas modifier"}
Les fichiers de déclaration sont régénérés à chaque exécution de `glyria generate` ou `glyria dev`. Toute modification manuelle sera écrasée. Ajoutez `.glyria/` à votre `.gitignore`.
::

## .env

Variables d'environnement de votre bot. glyria.js charge automatiquement ce fichier au démarrage.

```bash
TOKEN=your_bot_token_here
```

## glyria.config.ts

Configuration globale de votre bot — thème, modules, store, logging et plus encore. Voir la [référence complète de configuration](/api-reference/define-glyria-config).

```ts
export default defineGlyriaConfig({
  modules: ["@glyria/timers"],
  logChannel: "123456789",
  store: { adapter: "json" },
})
```

## tsconfig.json

Préconfiguré par `npx glyria init`. Inclut le dossier `.glyria/` pour la résolution des types liés aux auto-imports.
