Au lieu d'écrire du boilerplate encore et encore, glyria.js vous permet de vous concentrer sur ce qui compte vraiment — les fonctionnalités de votre bot.

## Pourquoi glyria.js ?

### Zéro boilerplate

Un bot minimal avec discord.js nécessite des dizaines de lignes de configuration. Avec glyria.js :

```ts
// src/index.ts
const client = new GlyriaClient({
    intents: [GatewayIntentBits.Guilds]
})

await client.login()
```

C'est tout. Le chargement du token, l'enregistrement des commandes, le routage des interactions — tout est géré automatiquement.

### Commandes basées sur les fichiers

Déposez un fichier dans `src/commands/` et il sera automatiquement chargé et enregistré sur Discord. Aucun import manuel, aucun code d'enregistrement.

```ts
// src/commands/ping.ts
export default new GlyriaCommand()
    .setName("ping")
    .setDescription("Pong!")
    .execute(async (ctx) => {
        await ctx.g.reply.success("Pong!")
    })
```

Il en va de même pour `src/events/`, `src/components/` et `src/modules/` — tout est basé sur les fichiers.

### Un contexte qui fait le gros du travail

Chaque handler reçoit l'interaction déjà enveloppée avec `ctx.g` — réponses stylisées, confirmations, pagination, réponses différées, un store intégré et plus encore :

```ts
export default new GlyriaCommand()
    .setName("clear")
    .setDescription("Clear messages")
    .setCooldown("10s")
    .setPermissions(["ManageMessages"])
    .execute(async (ctx) => {
        if (await ctx.g.confirm("Delete the last 50 messages?")) {
            // ... logique de suppression
            await ctx.g.reply.success("Done!").ephemeral().send()
        }
    })
```

Les cooldowns, les vérifications de permissions et leurs réponses d'erreur sont déclarés sur la commande — aucun `if` nécessaire.

### Auto-imports

Chaque utilitaire glyria.js est disponible globalement — aucun import nécessaire dans vos fichiers de commandes : `GlyriaCommand`, `GlyriaButton`, `defineModule`, `EmbedV2Builder`, `canvas` et plus encore.

### Embeds V2 par défaut

glyria.js inclut un builder Embed V2 de première classe — le nouveau système de composants Discord que la plupart des frameworks ne supportent pas encore. Les réponses stylisées (`ctx.g.reply.success(...)`) sont automatiquement rendues avec Embed V2.

### Un outillage qui va plus loin

La CLI couvre l'ensemble du cycle de vie, pas seulement le scaffolding :

| Commande | Ce qu'elle fait |
|---|---|
| `glyria dev` | Hot reload des commandes, events, composants et modules |
| `glyria studio` | Interface web locale pour exécuter des commandes et prévisualiser le rendu Discord |
| `glyria replay` | Rejoue n'importe quelle interaction enregistrée pour reproduire un bug |
| `glyria bench` | Teste vos handlers en charge, in-process |
| `glyria reload` | Déploiements sans interruption — les handlers sont remplacés en mémoire |
| `glyria start` | Superviseur auto-réparant avec rollback en cas de boucle de crash |

## Comment ça fonctionne

glyria.js repose sur discord.js comme une fine couche DX :

```
discord.js      →  gère WebSocket, REST et le cache
glyria.js       →  chargement basé sur les fichiers, ctx.g, guards, modules, CLI
votre bot       →  uniquement vos fonctionnalités
```

Vous avez toujours accès au client discord.js brut si nécessaire — glyria.js ne vous enferme jamais dans son écosystème.
