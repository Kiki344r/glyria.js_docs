## C’est quoi les auto-imports ?

Dans un projet TypeScript classique, tu dois importer manuellement chaque fonction ou classe que tu utilises :

```ts
import { GlyriaCommand } from "@glyria/bot"
import { EmbedV2Builder } from "@glyria/bot"
import { GlyriaClient } from "@glyria/bot"
```

glyria.js supprime totalement ce besoin. Tous les utilitaires du framework sont automatiquement disponibles en global — aucun import n’est nécessaire dans ton projet.

```ts
// aucun import — ça marche directement
export default GlyriaCommand()
  .setName("ping")
  .setDescription("Pong !")
  .execute(async (ctx) => {
    await ctx.reply({ content: "Pong !" })
  })
```

---

## Comment ça fonctionne

glyria.js utilise deux mécanismes complémentaires :

**Injection au runtime** — au démarrage du bot, glyria.js injecte tous les utilitaires dans `globalThis`. Chaque fichier exécuté après cela peut y accéder sans import.

**Déclarations de types** — glyria.js génère un fichier `.glyria/imports.d.ts` qui informe TypeScript de l’existence de ces globals. Ça permet d’avoir l’autocomplétion et le typage complet dans ton IDE.

## Globals utilisateur

Toute fonction exportée depuis src/utils/ ou src/composables/ est aussi auto-importée.

```ts
// src/utils/useDatabase.ts
export const useDatabase = () => {
  return {
    find: (id) => {},
    save: (data) => {},
  }
}
```

```ts
// src/commands/ping.ts
export default new GlyriaCommand()
  .setName("ping")
  .setDescription("Pong !")
  .execute(async (ctx) => {
    const db = useDatabase()
    const user = await db.find(ctx.user.id)
  })
```

---

## Régénération des auto-imports

Les auto-imports sont régénérés automatiquement en mode dev. Si tu ajoutes un nouvel utilitaire en production, exécute :

```bash
npx glyria generate
```

---

## Support IDE

Ajoute ceci dans ton tsconfig.json :

```json
{
  "include": ["src/**/*", ".glyria/**/*"]
}
```

---

## Important

Le fichier .glyria/imports.d.ts est généré automatiquement et ne doit jamais être modifié manuellement.
