Les exports plus modestes de `@glyria/bot` qui alimentent les fonctionnalités du framework — tous importables pour votre propre outillage.

## Durées

Le même parseur que celui utilisé par `.setCooldown()`, `confirm()` et les timeouts de `paginate()`.

### `parseDuration(input)`

```ts
import { parseDuration } from "@glyria/bot"

parseDuration("5s")    // 5000
parseDuration("2m")    // 120000
parseDuration("1.5h")  // 5400000
parseDuration(250)     // 250 (les nombres passent tels quels, en ms)
```

| Paramètre | Type | Description |
|---|---|---|
| `input` | `Duration` (`number \| string`) | Millisecondes, ou une chaîne avec un suffixe `ms`, `s`, `m`, `h` ou `d` |

Lève une exception sur une entrée invalide (nombres négatifs, suffixes inconnus comme `"5w"`).

### `formatDuration(ms)`

Formate des millisecondes en une chaîne compacte lisible, en arrondissant **au supérieur** à la seconde suivante — utilisé pour les messages de cooldown « réessayez dans X ».

```ts
formatDuration(1_001)     // "2s"
formatDuration(90_000)    // "1m 30s"
formatDuration(3_900_000) // "1h 5m"
```

## Enregistreur d'interactions

L'API derrière le [débogage time-travel](/cli/replay). Les interactions sont enregistrées automatiquement en dev (ou avec `recording: true`) dans `.glyria/interactions/<id>.json`.

| Fonction | Retourne | Description |
|---|---|---|
| `recordInteraction(entry)` | `void` | Écrit une `RecordedInteraction` sur disque (best-effort — les échecs sont loggés, jamais levés) |
| `readRecording(id)` | `RecordedInteraction \| null` | Charge un enregistrement par id d'interaction |
| `listRecordings()` | `RecordedInteraction[]` | Tous les enregistrements, du plus récent au plus ancien |

### `RecordedInteraction`

| Champ | Type | Description |
|---|---|---|
| `id` | `string` | Id de l'interaction Discord (le nom du fichier) |
| `key` | `string` | Clé du handler résolue, par exemple `"config:theme:set"` |
| `kind` | `"chat" \| "user" \| "message"` | Type de commande |
| `userId` / `username?` | `string` | Utilisateur invoquant |
| `guildId` / `channelId` | `string \| null` | Où elle s'est exécutée |
| `options` | `Record<string, unknown>` | Valeurs d'options à plat, par nom |
| `subcommand` | `string[]` | Chemin de sous-commande (`["theme", "set"]`) |
| `createdAt` | `number` | Horodatage |
| `replies` | `{ via, payload, timestamp }[]` | Tout ce que le handler a envoyé |
| `error?` | `string` | Présent quand le handler a levé une exception |

Combinez-le avec [`createTestContext()`](/api-reference/create-test-context) pour construire votre propre outillage de replay :

```ts
import { readRecording, createTestContext } from "@glyria/bot"

const recording = readRecording("1234567890")!
const ctx = createTestContext({
  userId: recording.userId,
  guildId: recording.guildId,
  options: recording.options,
  subcommand: recording.subcommand,
})
```

## Diff de commandes

Le moteur de diff derrière le [ré-enregistrement intelligent](/guide/commands) et le [changelog automatique](/guide/production).

### `diffCommandBodies(prev, next)`

Compare deux tableaux de payloads de commandes par nom et contenu sérialisé.

```ts
import { diffCommandBodies, isDiffEmpty } from "@glyria/bot"

const diff = diffCommandBodies(previousCommands, currentCommands)
// { added: ["new-cmd"], removed: ["old-cmd"], changed: ["edited-cmd"] }

if (isDiffEmpty(diff)) {
  // rien à déployer
}
```

| Export | Type | Description |
|---|---|---|
| `diffCommandBodies(prev, next)` | `CommandsDiff` | Commandes nommées ajoutées / supprimées / modifiées entre deux déploiements |
| `isDiffEmpty(diff)` | `boolean` | Vrai quand rien n'a changé |
| `CommandsDiff` | `{ added: string[]; removed: string[]; changed: string[] }` | La forme du diff |

## Helpers de modules

Les briques de plus bas niveau du [SDK de modules](/api-reference/define-module), utiles pour construire un outillage personnalisé autour des modules.

| Export | Description |
|---|---|
| `isModuleDefinition(value)` | Type guard — vrai quand `value` est un résultat brandé de `defineModule()`. Le loader l'utilise pour valider les exports par défaut |
| `resolveLoadOrder(definitions)` | Trie topologiquement les définitions de modules selon `dependsOn`. Retourne `{ order, failed }` où `failed` liste les modules avec des dépendances manquantes ou des cycles (et pourquoi) |
| `LoadedModule` *(type)* | L'enregistrement runtime d'un module dans le `ModuleManager` : `definition`, `status`, `api`, `context`, `errorCount`, `statusReason` |
| `CommandGuards` *(type)* | La forme déclarative des gardes attachées aux handlers de commandes : `{ cooldown?, permissions?, ownerOnly? }` — définies via [`setCooldown` / `setPermissions` / `setOwnerOnly`](/api-reference/glyria-command) |

```ts
import { resolveLoadOrder } from "@glyria/bot"

const { order, failed } = resolveLoadOrder(definitions)
// order : ordre de chargement respectant les dépendances
// failed : [{ name: "shop", reason: 'missing dependency "economy"' }]
```
