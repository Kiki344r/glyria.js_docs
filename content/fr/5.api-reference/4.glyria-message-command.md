## Vue d'ensemble

`GlyriaMessageCommand` est le constructeur utilisé pour définir des commandes de menu contextuel de message Discord. Elles apparaissent lors d'un clic droit sur un message, dans la section **Applications**.

```ts
export default new GlyriaMessageCommand()
  .setName("Translate")
  .execute(async (ctx) => {
    const message = ctx.targetMessage
    await ctx.reply({
      content: `Translating: "${message.content}"`,
      flags: djs.MessageFlags.Ephemeral,
    })
  })
```

::tip{title="Importation automatique"}
`GlyriaMessageCommand` est disponible globalement — aucun import n'est nécessaire.
::

## GlyriaMessageCommand

### Méthodes

| Méthode                  | Retourne | Description                                                |
| ------------------------ | -------- | ---------------------------------------------------------- |
| `.setName(name)`         | `this`   | Définit le nom de la commande                              |
| `.setPermissions(perms)` | `this`   | Restreint la commande à des permissions spécifiques        |
| `.setCooldown(input)`    | `this`   | Ajoute un cooldown par utilisateur, par serveur ou global  |
| `.setOwnerOnly(bool?)`   | `this`   | Restreint la commande au propriétaire du bot               |
| `.setMetaData(meta)`     | `this`   | Attache des métadonnées personnalisées à la commande       |
| `.execute(handler)`      | `this`   | Définit le gestionnaire de la commande                     |

::tip{title="Pas de description, d'options ni de sous-commandes"}
Les commandes de menu contextuel de message ne supportent pas les descriptions, les options ni les sous-commandes — ce sont des limitations de l'API Discord.
::

### `.setPermissions()`

Restreint la commande aux membres possédant des permissions Discord spécifiques. Accepte :

- un `bigint`, un `number` ou une `string` — utilisé tel quel comme bitfield Discord `default_member_permissions`
- un tableau `PermissionName[]` (ex. `["ManageMessages"]`) — les noms sont combinés en OR dans le bitfield `default_member_permissions` **et** revérifiés à l'exécution, avec en cas de refus une erreur éphémère stylisée listant la ou les permissions manquantes

```ts
export default new GlyriaMessageCommand()
  .setName("Delete message")
  .setPermissions(["ManageMessages"])
  .execute(async (ctx) => {
    // seuls les membres possédant la permission ManageMessages peuvent utiliser ceci
  })
```

### `.setCooldown()`

Ajoute un cooldown déclaratif. Accepte une chaîne de durée (`"5s"`, `"2m"`, `"1h"`), un nombre de millisecondes (les deux appliqués **par utilisateur**), ou un objet `{ user?, guild?, global? }` avec une durée par portée. Les membres encore en cooldown reçoivent une erreur éphémère stylisée avec le temps restant.

```ts
export default new GlyriaMessageCommand()
  .setName("Translate")
  .setCooldown({ user: "10s", guild: "2s" })
```

### `.setOwnerOnly()`

Restreint la commande au propriétaire du bot. Vaut `true` par défaut quand appelée sans argument — les non-propriétaires reçoivent une erreur éphémère stylisée.

```ts
export default new GlyriaMessageCommand()
  .setName("Dump message JSON")
  .setOwnerOnly()
```

### `.setMetaData()`

Attache des métadonnées personnalisées à la commande. Accepte n'importe quel objet clé-valeur — Glyria les stocke telles quelles et ne les interprète jamais.

```ts
export default new GlyriaMessageCommand()
  .setName("Translate")
  .setMetaData({
    category: "utility",
    cooldown: 5000,
  })
  .execute(async (ctx) => {
    // votre logique ici
  })
```

Les métadonnées sont accessibles à l'exécution via `useCommands()` :

```ts
const commands = useCommands()
// [
//   { name: "Translate", description: "", meta: { category: "utility", cooldown: 5000 } },
// ]
```

::tip{title="useCommands"}
`useCommands()` est disponible globalement — aucun import n'est nécessaire. Le registre est automatiquement rempli au démarrage du bot.
::

### `.execute()`

Définit le gestionnaire de la commande. Le handler reçoit un `GlyriaContext<MessageContextMenuCommandInteraction>` — l'interaction brute (le message ciblé est disponible via `ctx.targetMessage`) plus la boîte à outils Glyria `ctx.g`. Voir [ReplyableContext](/api-reference/replyable-context) pour l'API `ctx.g` complète.

```ts
export default new GlyriaMessageCommand()
  .setName("Translate")
  .execute(async (ctx) => {
    const message = ctx.targetMessage
    await ctx.g.reply.info(`Translating: "${message.content}"`).ephemeral()
  })
```
