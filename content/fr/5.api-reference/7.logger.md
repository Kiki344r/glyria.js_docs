## Vue d'ensemble

`logger` est l'utilitaire de logging interne de glyria.js, disponible **globalement** dans tout votre projet — aucun import nécessaire.

```ts
logger.info("MyModule", "Initialisation...")
logger.success("MyModule", "Prêt !")
```

Il produit des messages cohérents avec le style visuel du framework, alignés et colorés automatiquement dans le terminal.

---

## Méthodes

### `logger.info(scope, message)`

Affiche un message informatif en cyan.

```ts
logger.info("Database", "Connexion en cours...")
```

```text
│ ℹ Database      Connexion en cours...
```

| Paramètre | Type     | Description                          |
| --------- | -------- | ------------------------------------ |
| `scope`   | `string` | Nom du module ou contexte du message |
| `message` | `string` | Message à afficher                   |

---

### `logger.success(scope, message)`

Affiche un message de succès en vert.

```ts
logger.success("Database", "Connecté à PostgreSQL")
```

```text
├─ ✔ Database      Connecté à PostgreSQL
```

| Paramètre | Type     | Description                          |
| --------- | -------- | ------------------------------------ |
| `scope`   | `string` | Nom du module ou contexte du message |
| `message` | `string` | Message à afficher                   |

---

### `logger.warn(scope, message)`

Affiche un avertissement en jaune.

```ts
logger.warn("Cache", "Clé expirée, rechargement...")
```

```text
├─ ⚠ Cache         Clé expirée, rechargement...
```

| Paramètre | Type     | Description                          |
| --------- | -------- | ------------------------------------ |
| `scope`   | `string` | Nom du module ou contexte du message |
| `message` | `string` | Message à afficher                   |

---

### `logger.error(scope, message)`

Affiche une erreur en rouge.

```ts
logger.error("Redis", "Connexion échouée")
```

```text
├─ ✖ Redis         Connexion échouée
```

| Paramètre | Type     | Description                          |
| --------- | -------- | ------------------------------------ |
| `scope`   | `string` | Nom du module ou contexte du message |
| `message` | `string` | Message à afficher                   |

---

### `logger.hotreload(scope, message)`

Affiche un message de hot reload en magenta. Utilisé en interne par le watcher, mais disponible si vous implémentez votre propre logique de rechargement.

```ts
logger.hotreload("Commands", "ping.ts rechargé")
```

```text
├─ 🔥 Commands      ping.ts rechargé
```

| Paramètre | Type     | Description                          |
| --------- | -------- | ------------------------------------ |
| `scope`   | `string` | Nom du module ou contexte du message |
| `message` | `string` | Message à afficher                   |

---

### `logger.ready(botName)`

Affiche le message de connexion du bot. Appelé automatiquement par glyria.js au démarrage — vous n'avez pas besoin de l'appeler manuellement.

```ts
logger.ready("MonBot#1234")
```

```text
│
╰─ ⚡ bot           Ready as MonBot#1234
```

| Paramètre | Type     | Description               |
| --------- | -------- | ------------------------- |
| `botName` | `string` | Nom et tag du bot Discord |

---

## Exemple complet

Utilisation typique dans un fichier `src/utils/database.ts` auto-importé par glyria.js :

```ts
export const prisma = new PrismaClient()

export const init = async () => {
  try {
    await prisma.$connect()
    logger.success("Database", "Connecté à PostgreSQL")
  } catch (error) {
    logger.error("Database", "Connexion échouée")
    throw error
  }
}
```

```ts
export const redis = createClient({ url: process.env.REDIS_URL })

export const init = async () => {
  try {
    await redis.connect()
    logger.success("Redis", "Connecté")
  } catch (error) {
    logger.error("Redis", "Connexion échouée")
    throw error
  }
}
```

Le hook `init` est automatiquement appelé par glyria.js lors de l'auto-import — voir [Auto Imports](/docs/auto-imports).
\::

## Conventions

Le paramètre `scope` est padé automatiquement à 12 caractères pour aligner visuellement les messages dans le terminal. Privilégiez des noms courts et explicites :

| Bon          | À éviter                      |
| ------------ | ----------------------------- |
| `"Database"` | `"Initialisation de la base"` |
| `"Redis"`    | `"Cache Redis"`               |
| `"Commands"` | `"Gestionnaire de commandes"` |
