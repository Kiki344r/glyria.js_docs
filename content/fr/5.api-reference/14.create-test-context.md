## Vue d'ensemble

`createTestContext` construit une fausse interaction enveloppée dans un contexte Glyria complet — exécutez des handlers de commandes, des hooks de modules ou des composants sans Discord, puis faites vos assertions sur les réponses capturées.

```ts
const ctx = createTestContext({ options: { user: "42" } })
await myHandler(ctx)

ctx.repliesText() // ["✅ User banned."]
```

Le contexte retourné est un vrai `GlyriaContext` : `ctx.g.reply.*`, `ctx.g.store`, `ctx.g.edit`, `ctx.g.defer`, `ctx.g.reply.loading` fonctionnent tous. Les envois sont capturés au lieu de partir sur le réseau.

::tip{title="Importation automatique"}
`createTestContext` est disponible globalement dans un projet Glyria. Dans un fichier vitest brut, importez-le : `import { createTestContext } from "@glyria/bot"`.
::

## TestContextOptions

Chaque option a une valeur par défaut raisonnable — `createTestContext()` sans argument est valide.

| Option       | Type                      | Défaut           | Description                                                     |
| ------------ | ------------------------- | ---------------- | ---------------------------------------------------------------- |
| `userId`     | `string`                  | `"test-user"`    | Id de l'utilisateur à l'origine de l'invocation                   |
| `username`   | `string`                  | `"tester"`       | Nom d'utilisateur de l'utilisateur à l'origine de l'invocation    |
| `guildId`    | `string \| null`          | `"test-guild"`   | Id du serveur — passez `null` pour simuler un DM                  |
| `channelId`  | `string`                  | `"test-channel"` | Id du salon                                                       |
| `member`     | `unknown`                 | `null`           | Valeur retournée par `ctx.member` / `ctx.g.member`                |
| `options`    | `Record<string, unknown>` | `{}`             | Valeurs des options slash, indexées par nom d'option (`getString`, `getInteger`, ... y lisent) |
| `subcommand` | `string[]`                | `[]`             | Chemin de sous-commande, ex. `["theme", "set"]` pour groupe+sous-commande ou `["show"]` |

## TestContext

`createTestContext` retourne un `GlyriaContext<FakeInteraction>` étendu avec des helpers de capture :

| Membre           | Type              | Description                                              |
| ---------------- | ----------------- | -------------------------------------------------------- |
| `replies`        | `CapturedReply[]` | Tout ce que le handler a envoyé, dans l'ordre             |
| `repliesText()`  | `string[]`        | Vue en texte brut de chaque réponse (texte Embed V2 extrait, payloads vides filtrés) |

La fausse interaction elle-même expose `user`, `member`, `guildId`, `channelId`, `replied`, `deferred`, un résolveur `options` (`getString` / `getInteger` / `getNumber` / `getBoolean` / `getUser` / `getRole` / `getSubcommand` / `getSubcommandGroup` / `getFocused`), les méthodes de réponse (`reply` / `editReply` / `followUp` / `deferReply`), et `isChatInputCommand()` (toujours `true`).

### CapturedReply

| Champ       | Type                                                                       | Description                     |
| ----------- | --------------------------------------------------------------------------- | ------------------------------- |
| `via`       | `"reply" \| "editReply" \| "followUp" \| "deferReply" \| "update" \| "edit"` | Comment le payload a été livré  |
| `payload`   | `unknown`                                                                    | Le payload brut                 |
| `timestamp` | `number`                                                                     | `Date.now()` au moment de la capture |

::warning{title="Pas de clics sur les composants"}
Le faux message retourné par les captures supporte `edit` (donc `g.edit()` et `g.reply.loading()` fonctionnent), mais `awaitMessageComponent` lève une exception — `g.confirm()` et `g.paginate()` ont besoin d'un vrai utilisateur pour cliquer.
::

## Tester un handler de commande

```ts
// test/ban.test.ts
import { describe, expect, it } from "vitest"
import { createTestContext } from "@glyria/bot"
import ban from "../src/commands/ban"

describe("/ban", () => {
  it("bans the given user with a reason", async () => {
    const ctx = createTestContext({
      userId: "mod-1",
      options: { user: { id: "999" }, reason: "spam" },
    })

    // getHandlers() expose les fonctions enregistrées avec .execute()
    const handler = ban.getHandlers()[0]!.handler
    await handler(ctx)

    expect(ctx.repliesText()[0]).toContain("banned")
    expect(ctx.replies[0]!.via).toBe("reply")
  })

  it("reads subcommand paths", async () => {
    const ctx = createTestContext({ subcommand: ["theme", "set"] })
    expect(ctx.options.getSubcommandGroup()).toBe("theme")
    expect(ctx.options.getSubcommand()).toBe("set")
  })
})
```

## Tester un middleware de module

```ts
// test/blacklist.test.ts
import { describe, expect, it, vi } from "vitest"
import { createTestContext } from "@glyria/bot"
import blacklist from "../src/modules/blacklist"

describe("blacklist middleware", () => {
  it("blocks blacklisted users and skips next()", async () => {
    const ctx = createTestContext({ userId: "banned-user" })
    await ctx.g.store.user.set("blacklisted", true)

    const next = vi.fn()
    await blacklist.hooks!.beforeCommand!(
      ctx,
      { name: "ping", kind: "chat" },
      next,
    )

    expect(next).not.toHaveBeenCalled()
    expect(ctx.repliesText()[0]).toContain("blacklisted")
  })

  it("lets everyone else through", async () => {
    const ctx = createTestContext()
    const next = vi.fn()

    await blacklist.hooks!.beforeCommand!(ctx, { name: "ping", kind: "chat" }, next)

    expect(next).toHaveBeenCalledOnce()
    expect(ctx.replies).toHaveLength(0)
  })
})
```
