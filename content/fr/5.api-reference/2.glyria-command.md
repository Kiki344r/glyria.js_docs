## Vue d'ensemble

`GlyriaCommand` est le constructeur utilisé pour définir des commandes slash Discord. Chaque fichier dans `src/commands/` doit exporter une instance de `GlyriaCommand` par défaut.

```ts
export default new GlyriaCommand()
  .setName("ping")
  .setDescription("Pong!")
  .execute(async (ctx) => {
    await ctx.g.reply.primary("Pong!")
  })
```

::tip{title="Importation automatique"}
`GlyriaCommand` est disponible globalement — aucun import n'est nécessaire.
::

## GlyriaCommand

### Méthodes

| Méthode                   | Retourne | Description                                                       |
| ------------------------- | -------- | ----------------------------------------------------------------- |
| `.setName(name)`          | `this`   | Définit le nom de la commande                                     |
| `.setDescription(desc)`   | `this`   | Définit la description de la commande                             |
| `.setPermissions(perms)`  | `this`   | Restreint la commande à des permissions spécifiques               |
| `.setCooldown(input)`     | `this`   | Ajoute un cooldown par utilisateur, par serveur ou global         |
| `.setOwnerOnly(bool?)`    | `this`   | Restreint la commande au propriétaire du bot                      |
| `.setMetaData(meta)`      | `this`   | Attache des métadonnées personnalisées à la commande              |
| `.addStringOption(fn)`    | `this`   | Ajoute une option texte                                           |
| `.addBooleanOption(fn)`   | `this`   | Ajoute une option booléenne                                       |
| `.addIntegerOption(fn)`   | `this`   | Ajoute une option entière                                         |
| `.addNumberOption(fn)`    | `this`   | Ajoute une option numérique                                       |
| `.addUserOption(fn)`      | `this`   | Ajoute une option utilisateur                                     |
| `.addRoleOption(fn)`      | `this`   | Ajoute une option rôle                                            |
| `.addSubCommand(fn)`      | `this`   | Ajoute une sous-commande                                          |
| `.addSubCommandGroup(fn)` | `this`   | Ajoute un groupe de sous-commandes                                |
| `.execute(handler)`       | `this`   | Définit le gestionnaire de la commande                            |
| `.getAutocompletes()`     | `AutocompleteEntry[]` | Liste tous les handlers d'autocomplétion enregistrés (usage interne du framework) |

### `.setPermissions()`

Restreint la commande aux membres possédant des permissions Discord spécifiques. Accepte :

- un `bigint`, un `number` ou une `string` — utilisé tel quel comme bitfield Discord `default_member_permissions`
- un tableau `PermissionName[]` (ex. `["BanMembers"]`) — les noms sont combinés en OR dans le bitfield `default_member_permissions` **et** revérifiés à l'exécution par Glyria

```ts
// Bitfield brut — vérification côté Discord uniquement
export default new GlyriaCommand()
  .setName("ban")
  .setDescription("Ban a user")
  .setPermissions(djs.PermissionsBitField.Flags.BanMembers)

// Forme tableau — vérification côté Discord + garde à l'exécution
export default new GlyriaCommand()
  .setName("ban")
  .setDescription("Ban a user")
  .setPermissions(["BanMembers"])
```

Avec la forme tableau, quand un membre sans la permission exécute quand même la commande (ex. un admin a assoupli l'override côté Discord), Glyria la refuse avec une erreur éphémère stylisée listant la ou les permissions manquantes :

> ❌ You need the following permission(s) to use this command: **Ban Members**

`PermissionName` est n'importe quelle clé de `PermissionFlagsBits` de discord.js (`"BanMembers"`, `"ManageGuild"`, `"ModerateMembers"`, ...).

### `.setCooldown()`

Ajoute un cooldown déclaratif. Accepte un `CooldownInput` :

| Forme                           | Signification                                                        |
| ------------------------------- | -------------------------------------------------------------------- |
| `"5s"`, `"2m"`, `"1h"`, `"1d"`  | Chaîne de durée — appliquée comme cooldown **par utilisateur**       |
| `5000`                          | Nombre de millisecondes — appliqué comme cooldown **par utilisateur** |
| `{ user?, guild?, global? }`    | Durées par portée (chacune une chaîne ou un nombre de millisecondes) |

```ts
// 5 secondes par utilisateur
export default new GlyriaCommand()
  .setName("daily")
  .setDescription("Claim your daily reward")
  .setCooldown("5s")

// Portées différentes
export default new GlyriaCommand()
  .setName("raffle")
  .setDescription("Start a raffle")
  .setCooldown({ user: "30s", guild: "5m", global: "10s" })
```

Quand une portée est encore en cooldown, Glyria répond avec une erreur éphémère stylisée :

> ❌ You're on cooldown — try again in **4s**.

Les cooldowns ne sont consommés qu'une fois que toutes les autres gardes (permissions, owner-only) sont passées.

### `.setOwnerOnly()`

Restreint la commande au propriétaire du bot (résolu depuis l'application Discord). Vaut `true` par défaut quand appelée sans argument.

```ts
export default new GlyriaCommand()
  .setName("eval")
  .setDescription("Owner only!")
  .setOwnerOnly()
```

Les non-propriétaires reçoivent une erreur éphémère stylisée :

> ❌ This command is restricted to the bot owner.

### `.setMetaData()`

Attache des métadonnées personnalisées à la commande. Accepte n'importe quel objet clé-valeur — Glyria les stocke telles quelles et ne les interprète jamais.

```ts
export default new GlyriaCommand()
  .setName("ban")
  .setDescription("Ban a user")
  .setMetaData({
    category: "moderation",
    premium: false,
    guildOnly: true,
  })
  .execute(async (ctx) => {
    // votre logique ici
  })
```

Les métadonnées sont accessibles à l'exécution via `useCommands()` :

```ts
const commands = useCommands()
// [
//   { name: "ban", description: "Ban a user", meta: { category: "moderation", ... } },
//   { name: "ping", description: "Pong!", meta: {} },
// ]
```

::tip{title="useCommands"}
`useCommands()` est disponible globalement — aucun import n'est nécessaire. Le registre est automatiquement rempli au démarrage du bot.
::

### `.execute()`

Définit le gestionnaire de la commande. Le handler reçoit un `GlyriaContext<ChatInputCommandInteraction>` — l'interaction discord.js brute avec un namespace `ctx.g` supplémentaire contenant toute la boîte à outils Glyria (réponses stylisées, confirm, paginate, store, canvas, ...).

```ts
export default new GlyriaCommand()
  .setName("ping")
  .setDescription("Pong!")
  .execute(async (ctx) => {
    // ctx = la ChatInputCommandInteraction, intacte
    const ws = ctx.client.ws.ping

    // ctx.g = la couche Glyria
    await ctx.g.reply.success(`Pong! (${ws}ms)`)
  })
```

Voir [ReplyableContext](/api-reference/replyable-context) pour l'API `ctx.g` complète.

## CommandOption

Passé en argument dans chaque callback `add*Option`.

### Méthodes

| Méthode                    | Retourne | Description                                                                 |
| -------------------------- | -------- | --------------------------------------------------------------------------- |
| `.setName(name)`           | `this`   | Définit le nom de l'option                                                  |
| `.setDescription(desc)`    | `this`   | Définit la description de l'option                                          |
| `.setRequired(bool)`       | `this`   | Rend l'option obligatoire                                                   |
| `.setAutocomplete(handler)`| `this`   | Attache un handler d'autocomplétion inline (options string/integer/number uniquement) |

### Exemple

```ts
.addStringOption((option) =>
  option
    .setName("reason")
    .setDescription("Reason of the ban")
    .setRequired(false)
)
```

### `.setAutocomplete()`

Attache un handler d'autocomplétion inline directement sur l'option — aucun fichier de handler séparé nécessaire. Disponible uniquement sur les options **string**, **integer** et **number**.

```ts
type AutocompleteHandler = (
  query: string,
  interaction: AutocompleteInteraction,
) => AutocompleteChoice[] | Promise<AutocompleteChoice[]>

type AutocompleteChoice = string | number | { name: string; value: string | number }
```

Le handler reçoit la saisie actuelle de l'utilisateur (`query`) et l'`AutocompleteInteraction` brute, et retourne des choix. Les chaînes et nombres simples sont utilisés à la fois comme nom et valeur ; utilisez la forme `{ name, value }` pour afficher un libellé différent.

```ts
const FRUITS = ["apple", "banana", "cherry", "mango"]

export default new GlyriaCommand()
  .setName("eat")
  .setDescription("Eat a fruit")
  .addStringOption((option) =>
    option
      .setName("fruit")
      .setDescription("Which fruit?")
      .setRequired(true)
      .setAutocomplete((query) =>
        FRUITS.filter((f) => f.startsWith(query.toLowerCase()))
      )
  )
  .execute(async (ctx) => {
    await ctx.g.reply.success(`Yum, ${ctx.options.getString("fruit")}!`)
  })
```

Le handler peut être async — interrogez une API, le store, une base de données :

```ts
.setAutocomplete(async (query, interaction) => {
  const tags = await fetchTags(interaction.guildId)
  return tags
    .filter((t) => t.name.includes(query))
    .map((t) => ({ name: `🏷️ ${t.name}`, value: t.id }))
})
```

### `.getAutocompletes()`

Retourne chaque handler d'autocomplétion enregistré sur la commande (y compris les sous-commandes et groupes imbriqués) sous forme d'`AutocompleteEntry[]` — des paires `{ name, handler }` où `name` est la clé entièrement qualifiée (`"command::option"`, `"command:sub::option"`, `"command:group:sub::option"`). Glyria l'appelle en interne pour router les `AutocompleteInteraction` ; vous en aurez rarement besoin vous-même.

## GlyriaSubCommand

Passé en argument dans les callbacks `.addSubCommand()`.

### Méthodes

| Méthode                  | Retourne | Description                                                                 |
| ------------------------ | -------- | --------------------------------------------------------------------------- |
| `.setName(name)`         | `this`   | Définit le nom de la sous-commande                                          |
| `.setDescription(desc)`  | `this`   | Définit la description de la sous-commande                                  |
| `.setCooldown(input)`    | `this`   | Cooldown pour cette sous-commande (prime sur celui du parent)               |
| `.setPermissions(perms)` | `this`   | Vérification de permissions à l'exécution pour cette sous-commande (`PermissionName[]`, prime sur celle du parent) |
| `.setOwnerOnly(bool?)`   | `this`   | Restreint cette sous-commande au propriétaire du bot (prime sur le réglage du parent) |
| `.addStringOption(fn)`   | `this`   | Ajoute une option texte                                                     |
| `.addBooleanOption(fn)`  | `this`   | Ajoute une option booléenne                                                 |
| `.addIntegerOption(fn)`  | `this`   | Ajoute une option entière                                                   |
| `.addNumberOption(fn)`   | `this`   | Ajoute une option numérique                                                 |
| `.addUserOption(fn)`     | `this`   | Ajoute une option utilisateur                                               |
| `.addRoleOption(fn)`     | `this`   | Ajoute une option rôle                                                      |
| `.execute(handler)`      | `this`   | Définit le gestionnaire de la sous-commande                                 |

Comme la commande parente, le handler de sous-commande reçoit un `GlyriaContext<ChatInputCommandInteraction>`, et les options supportent `.setAutocomplete()`.

::tip{title="Priorité des gardes"}
Les gardes définies sur la `GlyriaCommand` parente s'appliquent à toutes les sous-commandes ; une garde définie sur la sous-commande elle-même prime sur celle du parent pour cette sous-commande.
::

::warning{title="Les permissions de sous-commande sont vérifiées à l'exécution uniquement"}
Discord ne supporte `default_member_permissions` qu'au niveau de la commande, donc `.setPermissions()` sur une sous-commande accepte un `PermissionName[]` et est appliqué comme vérification à l'exécution avec une erreur stylisée — elle ne masque pas la sous-commande dans l'interface Discord.
::

### Exemple

```ts
.addSubCommand((cmd) =>
  cmd
    .setName("ban")
    .setDescription("Ban a user")
    .setPermissions(["BanMembers"])
    .setCooldown("3s")
    .addUserOption((option) =>
      option.setName("user").setDescription("User to ban").setRequired(true)
    )
    .execute(async (ctx) => {
      await ctx.g.reply.success("User banned.").ephemeral()
    })
)
```

## GlyriaSubCommandGroup

Passé en argument dans les callbacks `.addSubCommandGroup()`.

### Méthodes

| Méthode                 | Retourne | Description                        |
| ----------------------- | -------- | ---------------------------------- |
| `.setName(name)`        | `this`   | Définit le nom du groupe           |
| `.setDescription(desc)` | `this`   | Définit la description du groupe   |
| `.addSubCommand(fn)`    | `this`   | Ajoute une sous-commande au groupe |

### Exemple

```ts
.addSubCommandGroup((group) =>
  group
    .setName("config")
    .setDescription("Configuration commands")
    .addSubCommand((cmd) =>
      cmd
        .setName("logs")
        .setDescription("Configure logs")
        .addBooleanOption((option) =>
          option.setName("enabled").setDescription("Enable logs").setRequired(true)
        )
        .execute(async (ctx) => {
          await ctx.g.reply.success("Logs configuration updated.").ephemeral()
        })
    )
)
```
