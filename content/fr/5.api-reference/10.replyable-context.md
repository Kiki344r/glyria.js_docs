## Vue d'ensemble

Chaque handler de commande, de composant et d'événement reçoit un `GlyriaContext<T>` — l'objet discord.js brut (`T`) intact, plus un namespace `g` contenant toute la boîte à outils Glyria.

```ts
export default new GlyriaCommand()
  .setName("profile")
  .setDescription("Show your profile")
  .execute(async (ctx) => {
    // ctx est la ChatInputCommandInteraction — tout discord.js fonctionne toujours
    const name = ctx.user.username

    // ctx.g est la couche Glyria
    const xp = (await ctx.g.store.user.get<number>("xp")) ?? 0
    await ctx.g.reply
      .primary(`Profile of ${name}`)
      .field("XP", String(xp))
      .ephemeral()
  })
```

```ts
type GlyriaContext<T extends Replyable> = T & { g: GlyriaG<T> }
```

Vous pouvez envelopper vous-même n'importe quel objet capable de répondre avec `createReplyableContext(source)` — le framework le fait automatiquement avant d'invoquer vos handlers.

::tip{title="Auto-defer"}
Avant d'invoquer un handler, Glyria arme un `deferReply` automatique qui se déclenche après ~1,5s si vous n'avez pas encore répondu — vous ne butez jamais sur la fenêtre d'interaction de 3 secondes de Discord. Tout envoi via `ctx.g` annule le timer.
::

## Réponses stylisées

### `ctx.g.reply`

Six senders stylisés, un par variante. Chacun retourne une **`ReplyChain` thenable** — `await`-ez-la directement, ou chaînez d'abord des méthodes de construction.

| Sender                | Couleur (clé du thème) | Préfixe |
| --------------------- | ------------------ | ------ |
| `reply.primary(content, opts?)`   | `primaryColor` (`#5865F2`)   | —    |
| `reply.secondary(content, opts?)` | `secondaryColor` (`#4F545C`) | —    |
| `reply.success(content, opts?)`   | `successColor` (`#57F287`)   | ✅   |
| `reply.warning(content, opts?)`   | `warningColor` (`#FEE75C`)   | ⚠️   |
| `reply.error(content, opts?)`     | `errorColor` (`#ED4245`)     | ❌   |
| `reply.info(content, opts?)`      | `infoColor` (`#5DADE2`)      | ℹ️   |

Les couleurs et préfixes viennent de votre [configuration de thème](/api-reference/define-glyria-config#themeembedv2).

Les envois sont routés automatiquement selon l'état de la source : interaction fraîche → `reply`, différée → `editReply`, déjà répondue → `followUp` (avec repli sur `channel.send`). Si la surface rejette les payloads Components V2, Glyria réessaie une fois en texte brut, en préservant les fichiers.

### ReplyChain

| Méthode                   | Retourne           | Description                                                        |
| ------------------------- | ------------------ | ------------------------------------------------------------------ |
| `.description(text)`      | `this`             | Ajoute un bloc de texte sous la ligne de titre                     |
| `.field(name, value)`     | `this`             | Ajoute un bloc `**name**\nvalue`                                   |
| `.file(data, name)`       | `this`             | Attache un fichier (`Buffer` ou chemin en string) affiché dans le container |
| `.ephemeral(bool?)`       | `this`             | Rend cet envoi éphémère (vaut `true` par défaut)                   |
| `.send()`                 | `Promise<unknown>` | Envoie explicitement — idempotent                                  |
| `.then(...)`              | —                  | La chaîne est thenable : `await` l'envoie                          |

```ts
await ctx.g.reply
  .success("Ban applied")
  .description("The user has been removed from the server.")
  .field("Reason", reason)
  .file(logBuffer, "audit.txt")
  .ephemeral()
// await sur la chaîne l'envoie — pas besoin de .send()
```

### `ctx.g.reply.raw(payload)`

Porte de sortie : envoie un payload discord.js brut, en contournant entièrement le style Embed V2 (toujours routé et enregistré dans `history()`).

```ts
await ctx.g.reply.raw({ content: "plain text", embeds: [myEmbed] })
```

### `ctx.g.reply.loading(content, promise, opts?)`

Envoie un message de chargement stylisé `⏳` (couleur secondaire), attend la promesse, puis modifie le message avec le résultat — style success si résolue, style error si rejetée. Résout avec le résultat de la promesse et **relance** l'erreur en cas d'échec.

```ts
const user = await ctx.g.reply.loading(
  "Fetching profile...",
  fetchProfile(id),
  {
    done: (result) => `Found ${(result as Profile).name}!`,
    fail: (error) => `Lookup failed: ${String(error)}`,
  },
)
```

#### LoadingOptions

| Option      | Type                                  | Défaut                   | Description                          |
| ----------- | ------------------------------------- | ------------------------ | ------------------------------------ |
| `ephemeral` | `boolean`                             | défaut du contexte       | Envoie le message de chargement en éphémère |
| `done`      | `string \| (result) => string`        | `"Done"`                 | Message affiché en cas de résolution |
| `fail`      | `string \| (error) => string`         | `"Something went wrong"` | Message affiché en cas de rejet      |

## `ctx.g.followUp`

Les mêmes six senders stylisés (`primary`/`secondary`/`success`/`warning`/`error`/`info`, chacun retournant une `ReplyChain`) plus `.raw(payload)`, mais toujours envoyés comme message de suivi plutôt que comme réponse initiale.

```ts
await ctx.g.reply.success("Order created")
await ctx.g.followUp.info("A confirmation email has been sent").ephemeral()
```

## `ctx.g.confirm(content, opts?)`

Envoie un message de couleur warning avec des boutons **Confirm** / **Cancel** et résout à `true` ou `false`. Seul l'utilisateur à l'origine de l'invocation peut cliquer ; un timeout (ou tout échec de collecte) résout à `false` et désactive les boutons.

```ts
const ok = await ctx.g.confirm("Really delete all 42 warnings?", {
  timeout: "1m",
  confirmLabel: "Delete",
  cancelLabel: "Keep",
})
if (!ok) return ctx.g.reply.secondary("Cancelled.")
```

### ConfirmOptions

| Option         | Type       | Défaut      | Description                                              |
| -------------- | ---------- | ----------- | -------------------------------------------------------- |
| `timeout`      | `Duration` | `"30s"`     | Délai d'inactivité avant que la confirmation résolve à `false` |
| `confirmLabel` | `string`   | `"Confirm"` | Libellé du bouton de confirmation                        |
| `cancelLabel`  | `string`   | `"Cancel"`  | Libellé du bouton d'annulation                           |
| `ephemeral`    | `boolean`  | défaut du contexte | Envoie l'invite en éphémère                       |

`Duration` est une chaîne comme `"500ms"`, `"5s"`, `"2m"`, `"1h"`, `"1d"` ou un nombre de millisecondes.

## `ctx.g.paginate(pages, opts?)`

Affiche un tableau de pages (chaînes) avec des boutons ◀ / ▶ et un indicateur de page. Seul l'utilisateur à l'origine de l'invocation peut naviguer ; les boutons sont désactivés à l'expiration du timeout. Une page unique est envoyée sans boutons. Lève une exception quand `pages` est vide.

```ts
const pages = chunks.map((c, i) => `**Page ${i + 1}**\n${c}`)
await ctx.g.paginate(pages, { timeout: "5m", ephemeral: true })
```

### PaginateOptions

| Option      | Type       | Défaut  | Description                                              |
| ----------- | ---------- | ------- | -------------------------------------------------------- |
| `timeout`   | `Duration` | `"2m"`  | Délai d'inactivité avant la désactivation des boutons de pagination |
| `ephemeral` | `boolean`  | défaut du contexte | Envoie les pages en éphémère                    |

## `ctx.g.edit(content, opts?)`

Modifie le **dernier message envoyé via ce contexte** avec un payload fraîchement stylisé. La variante prend par défaut celle du dernier envoi (ou `primary` si le dernier envoi était raw) ; passez `{ variant }` pour changer le style. Lève une exception si rien n'a encore été envoyé.

```ts
await ctx.g.reply.secondary("Working...")
// ...
await ctx.g.edit("All done!", { variant: "success" })
```

## `ctx.g.defer(opts?)`

Diffère la réponse explicitement (sans effet si déjà différée/répondue, ou si la source n'a pas de `deferReply`).

```ts
await ctx.g.defer({ ephemeral: true })
```

::tip{title="Typage conditionnel"}
`defer` n'existe sur le contexte que lorsque la source supporte `deferReply` (interactions — pas les simples messages). De même, `update` n'existe que pour les interactions de composants. TypeScript l'impose : `GlyriaG<T>` n'ajoute chaque membre que lorsque `T` le supporte.
::

## `ctx.g.ephemeral(bool?)`

Définit le comportement éphémère **par défaut** pour chaque envoi ultérieur depuis ce contexte (vaut `true` par défaut quand appelée sans argument). Les options par envoi priment toujours. Ignoré sur les sources qui ne peuvent pas être éphémères (simples messages).

```ts
ctx.g.ephemeral() // tout ce qui suit est éphémère par défaut
```

## `ctx.g.history()`

Retourne une copie de chaque message envoyé via ce contexte, le plus récent en dernier.

### SentEntry

| Champ       | Type                                          | Description                              |
| ----------- | --------------------------------------------- | ---------------------------------------- |
| `variant`   | `ReplyVariant \| "raw"`                       | Style utilisé (`"raw"` pour les envois non stylisés) |
| `via`       | `"reply" \| "followUp" \| "edit" \| "update"` | Canal de livraison réellement utilisé    |
| `payload`   | `unknown`                                     | Le payload qui a été envoyé              |
| `message`   | `unknown`                                     | L'objet message / réponse résultant      |
| `timestamp` | `number`                                      | `Date.now()` au moment de l'envoi        |

## `ctx.g.onSend(listener)`

Enregistre un callback invoqué après chaque message envoyé via ce contexte. Un listener qui lève une exception est loggé et ne casse jamais l'envoi.

```ts
ctx.g.onSend((entry) => analytics.track("bot_reply", { via: entry.via }))
```

## `ctx.g.log(message, level?)`

Logge dans la console et — quand `logChannel` est défini dans `glyria.config.ts` — publie un message stylisé dans ce salon Discord. `level` vaut `"info"` (défaut), `"warn"` ou `"error"` et correspond aux variantes info/warning/error.

```ts
await ctx.g.log(`${ctx.user.tag} purged 50 messages`, "warn")
```

## `ctx.g.user` / `ctx.g.member`

| Getter   | Description                                                              |
| -------- | ------------------------------------------------------------------------ |
| `user`   | L'utilisateur à l'origine de l'invocation — `interaction.user` ou `message.author` |
| `member` | Le membre de serveur à l'origine de l'invocation, quand disponible        |

## `ctx.g.store`

Store d'état intégré, pré-scopé à l'invocation. Voir [Store](/api-reference/store) pour l'API `ScopedStore` et la configuration des adapters.

| Portée         | Type          | Description                                            |
| -------------- | ------------- | ------------------------------------------------------ |
| `store.guild`  | `ScopedStore` | Scopé au serveur courant — lève une exception en DM    |
| `store.user`   | `ScopedStore` | Scopé à l'utilisateur à l'origine de l'invocation      |
| `store.global` | `ScopedStore` | Portée globale au bot                                  |

```ts
const xp = (await ctx.g.store.user.get<number>("xp")) ?? 0
await ctx.g.store.user.set("xp", xp + 10)
```

## `ctx.g.guildConfig`

Un `ScopedStore` avec un namespace dédié à la configuration par serveur, séparé des données de serveur classiques. Lève une exception en DM.

```ts
await ctx.g.guildConfig.set("welcomeChannel", channel.id)
const welcome = await ctx.g.guildConfig.get<string>("welcomeChannel")
```

## `ctx.g.canvas`

Le générateur visuel intégré — cartes de rang et classements en SVG/PNG. Voir [Canvas](/api-reference/canvas).

```ts
const card = await ctx.g.canvas
  .rankCard({ username: "Enzo", level: 12, xp: 340, xpNeeded: 500, rank: 3 })
  .attachment()

await ctx.g.reply.primary("Your rank").file(card.data, card.name)
```

## `ctx.g.update` (interactions de composants uniquement)

Pour les interactions de boutons, de menus déroulants et de modals, `ctx.g.update` expose les mêmes six senders stylisés mais restyle le **message du composant d'origine** (via `interaction.update`) au lieu d'en envoyer un nouveau. Les payloads d'update sont à envoi unique : l'update est déclenché dès que le sender est appelé, et les méthodes de construction chaînées (`description`/`field`/`file`/`ephemeral`) sont sans effet — passez `{ ephemeral }` en second argument à la place.

```ts
export default new GlyriaButton("verify:{userId}").execute(async (ctx, params) => {
  await ctx.g.update.success("You are verified!")
})
```

## Interfaces d'options

### ReplyOptions

| Option      | Type      | Description                       |
| ----------- | --------- | --------------------------------- |
| `ephemeral` | `boolean` | Envoie ce message en éphémère     |

Acceptée comme second argument de chaque sender stylisé — équivalent à chaîner `.ephemeral()`.

### Résumé des types

```ts
type ReplyVariant = "primary" | "secondary" | "success" | "warning" | "error" | "info"

interface ReplyOptions { ephemeral?: boolean }

interface ConfirmOptions {
  timeout?: Duration        // défaut "30s"
  confirmLabel?: string     // défaut "Confirm"
  cancelLabel?: string      // défaut "Cancel"
  ephemeral?: boolean
}

interface PaginateOptions {
  timeout?: Duration        // défaut "2m"
  ephemeral?: boolean
}

interface LoadingOptions extends ReplyOptions {
  done?: string | ((result: unknown) => string)  // défaut "Done"
  fail?: string | ((error: unknown) => string)   // défaut "Something went wrong"
}

interface SentEntry {
  variant: ReplyVariant | "raw"
  via: "reply" | "followUp" | "edit" | "update"
  payload: unknown
  message: unknown
  timestamp: number
}
```
