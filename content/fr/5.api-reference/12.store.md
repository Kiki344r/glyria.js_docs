## Vue d'ensemble

Glyria embarque un petit store clé-valeur asynchrone derrière `ctx.g.store`, `ctx.g.guildConfig`, les stores de modules et `useStore()`. Il est basé sur des adapters : en mémoire par défaut, persistance en fichier JSON prête à l'emploi, ou n'importe quel backend que vous branchez.

```ts
// Dans un handler — vues pré-scopées
const xp = (await ctx.g.store.user.get<number>("xp")) ?? 0
await ctx.g.store.user.set("xp", xp + 10)

// N'importe où — le store brut
const store = useStore()
await store.forGuild(guildId).set("prefix", "!")
```

L'adapter est sélectionné via la [clé `store` de `glyria.config.ts`](/api-reference/define-glyria-config#store).

## StoreAdapter

Le contrat que chaque backend implémente. Toutes les méthodes sont asynchrones.

```ts
interface StoreAdapter {
  get(key: string): Promise<unknown>
  set(key: string, value: unknown): Promise<void>
  delete(key: string): Promise<boolean>
  keys(prefix: string): Promise<string[]>
}
```

| Méthode         | Retourne           | Description                                     |
| --------------- | ------------------ | ----------------------------------------------- |
| `get(key)`      | `Promise<unknown>` | Lit une valeur (`undefined` si absente)         |
| `set(key, value)` | `Promise<void>`  | Écrit une valeur                                |
| `delete(key)`   | `Promise<boolean>` | Supprime une clé — `true` si elle existait      |
| `keys(prefix)`  | `Promise<string[]>`| Liste toutes les clés commençant par `prefix`   |

Implémentez cette interface pour adosser le store à Redis, SQLite, Postgres, ... et passez l'instance comme `store.adapter` dans votre config.

## MemoryStoreAdapter

L'adapter par défaut — une simple `Map` en mémoire. Aucune configuration, rien ne survit à un redémarrage.

```ts
const adapter = new MemoryStoreAdapter()
```

## JsonFileStoreAdapter

Persistance zéro-config : garde tout en mémoire et **debounce les écritures** vers un fichier JSON. Bien pour les petits bots ; branchez un vrai adapter pour tout usage sérieux.

```ts
new JsonFileStoreAdapter(path, flushDelay?)
```

| Paramètre    | Type     | Défaut  | Description                                            |
| ------------ | -------- | ------- | ------------------------------------------------------ |
| `path`       | `string` | —       | Fichier JSON à charger au démarrage et dans lequel écrire |
| `flushDelay` | `number` | `250`   | Délai de debounce (ms) entre une écriture et un flush  |

Comportement :

- À la construction, le fichier est chargé s'il existe (un fichier non parsable logge un avertissement et démarre vide).
- Chaque `set`/`delete` programme un flush `flushDelay` ms plus tard ; plusieurs écritures dans cette fenêtre sont fusionnées en une seule écriture de fichier.
- `flush()` écrit immédiatement, en annulant tout timer en attente (les répertoires parents sont créés si besoin).

| Méthode    | Retourne | Description                                       |
| ---------- | ------- | -------------------------------------------------- |
| `flush()`  | `void`  | Écrit le fichier maintenant, annule le timer en attente |

## ScopedStore

Chaque vue du store côté consommateur est un `ScopedStore` — les quatre mêmes opérations avec le préfixe de portée appliqué de manière transparente :

```ts
interface ScopedStore {
  get<T = unknown>(key: string): Promise<T | undefined>
  set(key: string, value: unknown): Promise<void>
  delete(key: string): Promise<boolean>
  keys(): Promise<string[]>
}
```

| Méthode           | Retourne                  | Description                                        |
| ----------------- | ------------------------- | -------------------------------------------------- |
| `get<T>(key)`     | `Promise<T \| undefined>` | Lit une valeur, typée via le générique             |
| `set(key, value)` | `Promise<void>`           | Écrit une valeur                                   |
| `delete(key)`     | `Promise<boolean>`        | Supprime une clé — `true` si elle existait         |
| `keys()`          | `Promise<string[]>`       | Les clés de cette portée, préfixe retiré           |

```ts
const inventory = ctx.g.store.user
await inventory.set("sword", { damage: 12 })
const sword = await inventory.get<{ damage: number }>("sword")
await inventory.keys()   // ["sword", ...]
await inventory.delete("sword")
```

## GlyriaStore

Le store racine, qui enveloppe un adapter et distribue des vues scopées :

| Membre                     | Retourne      | Préfixe de clé          | Description                                       |
| -------------------------- | ------------- | ----------------------- | ------------------------------------------------- |
| `global`                   | `ScopedStore` | `global:`               | Portée globale au bot                             |
| `forGuild(guildId)`        | `ScopedStore` | `guild:<id>:`           | Données par serveur                               |
| `forUser(userId)`          | `ScopedStore` | `user:<id>:`            | Données par utilisateur                           |
| `forModule(name)`          | `ScopedStore` | `module:<name>:`        | Portée avec namespace fournie aux modules (`ctx.store`) |
| `forGuildConfig(guildId)`  | `ScopedStore` | `guildconfig:<id>:`     | Configuration par serveur, séparée des données de serveur |

## configureStore(config)

Construit le singleton `GlyriaStore` à partir d'une `StoreConfig`. Appelée par le framework au démarrage avec l'entrée `store` de votre `glyria.config.ts` — ne l'appelez vous-même que dans des scripts/tests.

```ts
interface StoreConfig {
  adapter?: "memory" | "json" | StoreAdapter
  /** Chemin du fichier JSON quand adapter vaut "json". Défaut : .glyria/store.json */
  path?: string
}
```

| Valeur d'`adapter`     | Résultat                                                          |
| ---------------------- | ----------------------------------------------------------------- |
| omise ou `"memory"`    | `MemoryStoreAdapter`                                              |
| `"json"`               | `JsonFileStoreAdapter` à `path` (défaut `.glyria/store.json`, résolu depuis le cwd) |
| un objet `StoreAdapter`| Utilisé tel quel                                                  |

```ts
configureStore({ adapter: "json", path: ".glyria/store.json" })
```

## useStore()

Retourne le singleton `GlyriaStore`. Si `configureStore()` n'a jamais été appelée, un store en mémoire est créé paresseusement.

```ts
const store = useStore()
await store.global.set("startedAt", Date.now())
```

::tip{title="Importation automatique"}
`useStore` est disponible globalement — aucun import n'est nécessaire.
::
