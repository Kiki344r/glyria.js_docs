## Vue d'ensemble

`GlyriaButton`, `GlyriaSelect` et `GlyriaModal` définissent des handlers pour les composants interactifs. Le constructeur prend un **motif de customId** avec des placeholders `{param}` — Glyria fait correspondre les interactions entrantes avec ce motif et passe à votre handler les paramètres extraits, entièrement typés.

```ts
// src/components/rolePicker.ts
export default new GlyriaButton("role_picker:{roleId}:{userId}")
  .execute(async (ctx, params) => {
    // params: { roleId: string; userId: string } — inféré depuis le motif
    await ctx.g.update.success(`Role <@&${params.roleId}> assigned!`)
  })
```

Les fichiers de composants vivent dans `src/components/` (scanné récursivement). Un fichier peut exporter un composant en `default` ou plusieurs en exports nommés — chaque instance de `GlyriaButton` / `GlyriaSelect` / `GlyriaModal` exportée est enregistrée. Les modules peuvent aussi embarquer leur propre dossier `components/`.

::tip{title="Importation automatique"}
`GlyriaButton`, `GlyriaSelect` et `GlyriaModal` sont disponibles globalement — aucun import n'est nécessaire.
::

## Constructeurs

### `GlyriaButton<P>` / `GlyriaSelect<P>` / `GlyriaModal<P>`

Les trois partagent la même forme — seul le type d'interaction passé au handler diffère :

| Classe         | Contexte du handler                          |
| -------------- | -------------------------------------------- |
| `GlyriaButton` | `GlyriaContext<ButtonInteraction>`           |
| `GlyriaSelect` | `GlyriaContext<AnySelectMenuInteraction>`    |
| `GlyriaModal`  | `GlyriaContext<ModalSubmitInteraction>`      |

#### Constructeur

```ts
new GlyriaButton("confirm_ban:{userId}")
```

Le motif (une chaîne avec des placeholders `{param}` optionnels) est l'unique argument du constructeur et est disponible via la propriété en lecture seule `pattern`.

#### Méthodes

| Méthode              | Retourne              | Description                                                          |
| -------------------- | --------------------- | -------------------------------------------------------------------- |
| `.execute(handler)`  | `this`                | Définit le handler : `(ctx, params) => unknown` avec `params: PatternParams<P>` |
| `.id(params)`        | `string`              | Construit un customId concret pour ce composant (à utiliser au rendu) |
| `.build()`           | `ComponentDefinition` | Compile le motif en une définition — lève une exception si aucun handler `execute()` n'a été défini |

```ts
export const banButton = new GlyriaButton("confirm_ban:{userId}")
  .execute(async (ctx, params) => {
    await ctx.guild?.members.ban(params.userId)
    await ctx.g.update.success("User banned.")
  })

// ailleurs, au moment de rendre le bouton :
const customId = banButton.id({ userId: target.id })
// "confirm_ban:123456789"
```

## `PatternParams<P>`

Les noms des paramètres sont inférés **depuis le type de la chaîne du motif** — chaque placeholder `{name}` devient une propriété `string` requise :

```ts
type PatternParams<"role_picker:{roleId}:{userId}">
// => { roleId: string; userId: string }

type PatternParams<"refresh">
// => {} (aucun paramètre)
```

C'est ce qui rend `params` dans `.execute()` et l'argument de `.id()` entièrement typés : renommer un placeholder dans le motif signale immédiatement chaque site d'appel.

## Helpers

### `buildCustomId(pattern, params)`

Construit un customId concret en substituant chaque placeholder `{name}` par `params[name]`. C'est ce que `.id()` appelle en interne.

```ts
buildCustomId("role_picker:{roleId}", { roleId: "42" })
// => "role_picker:42"
```

Lève une exception quand :

- un placeholder n'a pas de paramètre correspondant — `customId: missing param "roleId" for "role_picker:{roleId}"`
- la valeur d'un paramètre contient `":"` — `customId: param "roleId" cannot contain ":"` (le `:` est le séparateur de segments, donc les valeurs ne doivent pas en contenir)

### `compilePattern(pattern)`

Compile un motif en une `RegExp` ancrée avec des groupes de capture nommés — chaque placeholder correspond à un segment `[^:]+`. Les parties littérales sont échappées pour la regex.

```ts
compilePattern("role_picker:{roleId}")
// => /^role_picker:(?<roleId>[^:]+)$/
```

Glyria utilise la regex compilée pour router les interactions entrantes et extraire les paramètres.

## ComponentDefinition

`.build()` retourne la forme brute que le loader enregistre :

```ts
type ComponentKind = "button" | "select" | "modal"

interface ComponentDefinition {
  kind: ComponentKind
  pattern: string
  regex: RegExp
  handler: (ctx: never, params: Record<string, string>) => unknown
}
```

Vous n'appelez normalement jamais `.build()` vous-même — le loader le fait pour chaque composant exporté.

## Emplacements des fichiers

| Emplacement                       | Chargé |
| --------------------------------- | ------ |
| `src/components/**` (récursif)    | ✅     |
| `src/modules/<name>/components/`  | ✅     |
| `<npm module pkg>/components/`    | ✅ (pour les packages listés dans `modules`) |

Un fichier peut exporter un seul composant en `default` ou plusieurs composants en exports nommés :

```ts
// src/components/tickets.ts
export const openTicket = new GlyriaButton("ticket:open:{userId}")
  .execute(async (ctx, params) => { /* ... */ })

export const closeTicket = new GlyriaButton("ticket:close:{ticketId}")
  .execute(async (ctx, params) => { /* ... */ })

export const ticketTopic = new GlyriaSelect("ticket:topic:{ticketId}")
  .execute(async (ctx, params) => {
    const topic = ctx.values[0]
    await ctx.g.update.info(`Topic set to ${topic}`)
  })
```
