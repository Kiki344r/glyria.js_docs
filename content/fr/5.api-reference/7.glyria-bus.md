## Vue d'ensemble

`GlyriaBus` est un bus d'événements pub/sub (publication/abonnement) typé avec support des middlewares. Il vous permet de faire communiquer les différentes parties de votre bot entre elles sans les coupler.

```ts
// src/utils/useBus.ts
type BotEvents = {
  userBanned: [guildId: string, userId: string, reason: string]
  levelUp: [userId: string, level: number]
}

export const useBus = new GlyriaBus<BotEvents>()
```

::tip{title="Auto-import"}
`GlyriaBus` est disponible globalement — aucun import n'est nécessaire. Définissez votre bus dans `src/utils/` et il sera auto-importé partout.
::

## Constructeur

```ts
new GlyriaBus<Events>()

```

### Paramètre de type

`Events` est un objet (record) associant les noms des événements aux types de leur contenu (sous forme de tuples) :

```ts
type Events = {
  userBanned: [guildId: string, userId: string]
  levelUp: [userId: string, level: number]
}

```

## Méthodes

### `.on(event, listener)`

Enregistre un écouteur (listener) pour un événement. Retourne une fonction de désinscription.

```ts
const stop = useBus.on("userBanned", (guildId, userId) => {
  console.log(`${userId} a été banni de ${guildId}`)
})

// plus tard
stop()

```

| Paramètre  | Type                  | Description                                      |
| ---------- | --------------------- | ------------------------------------------------ |
| `event`    | `keyof Events`        | Nom de l'événement                               |
| `listener` | `Listener<Events[K]>` | Gestionnaire recevant les données de l'événement |

**Retourne** `() => void` — appelez cette fonction pour supprimer l'écouteur.

---

### `.once(event, listener)`

Enregistre un écouteur supprimé après son premier appel. Retourne une fonction de désinscription, comme `.on()`.

```ts
useBus.once("userBanned", (guildId, userId, reason) => {
  console.log("premier ban uniquement")
})
```

---

### `.use(event, middleware)`

Enregistre un middleware pour un événement. Les middlewares et les écouteurs partagent une file unique et s'exécutent dans le pur ordre d'enregistrement — un middleware enregistré après un écouteur `.on()` s'exécute après lui. Un middleware reçoit le payload complet plus `next` comme dernier argument, et doit appeler `next()` pour poursuivre la chaîne.

```ts
useBus.use("userBanned", async (guildId, userId, reason, next) => {
  console.log(`[middleware] bannissement reçu`)
  await next()
})

```

| Paramètre    | Type                    | Description                                     |
| ------------ | ----------------------- | ----------------------------------------------- |
| `event`      | `keyof Events`          | Nom de l'événement                              |
| `middleware` | `Middleware<Events[K]>` | Gestionnaire avec `next` comme dernier argument |

---

### `.emit(event, ...args)`

Émet un événement avec des arguments typés. Exécute tous les middlewares et écouteurs dans l'ordre.

```ts
await useBus.emit("userBanned", guildId, userId, reason)

```

| Paramètre | Type           | Description                   |
| --------- | -------------- | ----------------------------- |
| `event`   | `keyof Events` | Nom de l'événement            |
| `...args` | `Events[K]`    | Données typées de l'événement |

**Retourne** `Promise<void>`

---

### `.off(event, middleware)`

Supprime un middleware spécifique pour un événement. Ne fonctionne qu'avec la fonction exacte passée à `.use()` — un écouteur enregistré via `.on()` est enveloppé en interne, donc `.off()` ne peut pas le supprimer. Utilisez plutôt la fonction de désinscription retournée par `.on()`.

```ts
useBus.off("userBanned", myMiddleware)

```

---

### `.clear(event)`

Supprime tous les écouteurs et middlewares pour un événement.

```ts
useBus.clear("userBanned")

```

---

## Types

### `Middleware<T>`

```ts
type Middleware<T extends unknown[]> = (
  ...args: [...ctx: T, next: NextFunction]
) => unknown

```

### `Listener<T>`

```ts
type Listener<T extends unknown[]> = (...ctx: T) => unknown

```

### `NextFunction`

```ts
type NextFunction = () => void | Promise<void>

```

## Chaîne de middlewares

Les middlewares et les écouteurs s'exécutent dans leur ordre d'enregistrement. Le fait de ne pas appeler `next()` interrompt la chaîne — les middlewares et écouteurs suivants ne seront pas exécutés.

```ts
useBus.use("levelUp", async (userId, level, next) => {
  if (level < 5) return // s'arrête ici, l'écouteur ne s'exécutera jamais
  await next()
})

useBus.on("levelUp", (userId, level) => {
  console.log(`${userId} a atteint le niveau ${level}`)
})

```

## globalBus

`globalBus` est une instance singleton de `GlyriaBus` fournie avec glyria.js. Contrairement à un bus que vous créez vous-même, il est partagé dans tout votre projet et par chaque module chargé — ce qui en fait l'endroit canonique pour les événements de cycle de vie du framework.

```ts
globalBus.on("botReady", (client) => {
  console.log(`Connecté en tant que ${client.user?.tag}`)
})
```

::tip{title="Auto-import"}
`globalBus` est disponible globalement — aucun import nécessaire.
::

### Événements

| Événement  | Payload          | Description                                                       |
| ---------- | ---------------- | ---------------------------------------------------------------- |
| `botReady` | `[GlyriaClient]` | Émis une seule fois, lorsque le client est connecté et prêt      |

`botReady` est le point d'entrée recommandé pour la logique d'initialisation — en particulier dans les [modules](/docs/guide/modules), où il remplace un écouteur d'événement `ready`.

```ts
// dans le index.ts d'un module
globalBus.on("botReady", async (client) => {
  // accès sûr à client.user, guilds, etc.
  client.bus.on(Events.MessageCreate, (message) => {
    // ...
  })
})
```

::warning{title="globalBus vs votre propre bus"}
Utilisez `globalBus` uniquement pour les événements de cycle de vie du framework comme `botReady`. Pour les événements propres à votre application, créez un `GlyriaBus` typé dédié afin que ses noms d'événements et payloads restent isolés et entièrement typés.
::
