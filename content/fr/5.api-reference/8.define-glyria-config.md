## Vue d'ensemble

`defineGlyriaConfig` est un helper typé pour définir la configuration globale de votre bot dans `glyria.config.ts` à la racine de votre projet.

```ts
// glyria.config.ts
export default defineGlyriaConfig({
  modules: ["@glyria/economy"],
  moduleConfig: {
    economy: { startingBalance: 100 },
  },
  logChannel: "1234567890123456789",
  store: { adapter: "json" },
  changelog: { channel: "1234567890123456789" },
  dev: {
    restartPaths: ['composables', 'utils', 'services'],
    autoImportDirs: ['utils', 'composables']
  },
  theme: {
    embedV2: {
      primaryColor: "#5865F2",
      successColor: "#57F287",
      errorColor: "#ED4245",
      footer: {
        text: "My Bot • v1.0",
      }
    }
  }
})
```

::tip{title="Importation automatique"}
`defineGlyriaConfig` est disponible globalement — aucun import n'est nécessaire.
::

::tip{title="Hot reload"}
`glyria.config.ts` est rechargé à chaud en mode dev — aucun redémarrage nécessaire quand vous mettez à jour votre config.
::

## GlyriaConfig

Chaque clé est optionnelle.

| Clé                 | Type                          | Description                                                              |
| ------------------- | ----------------------------- | ------------------------------------------------------------------------ |
| `modules`           | `string[]`                    | Packages npm à charger comme modules Glyria                              |
| `moduleConfig`      | `Record<string, unknown>`     | Configuration par module, validée par le schéma `config` de chaque module |
| `logChannel`        | `string`                      | Id du salon où `ctx.g.log()` et les notifications du framework sont publiés |
| `store`             | `StoreConfig`                 | Store d'état intégré (`ctx.g.store`). En mémoire par défaut              |
| `recording`         | `boolean`                     | Enregistre les interactions dans `.glyria/interactions` pour `glyria replay` |
| `changelog`         | `{ channel?: string }`        | Publie un changelog des commandes dans ce salon à chaque déploiement     |
| `dev`               | `{ autoImportDirs?, restartPaths? }` | Configuration du watcher du mode dev et des auto-imports          |
| `theme`             | `{ embedV2? }`                | Thème global pour les réponses Embed V2                                  |

### `modules`

Packages npm à charger comme modules Glyria, en plus du dossier local `src/modules/` (qui est toujours scanné automatiquement). Pour chaque package, Glyria importe `<pkg>/glyria.module.{ts,js}` ou se rabat sur `<pkg>/index.{ts,js}`, et charge aussi automatiquement les dossiers `commands/`, `events/` et `components/` du package.

```ts
export default defineGlyriaConfig({
  modules: ["@glyria/economy", "glyria-module-tickets"],
})
```

### `moduleConfig`

Configuration par module, indexée par nom de module. Chaque entrée est validée par le schéma `config` du module (voir [defineModule](/api-reference/define-module)) ; en son absence, le `defaultConfig` du module est utilisé.

```ts
export default defineGlyriaConfig({
  moduleConfig: {
    economy: { startingBalance: 100, currency: "🪙" },
    tickets: { category: "1234567890123456789" },
  },
})
```

::warning{title="Une config invalide désactive le module"}
Si le schéma d'un module rejette son entrée `moduleConfig`, le module est désactivé avec le statut `invalid config` — le bot continue de tourner.
::

### `logChannel`

Id du salon où `ctx.g.log(message, level)` et les notifications du framework sont publiés (stylisés avec les couleurs info/warning/error du thème). Le logging va toujours dans la console ; le salon Discord vient en plus.

```ts
export default defineGlyriaConfig({
  logChannel: "1234567890123456789",
})
```

### `store`

Configure le store d'état intégré derrière `ctx.g.store`, `ctx.g.guildConfig` et `useStore()`. Voir [Store](/api-reference/store) pour l'API complète.

| Option    | Type                                  | Défaut                | Description                                            |
| --------- | ------------------------------------- | --------------------- | ------------------------------------------------------ |
| `adapter` | `"memory" \| "json" \| StoreAdapter`  | `"memory"`            | Backend de stockage, ou une instance d'adapter personnalisé |
| `path`    | `string`                              | `.glyria/store.json`  | Chemin du fichier JSON quand `adapter` vaut `"json"`   |

```ts
export default defineGlyriaConfig({
  // Persistance zéro-config : en mémoire avec écritures JSON debouncées
  store: { adapter: "json", path: ".glyria/store.json" },
})
```

Passez n'importe quel objet implémentant l'interface `StoreAdapter` (`get`/`set`/`delete`/`keys`) pour brancher Redis, SQLite, ou tout autre backend :

```ts
import { myRedisAdapter } from "./services/redisStore"

export default defineGlyriaConfig({
  store: { adapter: myRedisAdapter },
})
```

### `recording`

Enregistre les interactions entrantes dans `.glyria/interactions` pour pouvoir les rejouer avec `glyria replay`. Toujours actif en mode dev ; définissez cette clé pour l'activer en production.

```ts
export default defineGlyriaConfig({
  recording: true,
})
```

### `changelog`

Quand `channel` est défini, Glyria diffe les commandes déployées avec le snapshot précédent (`.glyria/commands.snapshot.json`) à chaque déploiement et publie un changelog (commandes ajoutées / supprimées / modifiées) dans ce salon.

```ts
export default defineGlyriaConfig({
  changelog: {
    channel: "1234567890123456789",
  },
})
```

### `dev`

Configuration du watcher du mode dev et des auto-imports.

| Option           | Type       | Défaut                                 | Description                                                     |
| ---------------- | ---------- | -------------------------------------- | ---------------------------------------------------------------- |
| `restartPaths`   | `string[]` | `['composables', 'utils', 'services']` | Dossiers déclenchant un redémarrage complet du bot quand modifiés |
| `autoImportDirs` | `string[]` | `['utils', 'composables']`             | Dossiers scannés pour les globales auto-importées                 |

Par défaut, Glyria surveille votre dossier `src/` et applique le comportement suivant :

| Dossier                | Comportement                                                        |
| ---------------------- | -------------------------------------------------------------------- |
| `commands/`            | Hot reload — les commandes sont ré-enregistrées instantanément, pas de redémarrage |
| `events/`              | Hot reload — les listeners sont retirés et ré-ajoutés instantanément  |
| Dossiers `restartPaths` | Redémarrage complet — le processus du bot est proprement tué puis redémarré |
| Tout le reste          | Ignoré                                                                |

::tip{title="Pourquoi restartPaths ?"}
Les fichiers dans des dossiers comme `utils/` ou `services/` sont chargés une fois au démarrage et ne peuvent pas être rechargés à chaud de manière sûre en ESM. Un redémarrage propre est l'option la plus sûre.
::

::warning{title="Imports imbriqués"}
Si une commande importe un fichier depuis `utils/`, modifier ce fichier déclenchera un redémarrage (si `utils` est dans `restartPaths`) — mais s'il n'y est pas, l'ancien module peut rester en cache. Ajoutez le dossier à `restartPaths` pour garantir un rechargement propre.
::

#### `autoImportDirs`

Les dossiers listés dans `autoImportDirs` sont scannés au démarrage — chaque `export const`, `export function` et `export class` trouvé est injecté automatiquement dans le scope global.

Écrivez les noms de dossiers sans préfixe `src/` ni `dist/` — Glyria résout le bon chemin selon l'environnement.

```ts
export default defineGlyriaConfig({
  dev: {
    autoImportDirs: ['utils', 'composables', 'helpers', 'lib']
  }
})
```

::tip{title="src/index.ts"}
Les exports de `src/index.ts` sont toujours scannés automatiquement — aucune configuration nécessaire.
::

### `theme.embedV2`

Thème global appliqué automatiquement à tous les embeds construits avec `EmbedV2Builder` et à chaque envoi stylisé via `ctx.g`.

| Option           | Type             | Défaut    | Description                                       |
| ---------------- | ---------------- | --------- | -------------------------------------------------- |
| `primaryColor`   | `HexColorString` | `#5865F2` | Couleur pour `.g.reply.primary()`                  |
| `secondaryColor` | `HexColorString` | `#4F545C` | Couleur pour `.g.reply.secondary()`                |
| `successColor`   | `HexColorString` | `#57F287` | Couleur pour `.g.reply.success()`                  |
| `errorColor`     | `HexColorString` | `#ED4245` | Couleur pour `.g.reply.error()`                    |
| `infoColor`      | `HexColorString` | `#5DADE2` | Couleur pour `.g.reply.info()`                     |
| `warningColor`   | `HexColorString` | `#FEE75C` | Couleur pour `.g.reply.warning()`                  |
| `footer.text`    | `string`         | —         | Texte de pied de page ajouté à chaque container    |

#### Couleurs

Les couleurs sont définies comme des chaînes hexadécimales (`HexColorString` de discord.js) :

```ts
primaryColor: "#5865F2"  // ✅
primaryColor: 0x5865F2   // ❌ utilisez une chaîne hexadécimale, pas un nombre
```

#### Footer

Quand `footer.text` est défini, il est automatiquement ajouté à chaque `ContainerBuilder` lorsque `.end()` est appelé — aucun code supplémentaire nécessaire dans vos commandes.

```ts
theme: {
  embedV2: {
    footer: {
      text: "My Bot • v1.0"
    }
  }
}
```

## Exemple complet

```ts
// glyria.config.ts
export default defineGlyriaConfig({
  modules: ["@glyria/economy"],
  moduleConfig: {
    economy: { startingBalance: 100 },
  },
  logChannel: "1234567890123456789",
  store: { adapter: "json", path: ".glyria/store.json" },
  recording: true,
  changelog: { channel: "9876543210987654321" },
  dev: {
    autoImportDirs: ['utils', 'composables', 'helpers'],
    restartPaths: ['composables', 'utils', 'services']
  },
  theme: {
    embedV2: {
      primaryColor: "#7289DA",
      secondaryColor: "#747F8D",
      successColor: "#43B581",
      errorColor: "#F04747",
      warningColor: "#FAA61A",
      infoColor: "#00B0F4",
      footer: {
        text: "My Bot • v1.0"
      }
    }
  }
})
```
