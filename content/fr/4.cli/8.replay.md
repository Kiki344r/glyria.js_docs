## Utilisation

```bash
npx glyria replay --list   # les 20 enregistrements les plus récents
npx glyria replay <id>     # en rejouer un
```

## Comment les interactions sont enregistrées

En mode dev, **chaque exécution de commande est enregistrée automatiquement** — rien à activer. En production, définissez `recording: true` dans `glyria.config.ts`.

Chaque interaction est écrite dans `.glyria/interactions/<id>.json` avec tout le nécessaire pour la rejouer plus tard :

| Champ | Description |
|---|---|
| `key`, `kind` | Clé du handler résolue (ex. `config:theme:set`) et type (`chat`, `user`, `message`) |
| `userId`, `username`, `guildId`, `channelId` | Qui l'a exécutée, et où |
| `options`, `subcommand` | Valeurs d'options à plat et chemin de la sous-commande |
| `replies` | Chaque payload de réponse envoyé par le handler, avec méthode et timestamp |
| `error` | L'erreur, si le handler a levé une exception |

## `replay --list`

Affiche les 20 enregistrements les plus récents — un statut ✔/✖, l'id, la commande, l'utilisateur et depuis combien de temps elle a été exécutée :

```
  ✔ 1391442183218352109 /ping by enzo 2m ago
  ✖ 1391441990013225074 /config theme set by kiki 1h ago
```

Exécuter `glyria replay` sans id fait la même chose.

## `replay <id>`

Rejoue l'interaction enregistrée contre votre **code actuel** :

1. Affiche l'exécution originale — commande, utilisateur, serveur, timestamp, options, erreur, et le texte de chaque réponse
2. Charge vos commandes fraîchement depuis le disque et trouve le handler correspondant à la clé enregistrée
3. Construit un faux contexte à partir de l'enregistrement (même utilisateur, serveur, options, sous-commande) et exécute le handler — sans Discord
4. Affiche la nouvelle sortie, plus la stack trace complète si le handler lève une exception (`reproduced!`)
5. Affiche un verdict : **PASS** si le texte des réponses et l'état d'erreur correspondent à l'exécution originale, **DIFF** sinon

::tip{title="Reproduisez le bug d'un utilisateur — sans l'utilisateur"}
Un utilisateur signale que `/config theme set` a échoué il y a une heure. Au lieu de lui demander ce qu'il a tapé :

```bash
glyria replay --list        # trouvez son exécution (marquée ✖)
glyria replay <id>          # reproduisez le crash exact en local
# corrigez votre code...
glyria replay <id>          # PASS — correction vérifiée, même entrée
```

Son payload, ses options et son contexte exacts sont rejoués contre votre correctif.
::

## Cas d'erreur

- Id inconnu → `No recording found for id <id>`
- La commande enregistrée n'existe plus dans votre code → `Command "<key>" no longer exists`
