## Utilisation

```bash
npm run build && npx glyria reload
```

`glyria reload` hot-swap le nouveau code dans votre bot de production **en cours d'exécution** — sans redémarrer le processus et sans couper la connexion à la gateway. Votre bot n'apparaît jamais hors ligne et aucune interaction n'est manquée.

## Ce que ça fait

Quand votre bot se connecte, il écrit son id de processus dans `.glyria/bot.pid`. `glyria reload` lit ce fichier et envoie au processus un signal `SIGUSR2`. Le bot swap alors tout en mémoire :

| Swappé en mémoire | Détails |
|---|---|
| Config | `glyria.config.ts` est rechargé |
| Commandes | Handlers ré-importés depuis `dist/` |
| Événements | Listeners retirés puis ré-enregistrés |
| Composants | Handlers de composants ré-importés |
| Modules | Manifestes ré-importés, `setup()` ré-exécuté, hooks ré-enregistrés |

La connexion à la gateway n'est jamais touchée — le swap est purement in-process.

## Ré-enregistrement côté Discord

Les commandes ne sont ré-enregistrées côté Discord **que si elles ont réellement changé**. glyria.js diffe les nouveaux corps de commandes avec les précédents et :

- Aucune différence → l'appel à l'API Discord est entièrement sauté (`No command changes, skipping Discord re-register`)
- Commandes ajoutées / modifiées / supprimées → ré-enregistrement, avec un résumé du type `+ban ~ping -old`

Recharger après un pur changement de logique (aucune modification d'option ou de description) ne coûte donc aucun appel à l'API Discord.

## Workflow de déploiement

```bash
# sur votre serveur
git pull
npx glyria build
npx glyria reload   # le nouveau code est en ligne — le bot n'a jamais été hors ligne
```

::warning{title="Non supporté sur Windows"}
`glyria reload` repose sur le signal POSIX `SIGUSR2`, qui n'existe pas sous Windows. La commande se termine avec une erreur sur `win32`.
::

## Cas d'erreur

| Erreur | Signification |
|---|---|
| `No .glyria/bot.pid found — is the bot running?` | Le bot n'a pas démarré (ou a été démarré depuis un autre répertoire de travail) |
| `Invalid pid in .glyria/bot.pid` | Le fichier pid est corrompu — redémarrez le bot pour le réécrire |
| `Could not signal pid <pid> — is the bot still running?` | Le fichier pid est obsolète : le processus qu'il désigne n'existe plus |
