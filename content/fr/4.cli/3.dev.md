## Utilisation

```bash id="v7q1kz"
npm run dev
# ou
npx glyria dev
```

## Fonctionnement

`glyria dev` démarre votre bot avec hot reload — aucun redémarrage manuel n’est nécessaire pendant le développement.

## Comportement du hot reload

glyria.js surveille vos fichiers et réagit différemment selon ce qui change :

| Fichier modifié           | Comportement                                          |
| ------------------------- | ----------------------------------------------------- |
| `src/commands/**`         | Recharge uniquement les commandes — pas de restart    |
| `src/events/**`           | Recharge uniquement les events — pas de restart       |
| `glyria.config.ts`        | Recharge config + régénère les types — pas de restart |
| Fichiers `autoImportDirs` | Régénère les types instantanément — pas de restart    |
| `src/index.ts`            | Régénère les types instantanément — pas de restart    |
| `restartPaths`            | Redémarrage complet du bot                            |
| Autres fichiers `src/**`  | Ignorés                                               |

Cela permet de modifier une commande ou un event de manière quasi instantanée — le bot ne se déconnecte pas de Discord.

## Génération des types

Dès qu’un fichier dans vos dossiers d’auto-import change, glyria.js régénère automatiquement `.glyria/imports.d.ts` pour que votre IDE reste synchronisé sans exécuter `glyria generate` manuellement.

Cela s’applique également lorsque `glyria.config.ts` change, notamment si vous avez modifié `autoImportDirs`.

## Environnement

`glyria dev` définit automatiquement les variables d’environnement suivantes :

```bash id="z8k2p0"
NODE_ENV=development
GLYRIA_DEV=true
```

`GLYRIA_DEV=true` force le chargeur de commandes à utiliser directement les fichiers `src/` et `.ts` au lieu de `dist/` — aucun build n’est nécessaire en développement.

## Anti double-trigger

glyria.js utilise [chokidar](https://github.com/paulmillr/chokidar) avec un délai de stabilité de 200ms par fichier — le watcher attend que le fichier cesse d’être modifié avant de réagir. Cela évite les déclenchements multiples causés par les éditeurs, ESLint ou Prettier lors d’une sauvegarde.

## TypeScript

Vos fichiers TypeScript sont exécutés directement via `tsx` — aucune compilation n’est nécessaire en développement. Il suffit de sauvegarder et glyria.js s’occupe du reste.
