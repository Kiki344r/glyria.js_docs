## Utilisation

```bash
npm run generate
# ou
npx glyria generate
```

## Fonctionnement

`glyria generate` analyse votre projet et régénère le fichier `.glyria/imports.d.ts` — le fichier de déclaration TypeScript qui permet aux auto-imports de fonctionner dans votre IDE.

Il s’exécute automatiquement lors de `glyria init`, et pendant `glyria dev` dès que `glyria.config.ts` ou un fichier de vos dossiers d’auto-import change. Il ne s’exécute **pas** au démarrage de `glyria dev` — exécutez-le manuellement une fois si vos déclarations sont obsolètes.

## Ce qui est analysé

### Variables globales du framework

Tous les utilitaires de glyria.js sont déclarés globalement automatiquement :

```ts
GlyriaClient, GlyriaCommand, GlyriaUserCommand, GlyriaMessageCommand,
GlyriaEvent, GlyriaButton, GlyriaSelect, GlyriaModal, EmbedV2Builder,
GlyriaBus, globalBus, createReplyableContext, useCommands,
defineGlyriaConfig, defineModule, defineCommand, defineEvent, defineHook,
createTestContext, useStore, canvas, logger, hexToNumber, Events,
GatewayIntentBits
```

### Variables globales discord.js

L’intégralité de la bibliothèque discord.js est disponible globalement sous l’espace de noms `djs` :

```ts
djs.PermissionsBitField.Flags.BanMembers
djs.GatewayIntentBits.Guilds
djs.ButtonStyle.Primary
// ... tous les exports de discord.js
```

### Variables globales utilisateur

`glyria generate` analyse les dossiers et fichiers suivants à la recherche de fonctions, classes et constantes exportées :

| Source               | Description           |
| -------------------- | --------------------- |
| `src/utils/*.ts`       | Fonctions utilitaires |
| `src/composables/*.ts` | Composables           |
| `src/index.ts`       | Exports racine        |

::note{title="Fichiers de premier niveau uniquement"}
L'analyse n'est pas récursive — seuls les fichiers `.ts` situés directement dans chaque dossier sont pris en compte. Un fichier comme `src/utils/db/pool.ts` ne sera pas auto-importé.
::

Par défaut, `src/utils/` et `src/composables/` sont analysés. Vous pouvez personnaliser cela dans `glyria.config.ts` :

```ts
export default defineGlyriaConfig({
  dev: {
    autoImportDirs: ['utils', 'composables', 'helpers', 'lib']
  }
})
```

Toute déclaration `export const`, `export function` ou `export class` trouvée dans ces fichiers est automatiquement ajoutée au scope global.

```ts
// src/utils/useDatabase.ts
export const useDatabase = () => { ... }
export const formatDate = (date: Date) => { ... }
```

Après exécution de `glyria generate` :

```ts
// src/commands/ping.ts — aucun import nécessaire
const db = useDatabase()
const date = formatDate(new Date())
```

## Résultat généré

Le fichier `.glyria/imports.d.ts` généré ressemble à ceci :

```ts
// auto-généré par glyria — ne pas modifier

export {}

declare global {
  const djs: typeof import("discord.js")
  const GlyriaClient: typeof import("@glyria/bot")["GlyriaClient"]
  const GlyriaCommand: typeof import("@glyria/bot")["GlyriaCommand"]
  const useDatabase: typeof import("../src/utils/useDatabase.ts")["useDatabase"]
  // ...
}
```

::warning{title="Ne modifiez pas .glyria/"}
Ce fichier est écrasé à chaque exécution de `glyria generate`. Toute modification manuelle sera perdue.
::

## Quand l’exécuter manuellement

Exécutez `glyria generate` lorsque :

- Vous ajoutez un nouveau fichier dans `src/utils/` ou `src/composables/` en production
- Votre IDE ne reconnaît pas une variable globale qui devrait exister
- Après une mise à jour de glyria.js ajoutant de nouvelles fonctionnalités globales

En mode développement, `glyria dev` gère cela automatiquement — les types sont régénérés à chaque modification dans les dossiers d’auto-import.
