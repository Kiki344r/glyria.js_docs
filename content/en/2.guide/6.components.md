## Overview

Components in glyria.js are file-based, like commands and events. Every file in `src/components/` is automatically loaded at startup — export one component as `default`, or several as named exports.

A component declares a **customId pattern** and a handler. Placeholders in `{braces}` become typed params:

```ts
// src/components/vote.ts
export default new GlyriaButton("vote:{pollId}:{choice}")
  .execute(async (ctx, params) => {
    // params is inferred from the pattern: { pollId: string; choice: string }
    await registerVote(params.pollId, params.choice, ctx.user.id)
    await ctx.g.update.success(`Vote counted for **${params.choice}**!`)
  })
```

`ctx` is the wrapped `ButtonInteraction` — `ctx.g.update.*` edits the message the button lives on, `ctx.g.reply.*` sends a new one.

::tip{title="Auto-import"}
`GlyriaButton`, `GlyriaSelect` and `GlyriaModal` are available globally — no import needed.
::

## Typed params

Param types are inferred at the type level from the pattern string (`PatternParams`). Rename a placeholder and every `params.xxx` access updates — or breaks at compile time:

```ts
new GlyriaButton("role_picker:{roleId}:{userId}")
  .execute(async (ctx, params) => {
    params.roleId // string ✅
    params.userId // string ✅
    params.other  // ❌ type error
  })
```

::warning{title="No colons in params"}
`:` is the pattern separator — a param value containing `:` throws when building the id. Keep params to plain ids (snowflakes, slugs, numbers).
::

## Rendering a component

Call `.id({...})` on the component to build a concrete customId when rendering. Import the component from its file — the pattern stays in one place:

```ts
// src/components/vote.ts
export const voteButton = new GlyriaButton("vote:{pollId}:{choice}")
  .execute(async (ctx, params) => {
    await ctx.g.update.success(`Vote counted for **${params.choice}**!`)
  })
```

```ts
// src/commands/poll.ts
import { voteButton } from "../components/vote.js"

export default new GlyriaCommand()
  .setName("poll")
  .setDescription("Start a poll")
  .execute(async (ctx) => {
    const embed = new EmbedV2Builder()
      .container({ accentColor: 0x5865f2 })
      .textDisplay("**Tabs or spaces?**")
      .actionRow()
      .button({ label: "Tabs", customId: voteButton.id({ pollId: "42", choice: "tabs" }), style: "primary" })
      .button({ label: "Spaces", customId: voteButton.id({ pollId: "42", choice: "spaces" }), style: "secondary" })
      .end()
      .end()
      .build()

    await ctx.g.reply.raw(embed)
  })
```

`.id()` is fully typed too — missing or extra params are compile errors, and a missing param at runtime throws with the pattern name.

## Selects and modals

Same API, different interaction type:

```ts
// src/components/color-select.ts
export const colorSelect = new GlyriaSelect("color_select:{userId}")
  .execute(async (ctx, params) => {
    await ctx.g.update.success(`Color saved: ${ctx.values[0]}`)
  })

// src/components/feedback-modal.ts
export const feedbackModal = new GlyriaModal("feedback:{topic}")
  .execute(async (ctx, params) => {
    const text = ctx.fields.getTextInputValue("body")
    await ctx.g.reply.success(`Feedback on **${params.topic}** received!`).ephemeral()
  })
```

| Builder | Handles | `ctx` type |
|---|---|---|
| `GlyriaButton` | Button clicks | `ButtonInteraction` |
| `GlyriaSelect` | Any select menu | `AnySelectMenuInteraction` |
| `GlyriaModal` | Modal submits | `ModalSubmitInteraction` |

## Matching rules

- Each interaction is matched against loaded patterns of the same kind; the **first** matching component handles it.
- Patterns are anchored: `"vote:{pollId}:{choice}"` matches exactly three `:`-separated segments starting with `vote`.
- Slow handlers get the same automatic defer as commands.

::warning{title="Reserved prefix"}
customIds starting with `glyria:` are reserved for the framework (`ctx.g.confirm` and `ctx.g.paginate` buttons). Never use that prefix in your own patterns.
::

## Organizing files

Subfolders in `src/components/` are for organization only. Components inside [modules](/guide/modules) live in the module's own `components/` folder.

```text
src/components/
  vote.ts
  roles/
    picker.ts
  modals/
    feedback.ts
```

In dev (`glyria dev`), component files are hot reloaded on save — no restart needed.
