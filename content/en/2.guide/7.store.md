## Overview

glyria.js ships a built-in key-value store, available on every context as `ctx.g.store`. It comes pre-scoped so you never build key prefixes by hand:

```ts
export default new GlyriaCommand()
  .setName("count")
  .setDescription("Count your invocations")
  .execute(async (ctx) => {
    const count = ((await ctx.g.store.user.get<number>("count")) ?? 0) + 1
    await ctx.g.store.user.set("count", count)
    await ctx.g.store.guild.set("lastUser", ctx.user.id)

    await ctx.g.reply.success(`You've run this ${count} time(s).`)
  })
```

## Scopes

| Scope | Keyed by | Notes |
|---|---|---|
| `ctx.g.store.guild` | Current guild | Throws when used in DMs |
| `ctx.g.store.user` | Invoking user | |
| `ctx.g.store.global` | Bot-wide | |
| `ctx.g.guildConfig` | Current guild | Separate namespace for per-guild settings — throws in DMs |

Every scope exposes the same async API:

| Method | Returns |
|---|---|
| `get<T>(key)` | `Promise<T \| undefined>` |
| `set(key, value)` | `Promise<void>` |
| `delete(key)` | `Promise<boolean>` |
| `keys()` | `Promise<string[]>` (keys within the scope) |

`ctx.g.guildConfig` is deliberately kept apart from `ctx.g.store.guild` — settings on one side, data on the other:

```ts
await ctx.g.guildConfig.set("welcomeChannel", channel.id)
await ctx.g.store.guild.set("memberCount", 1024)
```

## Outside a context

`useStore()` (auto-imported) gives you the same store anywhere — jobs, event handlers, module setup:

```ts
const store = useStore()

await store.forGuild(guildId).set("raidMode", true)
await store.forUser(userId).get<number>("xp")
await store.global.set("bootedAt", Date.now())
await store.forModule("economy").set("taxRate", 0.05)
await store.forGuildConfig(guildId).get<string>("welcomeChannel")
```

::tip{title="Modules get a scoped store for free"}
Inside a [module](/guide/modules), `ctx.store` is already scoped to `module:<name>:` — no `forModule()` call needed.
::

## Persistence

The default adapter is **in-memory** — data is lost on restart. Switch to the JSON file adapter in `glyria.config.ts` for zero-config persistence:

```ts
// glyria.config.ts
export default defineGlyriaConfig({
  store: {
    adapter: "json",
    path: ".glyria/store.json", // default
  },
})
```

The JSON adapter keeps everything in memory and debounces writes to the file — good for small bots.

| Adapter | Persistence | Use case |
|---|---|---|
| `"memory"` (default) | none | Dev, caches, tests |
| `"json"` | debounced writes to `.glyria/store.json` | Small bots |
| custom `StoreAdapter` | up to you | Redis, SQLite, Postgres, ... |

## Custom adapters

Pass any object implementing `StoreAdapter` as the `adapter`. Keys arrive already prefixed (`guild:<id>:...`, `user:<id>:...`), so a flat backend works:

```ts
// glyria.config.ts
import { createClient } from "redis"
import type { StoreAdapter } from "@glyria/bot"

const redis = createClient()
await redis.connect()

const redisAdapter: StoreAdapter = {
  async get(key) {
    const raw = await redis.get(key)
    return raw === null ? undefined : JSON.parse(raw)
  },
  async set(key, value) {
    await redis.set(key, JSON.stringify(value))
  },
  async delete(key) {
    return (await redis.del(key)) > 0
  },
  async keys(prefix) {
    return redis.keys(`${prefix}*`)
  },
}

export default defineGlyriaConfig({
  store: { adapter: redisAdapter },
})
```

::warning{title="JSON adapter limits"}
The JSON file adapter loads the whole store in memory and rewrites the entire file on change. Plug a real adapter (Redis, SQLite) for anything beyond small bots.
::
