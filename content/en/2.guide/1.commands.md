## Overview

Commands in glyria.js are file-based. Every file in `src/commands/` is automatically loaded and registered on Discord at startup — no manual registration needed.

Each command file exports a command instance as default:

```ts
// src/commands/ping.ts
export default new GlyriaCommand()
  .setName("ping")
  .setDescription("Pong!")
  .execute(async (ctx) => {
    await ctx.g.reply.success("Pong!")
  })
```

::tip{title="Auto-import"}
`GlyriaCommand`, `GlyriaUserCommand` and `GlyriaMessageCommand` are available globally — no import needed.
::

## Automatic context

Handlers receive the interaction already wrapped. `ctx` **is** the `ChatInputCommandInteraction` — every discord.js method works as usual — plus a `ctx.g` property with styled replies, confirmations, pagination, the built-in store and more:

```ts
export default new GlyriaCommand()
  .setName("ping")
  .setDescription("Pong!")
  .execute(async (ctx) => {
    // plain discord.js still works:
    // await ctx.reply({ content: "Pong!" })

    // glyria one-liner:
    await ctx.g.reply.success("Pong!")
  })
```

No manual `createReplyableContext` call needed — the framework wraps the interaction before invoking your handler. See the [Replyable Context guide](/guide/replyable-context) for everything `ctx.g` can do.

## Slash commands

### Options

Add typed options to your command with the `add*Option` methods:

```ts
export default new GlyriaCommand()
  .setName("hello")
  .setDescription("Say hello to someone")
  .addUserOption((option) =>
    option
      .setName("user")
      .setDescription("The user to greet")
      .setRequired(true)
  )
  .addStringOption((option) =>
    option
      .setName("message")
      .setDescription("A custom message")
      .setRequired(false)
  )
  .execute(async (ctx) => {
    await ctx.reply({ content: "Hello!" })
  })
```

#### Available option types

| Method             | Type           |
| ------------------ | -------------- |
| `addStringOption`  | Text input     |
| `addIntegerOption` | Integer number |
| `addNumberOption`  | Decimal number |
| `addBooleanOption` | True / False   |
| `addUserOption`    | Discord user   |
| `addRoleOption`    | Discord role   |

Each option exposes:

| Method                  | Description                        |
| ----------------------- | ---------------------------------- |
| `.setName(name)`        | Option name (lowercase, no spaces) |
| `.setDescription(desc)` | Option description                 |
| `.setRequired(bool)`    | Whether the option is required     |

### Subcommands

Group related actions under a single command with `.addSubCommand()`:

```ts
export default new GlyriaCommand()
  .setName("moderation")
  .setDescription("Moderation commands")
  .addSubCommand((cmd) =>
    cmd
      .setName("ban")
      .setDescription("Ban a user")
      .addUserOption((option) =>
        option
          .setName("user")
          .setDescription("User to ban")
          .setRequired(true)
      )
      .addStringOption((option) =>
        option
          .setName("reason")
          .setDescription("Reason of the ban")
          .setRequired(false)
      )
      .execute(async (ctx) => {
        // handle ban
      })
  )
  .execute(async (ctx) => {
    // handle base command
  })
```

### Subcommand groups

For deeper organization, group subcommands with `.addSubCommandGroup()`:

```ts
export default new GlyriaCommand()
  .setName("moderation")
  .setDescription("Moderation commands")
  .addSubCommand((cmd) =>
    cmd
      .setName("ban")
      .setDescription("Ban a user")
      .addUserOption((option) =>
        option
          .setName("user")
          .setDescription("User to ban")
          .setRequired(true)
      )
      .addStringOption((option) =>
        option
          .setName("reason")
          .setDescription("Reason of the ban")
          .setRequired(false)
      )
      .execute((ctx) => {
        console.log("ban command")
      })
  )
  .addSubCommandGroup((group) =>
    group
      .setName("config")
      .setDescription("Configuration commands")
      .addSubCommand((cmd) =>
        cmd
          .setName("logs")
          .setDescription("Configure logs")
          .addBooleanOption((option) =>
            option
              .setName("enabled")
              .setDescription("Enable logs")
              .setRequired(true)
          )
          .execute(async (ctx) => {
            // handle logs config
          })
      )
  )
  .execute((ctx) => {
    ctx.reply({ content: "Moderation command executed!" })
  })
```

This generates the following Discord command structure:

```text
/moderation ban <user> [reason]
/moderation config logs <enabled>
```

## Context menus

Context menus appear when a user right-clicks on a user or a message, under the **Apps** section. They have no description, no options, and no subcommands.

### User context menu

Triggered by right-clicking on a user. The handler receives a `UserContextMenuCommandInteraction` — the targeted user is available via `ctx.targetUser`.

```ts
// src/commands/profile.ts
export default new GlyriaUserCommand()
  .setName("View profile")
  .execute(async (ctx) => {
    const user = ctx.targetUser
    await ctx.g.reply.info(`Profile of ${user.username}`).ephemeral()
  })
```

### Message context menu

Triggered by right-clicking on a message. The handler receives a `MessageContextMenuCommandInteraction` — the targeted message is available via `ctx.targetMessage`.

```ts
// src/commands/translate.ts
export default new GlyriaMessageCommand()
  .setName("Translate")
  .execute(async (ctx) => {
    const message = ctx.targetMessage
    await ctx.g.reply.info(`Translating: "${message.content}"`).ephemeral()
  })
```

## Declarative cooldowns

Rate-limit any command with `.setCooldown()`. A plain duration string applies a **per-user** cooldown:

```ts
export default new GlyriaCommand()
  .setName("daily")
  .setDescription("Claim your daily reward")
  .setCooldown("5s")
  .execute(async (ctx) => {
    await ctx.g.reply.success("Reward claimed!")
  })
```

Pass an object to combine scopes:

```ts
.setCooldown({ user: "5s", guild: "2s", global: "1s" })
```

| Scope | Applies to |
|---|---|
| `user` | The invoking user |
| `guild` | Everyone in the current server |
| `global` | Everyone, everywhere |

Durations accept `ms`, `s`, `m`, `h`, `d` suffixes (`"500ms"`, `"5s"`, `"2m"`, `"1h"`, `"1d"`) or a raw number of milliseconds.

`.setCooldown()` is available on `GlyriaCommand`, `GlyriaSubCommand`, `GlyriaUserCommand` and `GlyriaMessageCommand`. A cooldown set on a subcommand overrides the parent command's cooldown for that subcommand.

When a user is on cooldown, glyria denies the run with a styled ephemeral error showing the remaining time:

> ❌ You're on cooldown — try again in **3s**.

::tip{title="Guards run in order"}
The cooldown is only consumed once every other guard has passed — a run denied by `setOwnerOnly()` or `setPermissions()` never starts a cooldown.
::

## Declarative permissions

Pass permission names to `.setPermissions()` and glyria does two things:

1. Sets Discord's `default_member_permissions`, so the command is hidden from members who lack them.
2. Runtime-checks the invoker's permissions and denies with a styled ephemeral error listing what's missing.

```ts
export default new GlyriaCommand()
  .setName("ban")
  .setDescription("Ban a user")
  .setPermissions(["BanMembers"])
  .execute(async (ctx) => {
    // only members with Ban Members can run this
  })
```

> ❌ You need the following permission(s) to use this command: **Ban Members**

Permission names are the keys of discord.js's `PermissionFlagsBits` (`"BanMembers"`, `"ManageGuild"`, `"Administrator"`, ...), fully typed.

::note{title="Legacy form"}
The raw bitfield form still works — `setPermissions(8n)` sets `default_member_permissions` only, without the runtime check.
::

### Owner-only commands

`.setOwnerOnly()` restricts a command to the application owner. The owner is resolved from the Discord application — bots owned by a **Team** accept every team member.

```ts
export default new GlyriaCommand()
  .setName("eval")
  .setDescription("Owner only")
  .setOwnerOnly()
  .execute(async (ctx) => {
    // only the bot owner (or team members) gets here
  })
```

## Typed autocomplete

Attach an autocomplete handler directly on the option with `.setAutocomplete()` — no separate handler file:

```ts
export default new GlyriaCommand()
  .setName("play")
  .setDescription("Play a song")
  .addStringOption((o) =>
    o
      .setName("query")
      .setDescription("Song to search")
      .setAutocomplete(async (query, interaction) => {
        const results = await searchSongs(query)
        return results.map((song) => ({ name: song.title, value: song.id }))
      })
  )
  .execute(async (ctx) => {
    const id = ctx.options.getString("query", true)
    // ...
  })
```

The handler receives the current `query` string and the raw `AutocompleteInteraction`, and returns choices in any of three shapes:

| Return | Sent to Discord as |
|---|---|
| `"rock"` | `{ name: "rock", value: "rock" }` |
| `42` | `{ name: "42", value: 42 }` |
| `{ name: "Rock", value: "genre_rock" }` | as-is |

At most **25** choices are sent (extra ones are dropped). `.setAutocomplete()` is available on string, integer and number options — including inside subcommands and subcommand groups.

## Metadata

Attach custom data to a command with `.setMetaData()`. Works on `GlyriaCommand`, `GlyriaUserCommand` and `GlyriaMessageCommand`. Glyria stores it as-is and never interprets it — it's entirely up to you.

```ts
export default new GlyriaCommand()
  .setName("ban")
  .setDescription("Ban a user")
  .setMetaData({
    category: "moderation",
    cooldown: 5000,
    premium: false,
    guildOnly: true,
  })
  .execute(async (ctx) => {
    // your logic here
  })
```

### useCommands()

`useCommands()` returns the full list of loaded commands with their metadata. It's available globally and always reflects the current state of the bot.

```ts
const commands = useCommands()
// [
//   { name: "ban", description: "Ban a user", meta: { category: "moderation", cooldown: 5000 } },
//   { name: "ping", description: "Pong!", meta: {} },
//   { name: "View profile", description: "", meta: {} },
// ]
```

A common use case is building a `/help` command organized by category:

```ts
export default new GlyriaCommand()
  .setName("help")
  .setDescription("List all commands")
  .execute(async (ctx) => {
    const commands = useCommands()

    const byCategory = commands.reduce((acc, cmd) => {
      const cat = (cmd.meta.category as string) ?? "general"
      acc[cat] ??= []
      acc[cat].push(cmd)
      return acc
    }, {} as Record<string, typeof commands>)

    // build your embed from byCategory
  })
```

## Organizing files

Subfolders inside `src/commands/` are for organization only — every file at any depth is loaded automatically.

```text
src/commands/
  ping.ts
  moderation/
    ban.ts
    kick.ts
  config/
    advanced/
      logs.ts
  context-menus/
    profile.ts
    translate.ts
```

::tip{title="One command per file"}
Keep one command instance per file. Use subcommands and subcommand groups to group related actions inside a `GlyriaCommand`.
::
