## Overview

glyria.js wraps every replyable Discord object (interactions, messages) with a `g` property before your handler runs. `ctx` stays the raw discord.js object — `ctx.g` adds a batteries-included reply toolkit on top:

```ts
export default new GlyriaCommand()
  .setName("ban")
  .setDescription("Ban a user")
  .execute(async (ctx) => {
    await ctx.g.reply.success("User banned successfully!")
  })
```

The wrapping is automatic in command handlers, event handlers and component handlers — no setup needed.

## Styled one-liners

Each variant builds an Embed V2 with the matching accent color:

| Method | Color | Prefix |
|---|---|---|
| `ctx.g.reply.primary(content)` | `#5865F2` (blurple) | none |
| `ctx.g.reply.secondary(content)` | `#4F545C` (grey) | none |
| `ctx.g.reply.success(content)` | `#57F287` (green) | ✅ |
| `ctx.g.reply.warning(content)` | `#FEE75C` (yellow) | ⚠️ |
| `ctx.g.reply.error(content)` | `#ED4245` (red) | ❌ |
| `ctx.g.reply.info(content)` | `#5DADE2` (blue) | ℹ️ |

Override the theme colors in `glyria.config.ts`:

```ts
// glyria.config.ts
export default defineGlyriaConfig({
  theme: {
    embedV2: {
      primaryColor: "#7289DA",
      secondaryColor: "#747F8D",
      successColor: "#43B581",
      warningColor: "#FAA61A",
      errorColor: "#F04747",
      infoColor: "#00B0F4",
    },
  },
})
```

::tip{title="defineGlyriaConfig"}
The config helper is `defineGlyriaConfig` — auto-imported, fully typed. Colors are hex strings; glyria converts them internally.
::

## Fluent chaining

Every styled sender returns a chain you can extend before sending:

```ts
await ctx.g.reply
  .success("Backup complete")
  .description("All 3 databases were exported.")
  .field("Duration", "42s")
  .field("Size", "18 MB")
  .file(backupBuffer, "backup.zip")
  .ephemeral()
  .send()
```

| Method | Effect |
|---|---|
| `.description(text)` | Adds a text block below the title |
| `.field(name, value)` | Adds a `**name**` + value block |
| `.file(data, name)` | Attaches a `Buffer` or file path |
| `.ephemeral(bool?)` | Marks this reply ephemeral (default `true`) |
| `.send()` | Sends and returns the message |

The chain is **thenable** — a bare `await` sends it, so `.send()` is optional:

```ts
await ctx.g.reply.success("Done").field("Took", "3s")
```

## Smart routing

`ctx.g` always picks the right transport for the interaction's current state — you never have to think about `reply` vs `editReply` vs `followUp`:

| State | Sent via |
|---|---|
| Nothing sent yet | `reply()` |
| Deferred, nothing sent yet | `editReply()` |
| Something already sent | `followUp()` |

```ts
.execute(async (ctx) => {
  await ctx.g.reply.info("Working on it...")   // → reply()
  await ctx.g.reply.success("First step done") // → followUp(), automatically
  await ctx.g.reply.success("All done")        // → followUp()
})
```

## Confirmations

`ctx.g.confirm()` sends a message with Confirm/Cancel buttons and resolves to a boolean:

```ts
.execute(async (ctx) => {
  const confirmed = await ctx.g.confirm("Delete all 250 messages?", {
    timeout: "30s",
    confirmLabel: "Delete",
    cancelLabel: "Keep them",
    ephemeral: true,
  })

  if (!confirmed) return ctx.g.followUp.secondary("Cancelled.")
  // ... destructive action
})
```

| Option | Default | Description |
|---|---|---|
| `timeout` | `"30s"` | Idle timeout — resolves to `false` when it expires |
| `confirmLabel` | `"Confirm"` | Green button label |
| `cancelLabel` | `"Cancel"` | Red button label |
| `ephemeral` | `false` | Send the prompt ephemerally |

Only the **invoking user** can click the buttons — other users' clicks are ignored. Once resolved (click or timeout), the buttons are disabled.

## Pagination

`ctx.g.paginate()` turns an array of strings into a ◀ `1/N` ▶ browser:

```ts
.execute(async (ctx) => {
  const pages = chunks.map((c, i) => `**Page ${i + 1}**\n${c}`)
  await ctx.g.paginate(pages, { timeout: "2m" })
})
```

| Option | Default | Description |
|---|---|---|
| `timeout` | `"2m"` | Idle timeout — buttons are disabled when it expires |
| `ephemeral` | `false` | Send the pages ephemerally |

Only the invoker can navigate. A single-page array is sent without buttons.

## Deferring

Discord gives you 3 seconds to answer an interaction. glyria arms an **automatic defer** at ~1.5s: if your handler hasn't responded by then, it calls `deferReply()` for you and your later `ctx.g.reply.*` becomes an edit — slow handlers just work.

Defer manually when you know it'll be slow:

```ts
.execute(async (ctx) => {
  await ctx.g.defer() // or ctx.g.defer({ ephemeral: true })
  const stats = await crunchNumbers() // takes 10s
  await ctx.g.reply.success(`Crunched ${stats.total} rows`)
})
```

`ctx.g.defer()` is a no-op if the interaction is already deferred or replied to.

## Loading states

`ctx.g.reply.loading()` shows a ⏳ message, awaits your promise, then edits the message into a success or error. It resolves with the promise result (and rethrows on failure):

```ts
.execute(async (ctx) => {
  const results = await ctx.g.reply.loading("Searching...", searchApi(query), {
    done: (r) => `Found ${(r as Result[]).length} results`,
    fail: "The search service is down.",
  })
  // `results` is the resolved value of searchApi(query)
})
```

`done` and `fail` accept a string or a function of the result/error. Defaults: `"Done"` / `"Something went wrong"`.

## Editing

`ctx.g.edit()` edits the **last message sent through this context**, keeping its variant styling unless you override it:

```ts
await ctx.g.reply.info("Processing 0/100...")
await ctx.g.edit("Processing 50/100...")            // stays info-styled
await ctx.g.edit("All 100 processed", { variant: "success" })
```

It throws if nothing has been sent through the context yet.

## Follow-ups and raw payloads

`ctx.g.followUp.*` exposes the same six styled variants, always sent as a follow-up:

```ts
await ctx.g.followUp.warning("Heads up: this expires in 24h")
```

When you need full control, `raw()` bypasses the Embed V2 styling and sends any discord.js payload (smart routing still applies):

```ts
await ctx.g.reply.raw({ content: "plain text", files: [attachment] })
await ctx.g.followUp.raw({ embeds: [legacyEmbed] })
```

## Ephemeral defaults

Set a context-wide default once, or opt in per call:

```ts
ctx.g.ephemeral(true)                       // every send from now on is ephemeral
await ctx.g.reply.success("Only you see this")

await ctx.g.reply.info("Just this one", { ephemeral: true })  // per-call
```

Messages (e.g. in `messageCreate` handlers) can't be ephemeral — the flag is silently skipped for them.

## User, member and guild config

| Property | Value |
|---|---|
| `ctx.g.user` | The invoking user (`interaction.user` / `message.author`) |
| `ctx.g.member` | The invoking guild member, when available |
| `ctx.g.guildConfig` | Per-guild configuration namespace on the [store](/guide/store) — throws in DMs |

```ts
await ctx.g.guildConfig.set("welcomeChannel", channel.id)
const welcome = await ctx.g.guildConfig.get<string>("welcomeChannel")
```

`ctx.g.store` (guild/user/global scopes) and `ctx.g.canvas` (rank cards, leaderboards) are covered in the [Store](/guide/store) and [Canvas](/guide/canvas) guides.

## History and send hooks

Everything sent through the context is recorded:

```ts
ctx.g.onSend((entry) => {
  console.log(`sent ${entry.variant} via ${entry.via}`)
})

const entries = ctx.g.history()
// [{ variant: "success", via: "reply", payload, message, timestamp }, ...]
```

Each `SentEntry` has `variant` (`"primary"` ... `"info"` or `"raw"`), `via` (`"reply"`, `"followUp"`, `"edit"`, `"update"`), the raw `payload`, the resulting `message` and a `timestamp`.

## Logging

`ctx.g.log()` writes to the console and — when `logChannel` is set in `glyria.config.ts` — posts a styled message to that Discord channel:

```ts
await ctx.g.log(`${ctx.user.username} purged #general`, "warn")
```

```ts
// glyria.config.ts
export default defineGlyriaConfig({
  logChannel: "123456789012345678",
})
```

Levels: `"info"` (default), `"warn"`, `"error"` — mapped to the info/warning/error styles on Discord.

## Component updates

For button, select and modal interactions, `ctx.g.update.*` re-styles the originating message in place instead of sending a new one:

```ts
export default new GlyriaButton("vote:{pollId}:{choice}")
  .execute(async (ctx, params) => {
    await ctx.g.update.success(`Vote counted for **${params.choice}**!`)
  })
```

See the [Components guide](/guide/components) for typed customIds.

::note{title="Conditional typing"}
`ctx.g` adapts to its source: `ctx.g.defer()` only exists in the types when the source supports `deferReply()` (interactions, not messages), and `ctx.g.update.*` only when the source supports `update()` (component interactions). Your editor won't offer what can't work.
::

## Manual wrapping

For edge cases — a message fetched from an API, a test fake — `createReplyableContext` (auto-imported) wraps any replyable object by hand:

```ts
const target = await channel.messages.fetch(id)
const ctx = createReplyableContext(target)
await ctx.g.reply.info("Wrapped manually")
```

It's idempotent: wrapping an already-wrapped object returns it unchanged.
