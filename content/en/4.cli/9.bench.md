## Usage

```bash
npx glyria bench <command> [-n 1000] [-c 50] [-o name=value]
```

Runs a command handler many times in parallel and reports latency percentiles — a load test for your bot, no Discord required.

Run `glyria bench` with no arguments to list every available command key.

## Flags

| Flag | Default | Description |
|---|---|---|
| `-n`, `--runs` | `200` | Total number of runs |
| `-c`, `--concurrency` | `20` | Parallel workers |
| `-o`, `--option` | — | Set a command option, `name=value` (repeatable) |

## Command keys

Subcommands use a colon-separated key — the same key format shown by `--list` and used by `glyria replay`:

```bash
npx glyria bench ping                                    # /ping
npx glyria bench config:theme:set -o theme=dark          # /config theme set theme:dark
npx glyria bench profile -n 1000 -c 50 -o user=123
```

## Fresh user per run

Each run executes with a brand-new fake user (`bench-user-0`, `bench-user-1`, ...). Per-user cooldown guards therefore never trigger — your cooldown settings don't serialize the bench or skew the numbers.

## The report

```
  Results
  ────────────────────────────────────────
  total       1243.87ms
  throughput  160.8 runs/s
  min         2.11ms
  avg         5.83ms
  p50         4.92ms
  p95         14.37ms
  p99         28.10ms
  max         41.55ms
```

| Metric | Meaning |
|---|---|
| `total` | Wall-clock time for the whole bench |
| `throughput` | Runs per second at the given concurrency |
| `min` / `avg` / `max` | Latency extremes and mean |
| `p50` / `p95` / `p99` | Latency percentiles — `p95` is what your slowest 5% of users feel |

After the table, you get the error count: either `200/200 run(s) completed without errors`, or how many runs threw plus the first error.

::warning{title="It measures YOUR code, not Discord"}
Handlers run **in-process against a fake context**. The numbers reflect your handler code — database queries, computation, awaited work — not Discord's API latency or rate limits. That's the point: it isolates the part you can actually optimize.
::
