## Usage

```bash
npm run start
# or
npx glyria start
```

## What it does

`glyria start` launches your compiled bot in production mode. It runs the compiled entry (`dist/src/index.js`) with the glyria.js runtime injected automatically — and supervises the process for you.

It's not a plain `node dist/src/index.js`: the supervisor restarts your bot when it crashes, detects crash loops, and can roll back to the last known-good build automatically.

::warning{title="Build required"}
`glyria start` requires a compiled build. If `dist/src/index.js` is not found, it exits with an error.

Always run `glyria build` before `glyria start`.
::

## Production workflow

```bash
# 1. compile
npm run build

# 2. start
npm run start
```

## Self-healing supervisor

When your bot exits with a non-zero code (a clean exit or `SIGTERM` never triggers a restart), the supervisor kicks in:

**Exponential backoff.** Each crash restarts the bot after a growing delay — 1s after the first crash, then 2s, then 4s... The counter only looks at crashes within the last 60 seconds, so an occasional crash long after the previous one restarts quickly.

**Crash-loop detection.** 3 crashes within 60 seconds is considered a crash loop — restarting the same build again won't help, so the supervisor rolls back instead.

## Stable snapshots

A run that stays up for 60 seconds is considered stable. When that happens, the supervisor:

1. Resets the crash counter
2. Snapshots `dist/` to `.glyria/last-good`

That snapshot becomes the rollback target — always the last build that actually survived in production.

## How rollback works

When a crash loop is detected:

1. `dist/` is deleted and replaced with the `.glyria/last-good` snapshot
2. The bot restarts on that last stable build
3. If the rolled-back build stays up 60 seconds, it becomes the new stable snapshot

If there is no snapshot yet, or the bot crash-loops **again after already rolling back**, the supervisor gives up cleanly and exits with code 1 — it never loops forever on a broken build.

::tip{title="Ship a bad deploy? You're covered"}
`glyria build && glyria start` with a broken release means: 3 crashes, automatic rollback, and your users are back on the previous version — before you've even read the stack trace.
::

## Shutdown

`Ctrl+C` (`SIGINT`) and `SIGTERM` are forwarded to the bot process, and the supervisor does not restart it — stopping the bot on purpose is always clean.

## Difference with dev mode

| | `glyria dev` | `glyria start` |
|---|---|---|
| Source | `src/` (TypeScript) | `dist/` (JavaScript) |
| Hot reload | ✅ | ❌ (use [`glyria reload`](/cli/reload)) |
| Requires build | ❌ | ✅ |
| Self-healing restarts | ❌ | ✅ |
| Use case | Development | Production |
