## Usage

```bash
npx glyria replay --list   # 20 most recent recordings
npx glyria replay <id>     # re-run one of them
```

## How interactions get recorded

In dev mode, **every command execution is recorded automatically** — nothing to enable. In production, set `recording: true` in `glyria.config.ts`.

Each interaction is written to `.glyria/interactions/<id>.json` with everything needed to replay it later:

| Field | Description |
|---|---|
| `key`, `kind` | Resolved handler key (e.g. `config:theme:set`) and kind (`chat`, `user`, `message`) |
| `userId`, `username`, `guildId`, `channelId` | Who ran it, and where |
| `options`, `subcommand` | Flat option values and the subcommand path |
| `replies` | Every reply payload the handler sent, with method and timestamp |
| `error` | The error, if the handler threw |

## `replay --list`

Shows the 20 most recent recordings — a ✔/✖ status, the id, the command, the user and how long ago it ran:

```
  ✔ 1391442183218352109 /ping by enzo 2m ago
  ✖ 1391441990013225074 /config theme set by kiki 1h ago
```

Running `glyria replay` with no id does the same thing.

## `replay <id>`

Re-runs the recorded interaction against your **current code**:

1. Prints the original run — command, user, guild, timestamp, options, error, and the text of every reply
2. Loads your commands fresh from disk and finds the handler for the recorded key
3. Builds a fake context from the recording (same user, guild, options, subcommand) and executes the handler — no Discord involved
4. Prints the new output, plus the full stack trace if the handler throws (`reproduced!`)
5. Prints a verdict: **PASS** if the reply text and error state match the original run, **DIFF** otherwise

::tip{title="Reproduce a user's bug — without the user"}
A user reports that `/config theme set` errored an hour ago. Instead of asking them what they typed:

```bash
glyria replay --list        # find their run (marked ✖)
glyria replay <id>          # reproduce the exact crash locally
# fix your code...
glyria replay <id>          # PASS — verified fixed, same input
```

Their exact payload, options and context are replayed against your fix.
::

## Error cases

- Unknown id → `No recording found for id <id>`
- The recorded command no longer exists in your code → `Command "<key>" no longer exists`
