## Usage

```bash
npx glyria module create <name>
npx glyria module list
```

Modules are self-contained features — a manifest, plus their own commands, events and components. Read the [modules guide](/guide/modules) for the full picture.

## `module create`

```bash
npx glyria module create economy
```

Scaffolds a ready-to-run module:

```
src/modules/economy/
  index.ts        # module manifest (defineModule)
  commands/
    economy.ts    # example command — auto-loaded
```

The generated `index.ts` is a `defineModule` manifest with everything pre-wired:

| Part | Description |
|---|---|
| `name`, `version`, `description` | Module identity (starts at `0.1.0`) |
| `setup(ctx)` | Runs on load — the returned object is the module's public API, callable from other modules via `ctx.modules.get("economy")` |
| `hooks.onReady` | Runs when the bot is ready |
| `dependsOn`, `config`, `beforeCommand` | Commented examples for dependencies, config schema and global middleware |

The `commands/` folder works exactly like `src/commands/` — anything you drop in there is auto-loaded, hot reloaded in dev, and scoped to the module.

::warning{title="Existing modules are never touched"}
If `src/modules/<name>` already exists, `module create` exits with an error instead of overwriting anything.
::

## `module list`

```bash
npx glyria module list
```

Discovers and prints every module your bot would load:

- **Local modules** from `src/modules/`
- **npm modules** declared in the `modules` array of `glyria.config.ts`

For each module you get its name, version, dependencies (`dependsOn`) and registered hooks:

```
  ✔ economy v0.1.0 hooks: onReady
  ✔ moderation v1.2.0 deps: economy hooks: onReady, beforeCommand
```

Entries whose default export is not a `defineModule` manifest are flagged as `✖ <invalid>` with their source path. Note that a module file with **no default export at all** is skipped during discovery and won't appear in the list — if a module is missing here, check its `export default` first.

## The `--module` flag

Unrelated to `glyria module`: `glyria dev`, `build`, `generate` and `start` all accept a global `--module` flag for **module-SDK mode** — developing a standalone module package whose test bot lives in a `Bot/` subfolder. With the flag, those commands root themselves at `Bot/` (`Bot/src/`, `Bot/dist/`, `Bot/glyria.config.ts`) instead of the project root.

```bash
npx glyria dev --module
```
