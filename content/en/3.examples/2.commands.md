## Basic Command

Create a file inside `src/commands/` — it will be automatically loaded and registered on Discord.

```ts
// src/commands/ping.ts
export default new GlyriaCommand()
  .setName("ping")
  .setDescription("Pong!")
  .execute(async (ctx) => {
    await ctx.g.reply.success("Pong!")
  })
```

::tip{title="Auto-import"}
`GlyriaCommand` is available globally — no import needed. The handler receives the interaction already wrapped with [`ctx.g`](/guide/replyable-context).
::

## Command with Options

```ts
// src/commands/hello.ts
export default new GlyriaCommand()
  .setName("hello")
  .setDescription("Say hello to someone")
  .addUserOption((option) =>
    option
      .setName("user")
      .setDescription("The user to greet")
      .setRequired(true)
  )
  .addStringOption((option) =>
    option
      .setName("message")
      .setDescription("A custom message")
      .setRequired(false)
  )
  .execute(async (ctx) => {
    const message = ctx.options.getString("message") ?? "Hello!"
    await ctx.g.reply.primary(message)
  })
```

## Available Option Types

| Method             | Discord Type |
| ------------------ | ------------ |
| `addStringOption`  | String       |
| `addIntegerOption` | Integer      |
| `addNumberOption`  | Number       |
| `addBooleanOption` | Boolean      |
| `addUserOption`    | User         |
| `addRoleOption`    | Role         |

## Autocomplete

String, integer, and number options support inline autocomplete — no separate handler file:

```ts
// src/commands/tag.ts
export default new GlyriaCommand()
  .setName("tag")
  .setDescription("Show a tag")
  .addStringOption((option) =>
    option
      .setName("name")
      .setDescription("Tag name")
      .setRequired(true)
      .setAutocomplete(async (query) => {
        const tags = ["rules", "welcome", "faq", "support"]
        return tags.filter((tag) => tag.startsWith(query))
      })
  )
  .execute(async (ctx) => {
    await ctx.g.reply.info(`Tag: ${ctx.options.getString("name")}`)
  })
```

Return strings, numbers, or `{ name, value }` objects — glyria.js normalizes and caps them at Discord's limit of 25.

## Cooldowns

Declare cooldowns directly on the command — the denial reply is styled, ephemeral, and automatic:

```ts
export default new GlyriaCommand()
  .setName("daily")
  .setDescription("Claim your daily reward")
  .setCooldown("24h")                             // per-user by default
  .execute(async (ctx) => { /* ... */ })
```

Scoped cooldowns:

```ts
.setCooldown({ user: "5s", guild: "2s", global: "1s" })
```

Durations accept `ms`, `s`, `m`, `h`, `d` (`"500ms"`, `"5s"`, `"2m"`, `"1h"`, `"1d"`) or a raw number of milliseconds. Subcommands can override the parent's cooldown with their own `.setCooldown()`.

## Permissions

Pass permission names to get Discord-side gating **and** a runtime check with a styled error listing what's missing:

```ts
export default new GlyriaCommand()
  .setName("ban")
  .setDescription("Ban a user")
  .setPermissions(["BanMembers"])
  .addUserOption((option) =>
    option
      .setName("user")
      .setDescription("User to ban")
      .setRequired(true)
  )
  .execute(async (ctx) => {
    // only members with the BanMembers permission get here
  })
```

The legacy bitfield form still works: `.setPermissions(djs.PermissionsBitField.Flags.BanMembers)`.

Restrict a command to the bot owner (Teams supported):

```ts
.setOwnerOnly()
```

## Metadata

Attach custom data to a command with `.setMetaData()`. Glyria stores this data as-is and never interprets it.

```ts
export default new GlyriaCommand()
  .setName("ban")
  .setDescription("Ban a user")
  .setMetaData({
    category: "moderation",
    premium: false,
    guildOnly: true,
  })
  .execute(async (ctx) => {
    // your logic here
  })
```

### useCommands()

`useCommands()` returns the full list of loaded commands along with their metadata.

```ts
const commands = useCommands()

// [
//   {
//     name: "ban",
//     description: "Ban a user",
//     meta: {
//       category: "moderation"
//     }
//   }
// ]
```

Example of a `/help` command organized by category, with pagination:

```ts
export default new GlyriaCommand()
  .setName("help")
  .setDescription("List all commands")
  .execute(async (ctx) => {
    const commands = useCommands()

    const byCategory = commands.reduce((acc, cmd) => {
      const category = (cmd.meta.category as string) ?? "general"

      acc[category] ??= []
      acc[category].push(cmd)

      return acc
    }, {} as Record<string, typeof commands>)

    const pages = Object.entries(byCategory).map(
      ([category, cmds]) =>
        `# ${category}\n${cmds.map((c) => `**/${c.name}** — ${c.description}`).join("\n")}`
    )

    await ctx.g.paginate(pages)
  })
```

## Subcommands

```ts
// src/commands/moderation.ts
export default new GlyriaCommand()
  .setName("moderation")
  .setDescription("Moderation commands")
  .setPermissions(["ModerateMembers"])
  .addSubCommand((cmd) =>
    cmd
      .setName("ban")
      .setDescription("Ban a user")
      .setPermissions(["BanMembers"])            // overrides the parent for this subcommand
      .addUserOption((option) =>
        option
          .setName("user")
          .setDescription("User to ban")
          .setRequired(true)
      )
      .addStringOption((option) =>
        option
          .setName("reason")
          .setDescription("Reason for the ban")
      )
      .execute(async (ctx) => {
        // handle ban
      })
  )
  .addSubCommand((cmd) =>
    cmd
      .setName("kick")
      .setDescription("Kick a user")
      .execute(async (ctx) => {
        // handle kick
      })
  )
```

## Subcommand Groups

```ts
export default new GlyriaCommand()
  .setName("config")
  .setDescription("Configuration commands")
  .addSubCommandGroup((group) =>
    group
      .setName("logs")
      .setDescription("Logs configuration")
      .addSubCommand((cmd) =>
        cmd
          .setName("enable")
          .setDescription("Enable logs")
          .execute(async (ctx) => {
            // handle log enabling
          })
      )
      .addSubCommand((cmd) =>
        cmd
          .setName("disable")
          .setDescription("Disable logs")
          .execute(async (ctx) => {
            // handle log disabling
          })
      )
  )
```

This generates a command structure similar to:

```txt
/config logs enable
/config logs disable
/moderation ban <user> [reason]
/moderation kick <user>
```

## Organizing Commands

Subfolders inside `src/commands/` are for organization only — every file, regardless of depth, is loaded automatically.

```txt
src/commands/
  ping.ts
  moderation/
    ban.ts
    kick.ts
  config/
    advanced/
      logs.ts
```

Keep one command per file. Use subcommands and subcommand groups to organize related functionality.
