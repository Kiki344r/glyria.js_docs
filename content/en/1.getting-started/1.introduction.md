Instead of writing boilerplate over and over, glyria.js lets you focus on what matters — your bot's features.

## Why glyria.js?

### Zero boilerplate

A minimal bot with discord.js requires dozens of lines of setup. With glyria.js:

```ts
// src/index.ts
const client = new GlyriaClient({
    intents: [GatewayIntentBits.Guilds]
})

await client.login()
```

That's it. Token loading, command registration, interaction routing — all handled automatically.

### File-based commands

Drop a file in `src/commands/` and it's automatically loaded and registered on Discord. No manual imports, no registration code.

```ts
// src/commands/ping.ts
export default new GlyriaCommand()
    .setName("ping")
    .setDescription("Pong!")
    .execute(async (ctx) => {
        await ctx.g.reply.success("Pong!")
    })
```

The same applies to `src/events/`, `src/components/`, and `src/modules/` — everything is file-based.

### A context that does the heavy lifting

Every handler receives the interaction already wrapped with `ctx.g` — styled replies, confirmations, pagination, deferred responses, a built-in store, and more:

```ts
export default new GlyriaCommand()
    .setName("clear")
    .setDescription("Clear messages")
    .setCooldown("10s")
    .setPermissions(["ManageMessages"])
    .execute(async (ctx) => {
        if (await ctx.g.confirm("Delete the last 50 messages?")) {
            // ... delete logic
            await ctx.g.reply.success("Done!").ephemeral().send()
        }
    })
```

Cooldowns, permission checks, and their error replies are declared on the command — no `if` statements needed.

### Auto-imports

Every glyria.js utility is available globally — no imports needed in your command files: `GlyriaCommand`, `GlyriaButton`, `defineModule`, `EmbedV2Builder`, `canvas`, and more.

### Embeds V2 by default

glyria.js ships with a first-class Embed V2 builder — the new Discord component system that most frameworks don't support yet. Styled replies (`ctx.g.reply.success(...)`) are rendered with Embed V2 automatically.

### Tooling that goes further

The CLI covers the whole lifecycle, not just scaffolding:

| Command | What it does |
|---|---|
| `glyria dev` | Hot reload for commands, events, components, and modules |
| `glyria studio` | Local web UI to run commands and preview the Discord render |
| `glyria replay` | Re-run any recorded interaction to reproduce a bug |
| `glyria bench` | Load-test your handlers in-process |
| `glyria reload` | Zero-downtime deploys — handlers swap in memory |
| `glyria start` | Self-healing supervisor with crash-loop rollback |

## How it works

glyria.js sits on top of discord.js as a thin DX layer:

```
discord.js      →  handles WebSocket, REST, caching
glyria.js       →  file-based loading, ctx.g, guards, modules, CLI
your bot        →  just your features
```

You always have access to the raw discord.js client if needed — glyria.js never locks you in.
