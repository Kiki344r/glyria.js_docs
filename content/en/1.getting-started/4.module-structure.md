A Glyria module is either a **local folder** in `src/modules/` or a **standard NPM package** declared in `glyria.config.ts`. In both cases Glyria automatically discovers and loads its manifest, commands, events, and components.

```txt
@glyria/your-module/
  src/
    glyria.module.ts   ← manifest (defineModule)
    commands/
    events/
    components/
    index.ts
  dist/
    glyria.module.js
    commands/
    events/
    components/
    index.js
  package.json
```

Local modules follow the same shape, minus the packaging:

```txt
src/modules/economy/
  index.ts             ← manifest (defineModule)
  commands/
  events/
  components/
```

## The manifest

The manifest is the module's identity: a default export created with `defineModule()`. For npm packages Glyria looks for `glyria.module.ts` first, then falls back to `index.ts`.

```ts
// glyria.module.ts
export default defineModule({
  name: "timers",
  version: "1.0.0",
  dependsOn: [],

  setup(ctx) {
    // returned object = public API, consumable via ctx.modules.get("timers")
    return { createJob, deleteJob }
  },
})
```

See the [Module SDK guide](/guide/modules) for lifecycle hooks, middleware, config validation, and dependency resolution.

## dist/ vs src/

In production, Glyria prefers the built output: it looks for `dist/src/`, then `dist/`, then falls back to `src/`. In dev mode (`glyria dev`), `src/` always wins when it exists — even if `dist/` is also present.

| Folder             | Used when                                                 |
| ------------------ | --------------------------------------------------------- |
| `src/`             | Dev mode (`glyria dev`), or no build output in production |
| `dist/src/`, `dist/` | Production, when the package is built                   |

## commands/

Slash commands exposed by the module. Glyria recursively scans this folder and loads every file, exactly like your own `src/commands/`.

```txt
dist/
  commands/
    ban.js
    kick.js
    config/
      logs.js
```

::tip{title="Subfolders"}
Subfolders are purely for organization — every file regardless of depth is loaded as a command.
::

## events/

Discord event listeners exposed by the module. Loaded alongside your own `src/events/`.

## components/

Typed component handlers ([buttons, selects, modals](/guide/components)) exposed by the module. Loaded alongside your own `src/components/`.

## index.ts

The module's main entry point. All exports from this file are automatically available in the user's project under the module's namespace — no import needed.

```ts
// @glyria/timers — src/index.ts
export const createJob = () => { ... }
export const deleteJob = () => { ... }
```

```ts
// In the user's project — no import required
const job = Timers.createJob(() => {
    console.log("runs every minute")
}, "* * * * *")
```

The namespace is the package name without the scope, non-alphanumeric characters stripped, first letter uppercased — `@glyria/timers` → `Timers`, `@glyria/some-feature` → `Somefeature`.

::tip{title="Namespace vs ctx.modules"}
The global namespace exposes the file's **exports** globally. The `setup()` return value is a separate, runtime-checked API consumed with `ctx.modules.get("name")` — prefer it for module-to-module calls since it respects load order and module status.
::

## package.json

The `main` field should point to your built entry point. It is recommended to declare `@glyria/bot` as a peer dependency to avoid shipping multiple instances of the framework in the user's project.

```json
{
  "name": "@glyria/your-module",
  "main": "./dist/index.js",
  "types": "./dist/index.d.ts",
  "peerDependencies": {
    "@glyria/bot": "*"
  }
}
```

::tip{title="peerDependencies"}
Using `peerDependencies` ensures the module reuses the `@glyria/bot` instance already installed in the user's project, rather than bundling its own copy.
::

## Minimal example

A module doesn't need every folder. If a folder doesn't exist, Glyria skips it silently. A module that only exposes utility functions through its `index.ts` is perfectly valid.

```txt
@glyria/timers/
  dist/
    index.js    ← only exports, no commands or events
  package.json
```
