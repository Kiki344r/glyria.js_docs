After running `npx glyria init`, your project will look like this:

```txt
your-bot/
  src/
    commands/
    events/
    components/
    modules/
    composables/
    utils/
    index.ts
  .glyria/
    imports.d.ts
  .env
  .gitignore
  tsconfig.json
  glyria.config.ts
  package.json
```

## src/

The main folder containing your bot's source code.

### src/commands/

All your slash commands live here. glyria.js recursively scans this folder at startup and automatically registers every file.

```txt
src/commands/
  ping.ts
  moderation/
    ban.ts
    kick.ts
  config/
    logs.ts
```

::tip{title="Subfolders as categories"}
Subfolders are purely for organization — every `.ts` file, regardless of its depth, is loaded as a command.
::

### src/events/

Discord event listeners. Each file handles one or more discord.js events. Replyable arguments (messages, interactions) arrive already wrapped with `ctx.g`.

### src/components/

Interactive component handlers — buttons, select menus, and modals with [typed customIds](/guide/components):

```ts
// src/components/vote.ts
export default new GlyriaButton("vote:{pollId}:{choice}")
  .execute(async (ctx, params) => {
    await ctx.g.update.success(`Voted ${params.choice}!`)
  })
```

### src/modules/

Self-contained feature modules built with the [Module SDK](/guide/modules). Each module folder has an `index.ts` manifest and can carry its own `commands/`, `events/`, and `components/` — all auto-loaded.

```txt
src/modules/
  economy/
    index.ts        # defineModule({ ... })
    commands/
      balance.ts
```

Scaffold one with `glyria module create <name>`.

### src/composables/

Business logic and stateful utilities. Files placed here are automatically available globally through auto-imports — no import statement needed. The convention is to prefix functions with `use`.

```ts
// src/composables/useModeration.ts
export const useModeration = () => {
  // ban logic, kick logic, etc.
}

// src/commands/ban.ts — no import required
const moderation = useModeration()
```

### src/utils/

Pure functions with no dependencies or side effects. Files placed here are also auto-imported globally.

```ts
// src/utils/formatDate.ts
export const formatDate = (date: Date) => {
  // ...
}

// src/commands/ping.ts — no import required
const formatted = formatDate(new Date())
```

::tip{title="composables/ vs utils/"}
`utils/` is for pure functions with no dependencies — formatting, parsing, math. `composables/` is for logic that interacts with the database, Discord, or other services.
::

### src/index.ts

Your bot's entry point. Minimal by design:

```ts
const client = new GlyriaClient({
  intents: [GatewayIntentBits.Guilds]
})

await client.login()
```

## .glyria/

Generated and managed by glyria.js at runtime:

| Path | Purpose |
|---|---|
| `imports.d.ts` | TypeScript declarations for auto-imports |
| `store.json` | Persisted store data (when `store.adapter` is `"json"`) |
| `interactions/` | Recorded interactions for [`glyria replay`](/cli/replay) |
| `commands.snapshot.json` | Command snapshot used by the [auto-changelog](/guide/production) |
| `bot.pid` | Pid file used by [`glyria reload`](/cli/reload) |
| `last-good/` | Last stable build, used by the [self-healing supervisor](/cli/start) |

::warning{title="Do not modify"}
Declaration files are regenerated on every `glyria generate` or `glyria dev` run. Any manual changes will be overwritten. Add `.glyria/` to your `.gitignore`.
::

## .env

Environment variables for your bot. glyria.js automatically loads this file at startup.

```bash
TOKEN=your_bot_token_here
```

## glyria.config.ts

Global configuration for your bot — theme, modules, store, logging, and more. See the [full config reference](/api-reference/define-glyria-config).

```ts
export default defineGlyriaConfig({
  modules: ["@glyria/timers"],
  logChannel: "123456789",
  store: { adapter: "json" },
})
```

## tsconfig.json

Pre-configured by `npx glyria init`. Includes the `.glyria/` folder for auto-import type resolution.
