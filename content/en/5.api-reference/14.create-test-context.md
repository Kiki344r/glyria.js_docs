## Overview

`createTestContext` builds a fake interaction wrapped in a full Glyria context — run command handlers, module hooks, or components without Discord, then assert on the captured replies.

```ts
const ctx = createTestContext({ options: { user: "42" } })
await myHandler(ctx)

ctx.repliesText() // ["✅ User banned."]
```

The returned context is a real `GlyriaContext`: `ctx.g.reply.*`, `ctx.g.store`, `ctx.g.edit`, `ctx.g.defer`, `ctx.g.reply.loading` all work. Sends are captured instead of hitting the network.

::tip{title="Auto-import"}
`createTestContext` is available globally in a Glyria project. In a plain vitest file, import it: `import { createTestContext } from "@glyria/bot"`.
::

## TestContextOptions

Every option has a sensible default — `createTestContext()` with no arguments is valid.

| Option       | Type                      | Default          | Description                                                    |
| ------------ | ------------------------- | ---------------- | --------------------------------------------------------------- |
| `userId`     | `string`                  | `"test-user"`    | Id of the invoking user                                          |
| `username`   | `string`                  | `"tester"`       | Username of the invoking user                                    |
| `guildId`    | `string \| null`          | `"test-guild"`   | Guild id — pass `null` to simulate a DM                          |
| `channelId`  | `string`                  | `"test-channel"` | Channel id                                                       |
| `member`     | `unknown`                 | `null`           | Value returned by `ctx.member` / `ctx.g.member`                  |
| `options`    | `Record<string, unknown>` | `{}`             | Slash option values, keyed by option name (`getString`, `getInteger`, ... read from it) |
| `subcommand` | `string[]`                | `[]`             | Subcommand path, e.g. `["theme", "set"]` for group+sub or `["show"]` |

## TestContext

`createTestContext` returns a `GlyriaContext<FakeInteraction>` extended with capture helpers:

| Member           | Type              | Description                                              |
| ---------------- | ----------------- | -------------------------------------------------------- |
| `replies`        | `CapturedReply[]` | Everything the handler sent, in order                     |
| `repliesText()`  | `string[]`        | Plain-text view of every reply (Embed V2 text extracted, empty payloads filtered out) |

The fake interaction itself exposes `user`, `member`, `guildId`, `channelId`, `replied`, `deferred`, an `options` resolver (`getString` / `getInteger` / `getNumber` / `getBoolean` / `getUser` / `getRole` / `getSubcommand` / `getSubcommandGroup` / `getFocused`), the reply methods (`reply` / `editReply` / `followUp` / `deferReply`), and `isChatInputCommand()` (always `true`).

### CapturedReply

| Field       | Type                                                                       | Description                     |
| ----------- | --------------------------------------------------------------------------- | ------------------------------- |
| `via`       | `"reply" \| "editReply" \| "followUp" \| "deferReply" \| "update" \| "edit"` | How the payload was delivered   |
| `payload`   | `unknown`                                                                    | The raw payload                 |
| `timestamp` | `number`                                                                     | `Date.now()` at capture time    |

::warning{title="No component clicks"}
The fake message returned by captures supports `edit` (so `g.edit()` and `g.reply.loading()` work), but `awaitMessageComponent` throws — `g.confirm()` and `g.paginate()` need a real user to click.
::

## Testing a command handler

```ts
// test/ban.test.ts
import { describe, expect, it } from "vitest"
import { createTestContext } from "@glyria/bot"
import ban from "../src/commands/ban"

describe("/ban", () => {
  it("bans the given user with a reason", async () => {
    const ctx = createTestContext({
      userId: "mod-1",
      options: { user: { id: "999" }, reason: "spam" },
    })

    // getHandlers() exposes the functions registered with .execute()
    const handler = ban.getHandlers()[0]!.handler
    await handler(ctx)

    expect(ctx.repliesText()[0]).toContain("banned")
    expect(ctx.replies[0]!.via).toBe("reply")
  })

  it("reads subcommand paths", async () => {
    const ctx = createTestContext({ subcommand: ["theme", "set"] })
    expect(ctx.options.getSubcommandGroup()).toBe("theme")
    expect(ctx.options.getSubcommand()).toBe("set")
  })
})
```

## Testing a module middleware

```ts
// test/blacklist.test.ts
import { describe, expect, it, vi } from "vitest"
import { createTestContext } from "@glyria/bot"
import blacklist from "../src/modules/blacklist"

describe("blacklist middleware", () => {
  it("blocks blacklisted users and skips next()", async () => {
    const ctx = createTestContext({ userId: "banned-user" })
    await ctx.g.store.user.set("blacklisted", true)

    const next = vi.fn()
    await blacklist.hooks!.beforeCommand!(
      ctx,
      { name: "ping", kind: "chat" },
      next,
    )

    expect(next).not.toHaveBeenCalled()
    expect(ctx.repliesText()[0]).toContain("blacklisted")
  })

  it("lets everyone else through", async () => {
    const ctx = createTestContext()
    const next = vi.fn()

    await blacklist.hooks!.beforeCommand!(ctx, { name: "ping", kind: "chat" }, next)

    expect(next).toHaveBeenCalledOnce()
    expect(ctx.replies).toHaveLength(0)
  })
})
```
