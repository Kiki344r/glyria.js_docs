## Overview

Glyria ships a small async key-value store behind `ctx.g.store`, `ctx.g.guildConfig`, module stores, and `useStore()`. It is adapter-based: in-memory by default, JSON-file persistence out of the box, or any backend you plug in.

```ts
// In a handler — pre-scoped views
const xp = (await ctx.g.store.user.get<number>("xp")) ?? 0
await ctx.g.store.user.set("xp", xp + 10)

// Anywhere — the raw store
const store = useStore()
await store.forGuild(guildId).set("prefix", "!")
```

The adapter is selected via the [`store` key of `glyria.config.ts`](/api-reference/define-glyria-config#store).

## StoreAdapter

The contract every backend implements. All methods are async.

```ts
interface StoreAdapter {
  get(key: string): Promise<unknown>
  set(key: string, value: unknown): Promise<void>
  delete(key: string): Promise<boolean>
  keys(prefix: string): Promise<string[]>
}
```

| Method          | Returns            | Description                                  |
| --------------- | ------------------ | -------------------------------------------- |
| `get(key)`      | `Promise<unknown>` | Read a value (`undefined` when absent)       |
| `set(key, value)` | `Promise<void>`  | Write a value                                |
| `delete(key)`   | `Promise<boolean>` | Delete a key — `true` if it existed          |
| `keys(prefix)`  | `Promise<string[]>`| List every key starting with `prefix`        |

Implement this interface to back the store with Redis, SQLite, Postgres, ... and pass the instance as `store.adapter` in your config.

## MemoryStoreAdapter

The default adapter — a plain `Map` in memory. Zero setup, nothing survives a restart.

```ts
const adapter = new MemoryStoreAdapter()
```

## JsonFileStoreAdapter

Zero-config persistence: keeps everything in memory and **debounces writes** to a JSON file. Good for small bots; plug a real adapter for anything serious.

```ts
new JsonFileStoreAdapter(path, flushDelay?)
```

| Parameter    | Type     | Default | Description                                     |
| ------------ | -------- | ------- | ----------------------------------------------- |
| `path`       | `string` | —       | JSON file to load at boot and write to          |
| `flushDelay` | `number` | `250`   | Debounce delay (ms) between a write and a flush |

Behavior:

- On construction, the file is loaded if it exists (an unparsable file logs a warning and starts empty).
- Every `set`/`delete` schedules a flush `flushDelay` ms later; multiple writes within the window coalesce into one file write.
- `flush()` writes immediately, cancelling any pending timer (parent directories are created as needed).

| Method     | Returns | Description                              |
| ---------- | ------- | ---------------------------------------- |
| `flush()`  | `void`  | Write the file now, cancel pending timer |

## ScopedStore

Every consumer-facing view of the store is a `ScopedStore` — the same four operations with the scope prefix applied transparently:

```ts
interface ScopedStore {
  get<T = unknown>(key: string): Promise<T | undefined>
  set(key: string, value: unknown): Promise<void>
  delete(key: string): Promise<boolean>
  keys(): Promise<string[]>
}
```

| Method            | Returns                   | Description                                        |
| ----------------- | ------------------------- | -------------------------------------------------- |
| `get<T>(key)`     | `Promise<T \| undefined>` | Read a value, typed via the generic                |
| `set(key, value)` | `Promise<void>`           | Write a value                                      |
| `delete(key)`     | `Promise<boolean>`        | Delete a key — `true` if it existed                |
| `keys()`          | `Promise<string[]>`       | Keys in this scope, with the prefix stripped       |

```ts
const inventory = ctx.g.store.user
await inventory.set("sword", { damage: 12 })
const sword = await inventory.get<{ damage: number }>("sword")
await inventory.keys()   // ["sword", ...]
await inventory.delete("sword")
```

## GlyriaStore

The root store, wrapping an adapter and handing out scoped views:

| Member                     | Returns       | Key prefix              | Description                                       |
| -------------------------- | ------------- | ----------------------- | ------------------------------------------------- |
| `global`                   | `ScopedStore` | `global:`               | Bot-wide scope                                    |
| `forGuild(guildId)`        | `ScopedStore` | `guild:<id>:`           | Per-guild data                                    |
| `forUser(userId)`          | `ScopedStore` | `user:<id>:`            | Per-user data                                     |
| `forModule(name)`          | `ScopedStore` | `module:<name>:`        | Namespaced scope handed to modules (`ctx.store`)  |
| `forGuildConfig(guildId)`  | `ScopedStore` | `guildconfig:<id>:`     | Per-guild configuration, kept apart from guild data |

## configureStore(config)

Builds the singleton `GlyriaStore` from a `StoreConfig`. Called by the framework at boot with your `glyria.config.ts` `store` entry — call it yourself only in scripts/tests.

```ts
interface StoreConfig {
  adapter?: "memory" | "json" | StoreAdapter
  /** Path of the JSON file when adapter is "json". Default: .glyria/store.json */
  path?: string
}
```

| `adapter` value        | Result                                                           |
| ---------------------- | ---------------------------------------------------------------- |
| omitted or `"memory"`  | `MemoryStoreAdapter`                                             |
| `"json"`               | `JsonFileStoreAdapter` at `path` (default `.glyria/store.json`, resolved from the cwd) |
| a `StoreAdapter` object| Used as-is                                                       |

```ts
configureStore({ adapter: "json", path: ".glyria/store.json" })
```

## useStore()

Returns the singleton `GlyriaStore`. If `configureStore()` has never been called, a memory-backed store is created lazily.

```ts
const store = useStore()
await store.global.set("startedAt", Date.now())
```

::tip{title="Auto-import"}
`useStore` is available globally — no import needed.
::
