## Overview

Every command, component, and event handler receives a `GlyriaContext<T>` — the raw discord.js object (`T`) untouched, plus a `g` namespace holding the whole Glyria toolkit.

```ts
export default new GlyriaCommand()
  .setName("profile")
  .setDescription("Show your profile")
  .execute(async (ctx) => {
    // ctx is the ChatInputCommandInteraction — everything discord.js still works
    const name = ctx.user.username

    // ctx.g is the Glyria layer
    const xp = (await ctx.g.store.user.get<number>("xp")) ?? 0
    await ctx.g.reply
      .primary(`Profile of ${name}`)
      .field("XP", String(xp))
      .ephemeral()
  })
```

```ts
type GlyriaContext<T extends Replyable> = T & { g: GlyriaG<T> }
```

You can wrap any replyable object yourself with `createReplyableContext(source)` — the framework does it automatically before invoking your handlers.

::tip{title="Auto-defer"}
Before invoking a handler, Glyria arms an automatic `deferReply` that fires after ~1.5s if you haven't responded yet — you never hit Discord's 3-second interaction window. Any send through `ctx.g` cancels the timer.
::

## Styled replies

### `ctx.g.reply`

Six styled senders, one per variant. Each returns a **thenable `ReplyChain`** — `await` it directly, or chain builder methods first.

| Sender                | Color (theme key)  | Prefix |
| --------------------- | ------------------ | ------ |
| `reply.primary(content, opts?)`   | `primaryColor` (`#5865F2`)   | —    |
| `reply.secondary(content, opts?)` | `secondaryColor` (`#4F545C`) | —    |
| `reply.success(content, opts?)`   | `successColor` (`#57F287`)   | ✅   |
| `reply.warning(content, opts?)`   | `warningColor` (`#FEE75C`)   | ⚠️   |
| `reply.error(content, opts?)`     | `errorColor` (`#ED4245`)     | ❌   |
| `reply.info(content, opts?)`      | `infoColor` (`#5DADE2`)      | ℹ️   |

Colors and prefixes come from your [theme configuration](/api-reference/define-glyria-config#themeembedv2).

Sends are routed automatically based on the source's state: fresh interaction → `reply`, deferred → `editReply`, already replied → `followUp` (falling back to `channel.send`). If the surface rejects Components V2 payloads, Glyria retries once as plain text, preserving files.

### ReplyChain

| Method                    | Returns            | Description                                                    |
| ------------------------- | ------------------ | -------------------------------------------------------------- |
| `.description(text)`      | `this`             | Append a text block below the title line                       |
| `.field(name, value)`     | `this`             | Append a `**name**\nvalue` block                               |
| `.file(data, name)`       | `this`             | Attach a file (`Buffer` or path string) shown in the container |
| `.ephemeral(bool?)`       | `this`             | Make this send ephemeral (defaults to `true`)                  |
| `.send()`                 | `Promise<unknown>` | Send explicitly — idempotent                                   |
| `.then(...)`              | —                  | The chain is thenable: `await` sends it                        |

```ts
await ctx.g.reply
  .success("Ban applied")
  .description("The user has been removed from the server.")
  .field("Reason", reason)
  .file(logBuffer, "audit.txt")
  .ephemeral()
// awaiting the chain sends it — no .send() needed
```

### `ctx.g.reply.raw(payload)`

Escape hatch: sends a raw discord.js payload, bypassing Embed V2 styling entirely (still routed and recorded in `history()`).

```ts
await ctx.g.reply.raw({ content: "plain text", embeds: [myEmbed] })
```

### `ctx.g.reply.loading(content, promise, opts?)`

Sends a styled `⏳` loading message (secondary color), awaits the promise, then edits the message with the outcome — success style on resolve, error style on reject. Resolves with the promise's result and **rethrows** on failure.

```ts
const user = await ctx.g.reply.loading(
  "Fetching profile...",
  fetchProfile(id),
  {
    done: (result) => `Found ${(result as Profile).name}!`,
    fail: (error) => `Lookup failed: ${String(error)}`,
  },
)
```

#### LoadingOptions

| Option      | Type                                  | Default                  | Description                        |
| ----------- | ------------------------------------- | ------------------------ | ---------------------------------- |
| `ephemeral` | `boolean`                             | context default          | Send the loading message ephemeral |
| `done`      | `string \| (result) => string`        | `"Done"`                 | Message shown on resolve           |
| `fail`      | `string \| (error) => string`         | `"Something went wrong"` | Message shown on reject            |

## `ctx.g.followUp`

The same six styled senders (`primary`/`secondary`/`success`/`warning`/`error`/`info`, each returning a `ReplyChain`) plus `.raw(payload)`, but always sent as a follow-up message rather than the initial reply.

```ts
await ctx.g.reply.success("Order created")
await ctx.g.followUp.info("A confirmation email has been sent").ephemeral()
```

## `ctx.g.confirm(content, opts?)`

Sends a warning-colored message with **Confirm** / **Cancel** buttons and resolves to `true` or `false`. Only the invoking user can click; a timeout (or any failure to collect) resolves to `false` and disables the buttons.

```ts
const ok = await ctx.g.confirm("Really delete all 42 warnings?", {
  timeout: "1m",
  confirmLabel: "Delete",
  cancelLabel: "Keep",
})
if (!ok) return ctx.g.reply.secondary("Cancelled.")
```

### ConfirmOptions

| Option         | Type       | Default     | Description                                        |
| -------------- | ---------- | ----------- | -------------------------------------------------- |
| `timeout`      | `Duration` | `"30s"`     | Idle timeout before the confirmation resolves to `false` |
| `confirmLabel` | `string`   | `"Confirm"` | Label of the confirm button                        |
| `cancelLabel`  | `string`   | `"Cancel"`  | Label of the cancel button                         |
| `ephemeral`    | `boolean`  | context default | Send the prompt ephemeral                      |

`Duration` is a string like `"500ms"`, `"5s"`, `"2m"`, `"1h"`, `"1d"` or a number of milliseconds.

## `ctx.g.paginate(pages, opts?)`

Renders an array of page strings with ◀ / ▶ buttons and a page indicator. Only the invoking user can navigate; buttons are disabled when the timeout elapses. A single page is sent without buttons. Throws when `pages` is empty.

```ts
const pages = chunks.map((c, i) => `**Page ${i + 1}**\n${c}`)
await ctx.g.paginate(pages, { timeout: "5m", ephemeral: true })
```

### PaginateOptions

| Option      | Type       | Default | Description                                          |
| ----------- | ---------- | ------- | ---------------------------------------------------- |
| `timeout`   | `Duration` | `"2m"`  | Idle timeout before the pagination buttons disable   |
| `ephemeral` | `boolean`  | context default | Send the pages ephemeral                     |

## `ctx.g.edit(content, opts?)`

Edits the **last message sent through this context** with a freshly styled payload. The variant defaults to the last send's variant (or `primary` when the last send was raw); pass `{ variant }` to restyle. Throws when nothing has been sent yet.

```ts
await ctx.g.reply.secondary("Working...")
// ...
await ctx.g.edit("All done!", { variant: "success" })
```

## `ctx.g.defer(opts?)`

Defers the reply explicitly (a no-op when already deferred/replied, or when the source has no `deferReply`).

```ts
await ctx.g.defer({ ephemeral: true })
```

::tip{title="Conditional typing"}
`defer` only exists on the context when the source supports `deferReply` (interactions — not plain messages). Likewise, `update` only exists for component interactions. TypeScript enforces this: `GlyriaG<T>` adds each member only when `T` supports it.
::

## `ctx.g.ephemeral(bool?)`

Sets the **default** ephemeral behavior for every subsequent send from this context (defaults to `true` when called without arguments). Per-send options still win. Ignored on sources that can't be ephemeral (plain messages).

```ts
ctx.g.ephemeral() // everything from here on is ephemeral by default
```

## `ctx.g.history()`

Returns a copy of every message sent through this context, most recent last.

### SentEntry

| Field       | Type                                          | Description                              |
| ----------- | --------------------------------------------- | ---------------------------------------- |
| `variant`   | `ReplyVariant \| "raw"`                       | Style used (`"raw"` for unstyled sends)  |
| `via`       | `"reply" \| "followUp" \| "edit" \| "update"` | Delivery channel actually used           |
| `payload`   | `unknown`                                     | The payload that was sent                |
| `message`   | `unknown`                                     | The resulting message / response object  |
| `timestamp` | `number`                                      | `Date.now()` at send time                |

## `ctx.g.onSend(listener)`

Registers a callback invoked after every message sent through this context. A throwing listener is logged and never breaks the send.

```ts
ctx.g.onSend((entry) => analytics.track("bot_reply", { via: entry.via }))
```

## `ctx.g.log(message, level?)`

Logs to the console and — when `logChannel` is set in `glyria.config.ts` — posts a styled message to that Discord channel. `level` is `"info"` (default), `"warn"`, or `"error"` and maps to the info/warning/error variants.

```ts
await ctx.g.log(`${ctx.user.tag} purged 50 messages`, "warn")
```

## `ctx.g.user` / `ctx.g.member`

| Getter   | Description                                                              |
| -------- | ------------------------------------------------------------------------ |
| `user`   | The invoking user — `interaction.user` or `message.author`               |
| `member` | The invoking guild member, when available                                 |

## `ctx.g.store`

Built-in state store, pre-scoped to the invocation. See [Store](/api-reference/store) for the `ScopedStore` API and adapter configuration.

| Scope          | Type          | Description                                       |
| -------------- | ------------- | ------------------------------------------------- |
| `store.guild`  | `ScopedStore` | Scoped to the current guild — throws in DMs       |
| `store.user`   | `ScopedStore` | Scoped to the invoking user                       |
| `store.global` | `ScopedStore` | Bot-wide scope                                    |

```ts
const xp = (await ctx.g.store.user.get<number>("xp")) ?? 0
await ctx.g.store.user.set("xp", xp + 10)
```

## `ctx.g.guildConfig`

A `ScopedStore` namespaced for per-guild configuration, kept apart from regular guild data. Throws when used in DMs.

```ts
await ctx.g.guildConfig.set("welcomeChannel", channel.id)
const welcome = await ctx.g.guildConfig.get<string>("welcomeChannel")
```

## `ctx.g.canvas`

The built-in visual generator — rank cards and leaderboards as SVG/PNG. See [Canvas](/api-reference/canvas).

```ts
const card = await ctx.g.canvas
  .rankCard({ username: "Enzo", level: 12, xp: 340, xpNeeded: 500, rank: 3 })
  .attachment()

await ctx.g.reply.primary("Your rank").file(card.data, card.name)
```

## `ctx.g.update` (component interactions only)

For button, select, and modal interactions, `ctx.g.update` exposes the same six styled senders but re-styles the **originating component message** (via `interaction.update`) instead of sending a new one. Update payloads are single-shot: the update is dispatched as soon as the sender is called, and the chained builder methods (`description`/`field`/`file`/`ephemeral`) are no-ops — pass `{ ephemeral }` as the second argument instead.

```ts
export default new GlyriaButton("verify:{userId}").execute(async (ctx, params) => {
  await ctx.g.update.success("You are verified!")
})
```

## Option interfaces

### ReplyOptions

| Option      | Type      | Description                       |
| ----------- | --------- | --------------------------------- |
| `ephemeral` | `boolean` | Send this message ephemeral       |

Accepted as the second argument of every styled sender — equivalent to chaining `.ephemeral()`.

### Types summary

```ts
type ReplyVariant = "primary" | "secondary" | "success" | "warning" | "error" | "info"

interface ReplyOptions { ephemeral?: boolean }

interface ConfirmOptions {
  timeout?: Duration        // default "30s"
  confirmLabel?: string     // default "Confirm"
  cancelLabel?: string      // default "Cancel"
  ephemeral?: boolean
}

interface PaginateOptions {
  timeout?: Duration        // default "2m"
  ephemeral?: boolean
}

interface LoadingOptions extends ReplyOptions {
  done?: string | ((result: unknown) => string)  // default "Done"
  fail?: string | ((error: unknown) => string)   // default "Something went wrong"
}

interface SentEntry {
  variant: ReplyVariant | "raw"
  via: "reply" | "followUp" | "edit" | "update"
  payload: unknown
  message: unknown
  timestamp: number
}
```
