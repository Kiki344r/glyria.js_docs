## Overview

`GlyriaButton`, `GlyriaSelect`, and `GlyriaModal` define handlers for interactive components. The constructor takes a **customId pattern** with `{param}` placeholders — Glyria matches incoming interactions against it and hands your handler the extracted params, fully typed.

```ts
// src/components/rolePicker.ts
export default new GlyriaButton("role_picker:{roleId}:{userId}")
  .execute(async (ctx, params) => {
    // params: { roleId: string; userId: string } — inferred from the pattern
    await ctx.g.update.success(`Role <@&${params.roleId}> assigned!`)
  })
```

Component files live in `src/components/` (scanned recursively). A file may export one component as `default` or several as named exports — every exported `GlyriaButton` / `GlyriaSelect` / `GlyriaModal` instance is registered. Modules can also ship their own `components/` folder.

::tip{title="Auto-import"}
`GlyriaButton`, `GlyriaSelect`, and `GlyriaModal` are available globally — no import needed.
::

## Builders

### `GlyriaButton<P>` / `GlyriaSelect<P>` / `GlyriaModal<P>`

All three share the same shape — only the interaction type passed to the handler differs:

| Class          | Handler context                              |
| -------------- | -------------------------------------------- |
| `GlyriaButton` | `GlyriaContext<ButtonInteraction>`           |
| `GlyriaSelect` | `GlyriaContext<AnySelectMenuInteraction>`    |
| `GlyriaModal`  | `GlyriaContext<ModalSubmitInteraction>`      |

#### Constructor

```ts
new GlyriaButton("confirm_ban:{userId}")
```

The pattern (a string with optional `{param}` placeholders) is the single constructor argument and is available as the readonly `pattern` property.

#### Methods

| Method               | Returns               | Description                                                          |
| -------------------- | --------------------- | -------------------------------------------------------------------- |
| `.execute(handler)`  | `this`                | Set the handler: `(ctx, params) => unknown` with `params: PatternParams<P>` |
| `.id(params)`        | `string`              | Build a concrete customId for this component (use when rendering)    |
| `.build()`           | `ComponentDefinition` | Compile the pattern into a definition — throws if no `execute()` handler was set |

```ts
export const banButton = new GlyriaButton("confirm_ban:{userId}")
  .execute(async (ctx, params) => {
    await ctx.guild?.members.ban(params.userId)
    await ctx.g.update.success("User banned.")
  })

// elsewhere, when rendering the button:
const customId = banButton.id({ userId: target.id })
// "confirm_ban:123456789"
```

## `PatternParams<P>`

The param names are inferred **from the pattern string type** — every `{name}` placeholder becomes a required `string` property:

```ts
type PatternParams<"role_picker:{roleId}:{userId}">
// => { roleId: string; userId: string }

type PatternParams<"refresh">
// => {} (no params)
```

This is what makes `params` in `.execute()` and the argument of `.id()` fully typed: renaming a placeholder in the pattern immediately flags every call site.

## Helpers

### `buildCustomId(pattern, params)`

Builds a concrete customId by substituting each `{name}` placeholder with `params[name]`. This is what `.id()` calls under the hood.

```ts
buildCustomId("role_picker:{roleId}", { roleId: "42" })
// => "role_picker:42"
```

Throws when:

- a placeholder has no matching param — `customId: missing param "roleId" for "role_picker:{roleId}"`
- a param value contains `":"` — `customId: param "roleId" cannot contain ":"` (the `:` is the segment separator, so values must not contain it)

### `compilePattern(pattern)`

Compiles a pattern into an anchored `RegExp` with named capture groups — each placeholder matches one `[^:]+` segment. Literal parts are regex-escaped.

```ts
compilePattern("role_picker:{roleId}")
// => /^role_picker:(?<roleId>[^:]+)$/
```

Glyria uses the compiled regex to route incoming interactions and extract params.

## ComponentDefinition

`.build()` returns the plain shape the loader registers:

```ts
type ComponentKind = "button" | "select" | "modal"

interface ComponentDefinition {
  kind: ComponentKind
  pattern: string
  regex: RegExp
  handler: (ctx: never, params: Record<string, string>) => unknown
}
```

You normally never call `.build()` yourself — the loader does it for every exported component.

## File locations

| Location                          | Loaded |
| --------------------------------- | ------ |
| `src/components/**` (recursive)   | ✅     |
| `src/modules/<name>/components/`  | ✅     |
| `<npm module pkg>/components/`    | ✅ (for packages listed in `modules`) |

A file may export a single component as `default` or multiple components as named exports:

```ts
// src/components/tickets.ts
export const openTicket = new GlyriaButton("ticket:open:{userId}")
  .execute(async (ctx, params) => { /* ... */ })

export const closeTicket = new GlyriaButton("ticket:close:{ticketId}")
  .execute(async (ctx, params) => { /* ... */ })

export const ticketTopic = new GlyriaSelect("ticket:topic:{ticketId}")
  .execute(async (ctx, params) => {
    const topic = ctx.values[0]
    await ctx.g.update.info(`Topic set to ${topic}`)
  })
```
