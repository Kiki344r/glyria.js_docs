## Overview

`GlyriaCommand` is the builder used to define Discord slash commands. Every file in `src/commands/` should export a `GlyriaCommand` instance as default.

```ts
export default new GlyriaCommand()
  .setName("ping")
  .setDescription("Pong!")
  .execute(async (ctx) => {
    await ctx.g.reply.primary("Pong!")
  })
```

::tip{title="Auto-import"}
`GlyriaCommand` is available globally — no import needed.
::

## GlyriaCommand

### Methods

| Method                    | Returns | Description                                                    |
| ------------------------- | ------- | -------------------------------------------------------------- |
| `.setName(name)`          | `this`  | Set the command name                                           |
| `.setDescription(desc)`   | `this`  | Set the command description                                    |
| `.setPermissions(perms)`  | `this`  | Restrict the command to specific permissions                   |
| `.setCooldown(input)`     | `this`  | Add a per-user, per-guild, or global cooldown                  |
| `.setOwnerOnly(bool?)`    | `this`  | Restrict the command to the bot owner                          |
| `.setMetaData(meta)`      | `this`  | Attach custom metadata to the command                          |
| `.addStringOption(fn)`    | `this`  | Add a string option                                            |
| `.addBooleanOption(fn)`   | `this`  | Add a boolean option                                           |
| `.addIntegerOption(fn)`   | `this`  | Add an integer option                                          |
| `.addNumberOption(fn)`    | `this`  | Add a number option                                            |
| `.addUserOption(fn)`      | `this`  | Add a user option                                              |
| `.addRoleOption(fn)`      | `this`  | Add a role option                                              |
| `.addSubCommand(fn)`      | `this`  | Add a subcommand                                               |
| `.addSubCommandGroup(fn)` | `this`  | Add a subcommand group                                         |
| `.execute(handler)`       | `this`  | Set the command handler                                        |
| `.getAutocompletes()`     | `AutocompleteEntry[]` | List every registered autocomplete handler (framework use) |

### `.setPermissions()`

Restricts the command to members with specific Discord permissions. Accepts:

- a `bigint`, `number`, or `string` — used as-is as the Discord `default_member_permissions` bitfield
- a `PermissionName[]` array (e.g. `["BanMembers"]`) — the names are OR-ed into the `default_member_permissions` bitfield **and** re-checked at runtime by Glyria

```ts
// Raw bitfield — Discord-side gating only
export default new GlyriaCommand()
  .setName("ban")
  .setDescription("Ban a user")
  .setPermissions(djs.PermissionsBitField.Flags.BanMembers)

// Array form — Discord-side gating + runtime guard
export default new GlyriaCommand()
  .setName("ban")
  .setDescription("Ban a user")
  .setPermissions(["BanMembers"])
```

With the array form, when a member without the permission runs the command anyway (e.g. an admin loosened the Discord-side override), Glyria denies it with a styled ephemeral error listing the missing permission(s):

> ❌ You need the following permission(s) to use this command: **Ban Members**

`PermissionName` is any key of discord.js `PermissionFlagsBits` (`"BanMembers"`, `"ManageGuild"`, `"ModerateMembers"`, ...).

### `.setCooldown()`

Adds a declarative cooldown. Accepts a `CooldownInput`:

| Form                            | Meaning                                                       |
| ------------------------------- | ------------------------------------------------------------- |
| `"5s"`, `"2m"`, `"1h"`, `"1d"`  | Duration string — applied as a **per-user** cooldown          |
| `5000`                          | Number of milliseconds — applied as a **per-user** cooldown   |
| `{ user?, guild?, global? }`    | Per-scope durations (each a string or number of milliseconds) |

```ts
// 5 seconds per user
export default new GlyriaCommand()
  .setName("daily")
  .setDescription("Claim your daily reward")
  .setCooldown("5s")

// Different scopes
export default new GlyriaCommand()
  .setName("raffle")
  .setDescription("Start a raffle")
  .setCooldown({ user: "30s", guild: "5m", global: "10s" })
```

When a scope is still cooling down, Glyria replies with a styled ephemeral error:

> ❌ You're on cooldown — try again in **4s**.

Cooldowns are only consumed once every other guard (permissions, owner-only) has passed.

### `.setOwnerOnly()`

Restricts the command to the bot owner (resolved from the Discord application). Defaults to `true` when called without arguments.

```ts
export default new GlyriaCommand()
  .setName("eval")
  .setDescription("Owner only!")
  .setOwnerOnly()
```

Non-owners get a styled ephemeral error:

> ❌ This command is restricted to the bot owner.

### `.setMetaData()`

Attaches custom metadata to the command. Accepts any key-value object — Glyria stores it as-is and never interprets it.

```ts
export default new GlyriaCommand()
  .setName("ban")
  .setDescription("Ban a user")
  .setMetaData({
    category: "moderation",
    premium: false,
    guildOnly: true,
  })
  .execute(async (ctx) => {
    // your logic here
  })
```

Metadata is accessible at runtime via `useCommands()`:

```ts
const commands = useCommands()
// [
//   { name: "ban", description: "Ban a user", meta: { category: "moderation", ... } },
//   { name: "ping", description: "Pong!", meta: {} },
// ]
```

::tip{title="useCommands"}
`useCommands()` is available globally — no import needed. The registry is populated automatically when the bot starts.
::

### `.execute()`

Sets the command handler. The handler receives a `GlyriaContext<ChatInputCommandInteraction>` — the raw discord.js interaction with an extra `ctx.g` namespace holding the whole Glyria toolkit (styled replies, confirm, paginate, store, canvas, ...).

```ts
export default new GlyriaCommand()
  .setName("ping")
  .setDescription("Pong!")
  .execute(async (ctx) => {
    // ctx = the ChatInputCommandInteraction, untouched
    const ws = ctx.client.ws.ping

    // ctx.g = the Glyria layer
    await ctx.g.reply.success(`Pong! (${ws}ms)`)
  })
```

See [ReplyableContext](/api-reference/replyable-context) for the full `ctx.g` API.

## CommandOption

Passed as argument in every `add*Option` callback.

### Methods

| Method                     | Returns | Description                                             |
| -------------------------- | ------- | ------------------------------------------------------- |
| `.setName(name)`           | `this`  | Set the option name                                     |
| `.setDescription(desc)`    | `this`  | Set the option description                              |
| `.setRequired(bool)`       | `this`  | Mark the option as required                             |
| `.setAutocomplete(handler)`| `this`  | Attach an inline autocomplete handler (string/integer/number options only) |

### Example

```ts
.addStringOption((option) =>
  option
    .setName("reason")
    .setDescription("Reason of the ban")
    .setRequired(false)
)
```

### `.setAutocomplete()`

Attaches an inline autocomplete handler directly on the option — no separate handler file needed. Only available on **string**, **integer**, and **number** options.

```ts
type AutocompleteHandler = (
  query: string,
  interaction: AutocompleteInteraction,
) => AutocompleteChoice[] | Promise<AutocompleteChoice[]>

type AutocompleteChoice = string | number | { name: string; value: string | number }
```

The handler receives the user's current input (`query`) and the raw `AutocompleteInteraction`, and returns choices. Plain strings and numbers are used as both name and value; use the `{ name, value }` form to display a different label.

```ts
const FRUITS = ["apple", "banana", "cherry", "mango"]

export default new GlyriaCommand()
  .setName("eat")
  .setDescription("Eat a fruit")
  .addStringOption((option) =>
    option
      .setName("fruit")
      .setDescription("Which fruit?")
      .setRequired(true)
      .setAutocomplete((query) =>
        FRUITS.filter((f) => f.startsWith(query.toLowerCase()))
      )
  )
  .execute(async (ctx) => {
    await ctx.g.reply.success(`Yum, ${ctx.options.getString("fruit")}!`)
  })
```

The handler may be async — fetch from an API, the store, a database:

```ts
.setAutocomplete(async (query, interaction) => {
  const tags = await fetchTags(interaction.guildId)
  return tags
    .filter((t) => t.name.includes(query))
    .map((t) => ({ name: `🏷️ ${t.name}`, value: t.id }))
})
```

### `.getAutocompletes()`

Returns every autocomplete handler registered on the command (including nested subcommands and groups) as `AutocompleteEntry[]` — `{ name, handler }` pairs where `name` is the fully-namespaced key (`"command::option"`, `"command:sub::option"`, `"command:group:sub::option"`). Glyria calls this internally to route `AutocompleteInteraction`s; you rarely need it yourself.

## GlyriaSubCommand

Passed as argument in `.addSubCommand()` callbacks.

### Methods

| Method                   | Returns | Description                                             |
| ------------------------ | ------- | ------------------------------------------------------- |
| `.setName(name)`         | `this`  | Set the subcommand name                                 |
| `.setDescription(desc)`  | `this`  | Set the subcommand description                          |
| `.setCooldown(input)`    | `this`  | Cooldown for this subcommand (overrides the parent's)   |
| `.setPermissions(perms)` | `this`  | Runtime permission check for this subcommand (`PermissionName[]`, overrides the parent's) |
| `.setOwnerOnly(bool?)`   | `this`  | Restrict this subcommand to the bot owner (overrides the parent's) |
| `.addStringOption(fn)`   | `this`  | Add a string option                                     |
| `.addBooleanOption(fn)`  | `this`  | Add a boolean option                                    |
| `.addIntegerOption(fn)`  | `this`  | Add an integer option                                   |
| `.addNumberOption(fn)`   | `this`  | Add a number option                                     |
| `.addUserOption(fn)`     | `this`  | Add a user option                                       |
| `.addRoleOption(fn)`     | `this`  | Add a role option                                       |
| `.execute(handler)`      | `this`  | Set the subcommand handler                              |

Like the parent command, the subcommand handler receives a `GlyriaContext<ChatInputCommandInteraction>`, and options support `.setAutocomplete()`.

::tip{title="Guard precedence"}
Guards set on the parent `GlyriaCommand` apply to every subcommand; a guard set on the subcommand itself wins over the parent's for that subcommand.
::

::warning{title="Subcommand permissions are runtime-only"}
Discord only supports `default_member_permissions` at the command level, so `.setPermissions()` on a subcommand accepts a `PermissionName[]` and is enforced as a runtime check with a styled error — it does not hide the subcommand in the Discord UI.
::

### Example

```ts
.addSubCommand((cmd) =>
  cmd
    .setName("ban")
    .setDescription("Ban a user")
    .setPermissions(["BanMembers"])
    .setCooldown("3s")
    .addUserOption((option) =>
      option.setName("user").setDescription("User to ban").setRequired(true)
    )
    .execute(async (ctx) => {
      await ctx.g.reply.success("User banned.").ephemeral()
    })
)
```

## GlyriaSubCommandGroup

Passed as argument in `.addSubCommandGroup()` callbacks.

### Methods

| Method                  | Returns | Description                   |
| ----------------------- | ------- | ----------------------------- |
| `.setName(name)`        | `this`  | Set the group name            |
| `.setDescription(desc)` | `this`  | Set the group description     |
| `.addSubCommand(fn)`    | `this`  | Add a subcommand to the group |

### Example

```ts
.addSubCommandGroup((group) =>
  group
    .setName("config")
    .setDescription("Configuration commands")
    .addSubCommand((cmd) =>
      cmd
        .setName("logs")
        .setDescription("Configure logs")
        .addBooleanOption((option) =>
          option.setName("enabled").setDescription("Enable logs").setRequired(true)
        )
        .execute(async (ctx) => {
          await ctx.g.reply.success("Logs configuration updated.").ephemeral()
        })
    )
)
```
