## Overview

`GlyriaMessageCommand` is the builder used to define Discord message context menu commands. They appear when right-clicking on a message, under the **Apps** section.

```ts
export default new GlyriaMessageCommand()
  .setName("Translate")
  .execute(async (ctx) => {
    const message = ctx.targetMessage
    await ctx.reply({
      content: `Translating: "${message.content}"`,
      flags: djs.MessageFlags.Ephemeral,
    })
  })
```

::tip{title="Auto-import"}
`GlyriaMessageCommand` is available globally — no import needed.
::

## GlyriaMessageCommand

### Methods

| Method                   | Returns | Description                                    |
| ------------------------ | ------- | ---------------------------------------------- |
| `.setName(name)`         | `this`  | Set the command name                           |
| `.setPermissions(perms)` | `this`  | Restrict the command to specific permissions   |
| `.setCooldown(input)`    | `this`  | Add a per-user, per-guild, or global cooldown  |
| `.setOwnerOnly(bool?)`   | `this`  | Restrict the command to the bot owner          |
| `.setMetaData(meta)`     | `this`  | Attach custom metadata to the command          |
| `.execute(handler)`      | `this`  | Set the command handler                        |

::tip{title="No description, options or subcommands"}
Message context menu commands do not support descriptions, options, or subcommands — these are Discord API limitations.
::

### `.setPermissions()`

Restricts the command to members with specific Discord permissions. Accepts:

- a `bigint`, `number`, or `string` — used as-is as the Discord `default_member_permissions` bitfield
- a `PermissionName[]` array (e.g. `["ManageMessages"]`) — the names are OR-ed into the `default_member_permissions` bitfield **and** re-checked at runtime, denying with a styled ephemeral error listing the missing permission(s)

```ts
export default new GlyriaMessageCommand()
  .setName("Delete message")
  .setPermissions(["ManageMessages"])
  .execute(async (ctx) => {
    // only members with ManageMessages permission can use this
  })
```

### `.setCooldown()`

Adds a declarative cooldown. Accepts a duration string (`"5s"`, `"2m"`, `"1h"`), a number of milliseconds (both applied **per user**), or a `{ user?, guild?, global? }` object with a duration per scope. Members still cooling down get a styled ephemeral error with the remaining time.

```ts
export default new GlyriaMessageCommand()
  .setName("Translate")
  .setCooldown({ user: "10s", guild: "2s" })
```

### `.setOwnerOnly()`

Restricts the command to the bot owner. Defaults to `true` when called without arguments — non-owners get a styled ephemeral error.

```ts
export default new GlyriaMessageCommand()
  .setName("Dump message JSON")
  .setOwnerOnly()
```

### `.setMetaData()`

Attaches custom metadata to the command. Accepts any key-value object — Glyria stores it as-is and never interprets it.

```ts
export default new GlyriaMessageCommand()
  .setName("Translate")
  .setMetaData({
    category: "utility",
    cooldown: 5000,
  })
  .execute(async (ctx) => {
    // your logic here
  })
```

Metadata is accessible at runtime via `useCommands()`:

```ts
const commands = useCommands()
// [
//   { name: "Translate", description: "", meta: { category: "utility", cooldown: 5000 } },
// ]
```

::tip{title="useCommands"}
`useCommands()` is available globally — no import needed. The registry is populated automatically when the bot starts.
::

### `.execute()`

Sets the command handler. The handler receives a `GlyriaContext<MessageContextMenuCommandInteraction>` — the raw interaction (the targeted message is available via `ctx.targetMessage`) plus the `ctx.g` Glyria toolkit. See [ReplyableContext](/api-reference/replyable-context) for the full `ctx.g` API.

```ts
export default new GlyriaMessageCommand()
  .setName("Translate")
  .execute(async (ctx) => {
    const message = ctx.targetMessage
    await ctx.g.reply.info(`Translating: "${message.content}"`).ephemeral()
  })
```
