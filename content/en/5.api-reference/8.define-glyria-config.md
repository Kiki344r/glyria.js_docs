## Overview

`defineGlyriaConfig` is a typed helper to define your bot's global configuration in `glyria.config.ts` at the root of your project.

```ts
// glyria.config.ts
export default defineGlyriaConfig({
  modules: ["@glyria/economy"],
  moduleConfig: {
    economy: { startingBalance: 100 },
  },
  logChannel: "1234567890123456789",
  store: { adapter: "json" },
  changelog: { channel: "1234567890123456789" },
  dev: {
    restartPaths: ['composables', 'utils', 'services'],
    autoImportDirs: ['utils', 'composables']
  },
  theme: {
    embedV2: {
      primaryColor: "#5865F2",
      successColor: "#57F287",
      errorColor: "#ED4245",
      footer: {
        text: "My Bot • v1.0",
      }
    }
  }
})
```

::tip{title="Auto-import"}
`defineGlyriaConfig` is available globally — no import needed.
::

::tip{title="Hot reload"}
`glyria.config.ts` is hot reloaded in dev mode — no restart needed when you update your config.
::

## GlyriaConfig

Every key is optional.

| Key                 | Type                          | Description                                                            |
| ------------------- | ----------------------------- | ---------------------------------------------------------------------- |
| `modules`           | `string[]`                    | npm packages to load as Glyria modules                                 |
| `moduleConfig`      | `Record<string, unknown>`     | Per-module configuration, validated by each module's `config` schema   |
| `logChannel`        | `string`                      | Channel id where `ctx.g.log()` and framework notices are posted        |
| `store`             | `StoreConfig`                 | Built-in state store (`ctx.g.store`). Defaults to in-memory            |
| `recording`         | `boolean`                     | Record interactions to `.glyria/interactions` for `glyria replay`      |
| `changelog`         | `{ channel?: string }`        | Post a command changelog to this channel on every deployment           |
| `dev`               | `{ autoImportDirs?, restartPaths? }` | Dev mode watcher and auto-import configuration                  |
| `theme`             | `{ embedV2? }`                | Global theme for Embed V2 replies                                      |

### `modules`

npm packages to load as Glyria modules, in addition to the local `src/modules/` folder (which is always scanned automatically). For each package, Glyria imports `<pkg>/glyria.module.{ts,js}` or falls back to `<pkg>/index.{ts,js}`, and also auto-loads the package's `commands/`, `events/`, and `components/` folders.

```ts
export default defineGlyriaConfig({
  modules: ["@glyria/economy", "glyria-module-tickets"],
})
```

### `moduleConfig`

Per-module configuration, keyed by module name. Each entry is validated by the module's `config` schema (see [defineModule](/api-reference/define-module)); when absent, the module's `defaultConfig` is used.

```ts
export default defineGlyriaConfig({
  moduleConfig: {
    economy: { startingBalance: 100, currency: "🪙" },
    tickets: { category: "1234567890123456789" },
  },
})
```

::warning{title="Invalid config disables the module"}
If a module's schema rejects its `moduleConfig` entry, the module is disabled with an `invalid config` status — the bot keeps running.
::

### `logChannel`

Channel id where `ctx.g.log(message, level)` and framework notices are posted (styled with the theme's info/warning/error colors). Logging always goes to the console; the Discord channel is additional.

```ts
export default defineGlyriaConfig({
  logChannel: "1234567890123456789",
})
```

### `store`

Configures the built-in state store behind `ctx.g.store`, `ctx.g.guildConfig`, and `useStore()`. See [Store](/api-reference/store) for the full API.

| Option    | Type                                  | Default               | Description                                    |
| --------- | ------------------------------------- | --------------------- | ---------------------------------------------- |
| `adapter` | `"memory" \| "json" \| StoreAdapter`  | `"memory"`            | Storage backend, or a custom adapter instance  |
| `path`    | `string`                              | `.glyria/store.json`  | JSON file path when `adapter` is `"json"`      |

```ts
export default defineGlyriaConfig({
  // Zero-config persistence: in-memory with debounced JSON writes
  store: { adapter: "json", path: ".glyria/store.json" },
})
```

Pass any object implementing the `StoreAdapter` interface (`get`/`set`/`delete`/`keys`) to plug Redis, SQLite, or anything else:

```ts
import { myRedisAdapter } from "./services/redisStore"

export default defineGlyriaConfig({
  store: { adapter: myRedisAdapter },
})
```

### `recording`

Records incoming interactions to `.glyria/interactions` so they can be replayed with `glyria replay`. Always on in dev mode; set this to enable it in production.

```ts
export default defineGlyriaConfig({
  recording: true,
})
```

### `changelog`

When `channel` is set, Glyria diffs the deployed commands against the previous snapshot (`.glyria/commands.snapshot.json`) on every deployment and posts a changelog (added / removed / changed commands) to that channel.

```ts
export default defineGlyriaConfig({
  changelog: {
    channel: "1234567890123456789",
  },
})
```

### `dev`

Configuration for the dev mode watcher and auto-imports.

| Option           | Type       | Default                                | Description                                          |
| ---------------- | ---------- | -------------------------------------- | ---------------------------------------------------- |
| `restartPaths`   | `string[]` | `['composables', 'utils', 'services']` | Folders that trigger a full bot restart when changed |
| `autoImportDirs` | `string[]` | `['utils', 'composables']`             | Folders scanned for auto-imported globals            |

By default, Glyria watches your `src/` folder and applies the following behavior:

| Folder                 | Behavior                                                      |
| ---------------------- | ------------------------------------------------------------- |
| `commands/`            | Hot reload — commands are re-registered instantly, no restart |
| `events/`              | Hot reload — listeners are removed and re-added instantly     |
| `restartPaths` folders | Full restart — bot process is cleanly killed and restarted    |
| Everything else        | Ignored                                                       |

::tip{title="Why restartPaths?"}
Files in folders like `utils/` or `services/` are loaded once at boot and can't be hot reloaded safely in ESM. A clean restart is the safest option.
::

::warning{title="Nested imports"}
If a command imports a file from `utils/`, modifying that file will trigger a restart (if `utils` is in `restartPaths`) — but if it's not, the old module may still be cached. Add the folder to `restartPaths` to ensure a clean reload.
::

#### `autoImportDirs`

Folders listed in `autoImportDirs` are scanned at startup — every `export const`, `export function`, and `export class` found is injected into the global scope automatically.

Write folder names without `src/` or `dist/` prefix — Glyria resolves the correct path depending on the environment.

```ts
export default defineGlyriaConfig({
  dev: {
    autoImportDirs: ['utils', 'composables', 'helpers', 'lib']
  }
})
```

::tip{title="src/index.ts"}
Exports from `src/index.ts` are always scanned automatically — no configuration needed.
::

### `theme.embedV2`

Global theme applied automatically to all embeds built with `EmbedV2Builder` and every styled `ctx.g` send.

| Option           | Type             | Default   | Description                             |
| ---------------- | ---------------- | --------- | --------------------------------------- |
| `primaryColor`   | `HexColorString` | `#5865F2` | Color for `.g.reply.primary()`          |
| `secondaryColor` | `HexColorString` | `#4F545C` | Color for `.g.reply.secondary()`        |
| `successColor`   | `HexColorString` | `#57F287` | Color for `.g.reply.success()`          |
| `errorColor`     | `HexColorString` | `#ED4245` | Color for `.g.reply.error()`            |
| `infoColor`      | `HexColorString` | `#5DADE2` | Color for `.g.reply.info()`             |
| `warningColor`   | `HexColorString` | `#FEE75C` | Color for `.g.reply.warning()`          |
| `footer.text`    | `string`         | —         | Footer text appended to every container |

#### Colors

Colors are defined as hex strings (`HexColorString` from discord.js):

```ts
primaryColor: "#5865F2"  // ✅
primaryColor: 0x5865F2   // ❌ use hex string, not number
```

#### Footer

When `footer.text` is set, it is automatically appended to every `ContainerBuilder` when `.end()` is called — no extra code needed in your commands.

```ts
theme: {
  embedV2: {
    footer: {
      text: "My Bot • v1.0"
    }
  }
}
```

## Full example

```ts
// glyria.config.ts
export default defineGlyriaConfig({
  modules: ["@glyria/economy"],
  moduleConfig: {
    economy: { startingBalance: 100 },
  },
  logChannel: "1234567890123456789",
  store: { adapter: "json", path: ".glyria/store.json" },
  recording: true,
  changelog: { channel: "9876543210987654321" },
  dev: {
    autoImportDirs: ['utils', 'composables', 'helpers'],
    restartPaths: ['composables', 'utils', 'services']
  },
  theme: {
    embedV2: {
      primaryColor: "#7289DA",
      secondaryColor: "#747F8D",
      successColor: "#43B581",
      errorColor: "#F04747",
      warningColor: "#FAA61A",
      infoColor: "#00B0F4",
      footer: {
        text: "My Bot • v1.0"
      }
    }
  }
})
```
