Smaller exports of `@glyria/bot` that power the framework's features — all importable for your own tooling.

## Durations

The same parser used by `.setCooldown()`, `confirm()`, and `paginate()` timeouts.

### `parseDuration(input)`

```ts
import { parseDuration } from "@glyria/bot"

parseDuration("5s")    // 5000
parseDuration("2m")    // 120000
parseDuration("1.5h")  // 5400000
parseDuration(250)     // 250 (numbers pass through as ms)
```

| Parameter | Type | Description |
|---|---|---|
| `input` | `Duration` (`number \| string`) | Milliseconds, or a string with an `ms`, `s`, `m`, `h`, or `d` suffix |

Throws on invalid input (negative numbers, unknown suffixes like `"5w"`).

### `formatDuration(ms)`

Formats milliseconds into a compact human string, rounding **up** to the next second — used for "try again in X" cooldown messages.

```ts
formatDuration(1_001)     // "2s"
formatDuration(90_000)    // "1m 30s"
formatDuration(3_900_000) // "1h 5m"
```

## Interaction recorder

The API behind [time-travel debugging](/cli/replay). Interactions are recorded automatically in dev (or with `recording: true`) to `.glyria/interactions/<id>.json`.

| Function | Returns | Description |
|---|---|---|
| `recordInteraction(entry)` | `void` | Writes a `RecordedInteraction` to disk (best-effort — failures are logged, never thrown) |
| `readRecording(id)` | `RecordedInteraction \| null` | Loads one recording by interaction id |
| `listRecordings()` | `RecordedInteraction[]` | All recordings, most recent first |

### `RecordedInteraction`

| Field | Type | Description |
|---|---|---|
| `id` | `string` | Discord interaction id (the file name) |
| `key` | `string` | Resolved handler key, e.g. `"config:theme:set"` |
| `kind` | `"chat" \| "user" \| "message"` | Command kind |
| `userId` / `username?` | `string` | Invoking user |
| `guildId` / `channelId` | `string \| null` | Where it ran |
| `options` | `Record<string, unknown>` | Flat option values by name |
| `subcommand` | `string[]` | Subcommand path (`["theme", "set"]`) |
| `createdAt` | `number` | Timestamp |
| `replies` | `{ via, payload, timestamp }[]` | Everything the handler sent |
| `error?` | `string` | Present when the handler threw |

Pair with [`createTestContext()`](/api-reference/create-test-context) to build your own replay tooling:

```ts
import { readRecording, createTestContext } from "@glyria/bot"

const recording = readRecording("1234567890")!
const ctx = createTestContext({
  userId: recording.userId,
  guildId: recording.guildId,
  options: recording.options,
  subcommand: recording.subcommand,
})
```

## Command diffing

The diff engine behind the [smart re-register](/guide/commands) and the [auto-changelog](/guide/production).

### `diffCommandBodies(prev, next)`

Compares two command payload arrays by name and serialized content.

```ts
import { diffCommandBodies, isDiffEmpty } from "@glyria/bot"

const diff = diffCommandBodies(previousCommands, currentCommands)
// { added: ["new-cmd"], removed: ["old-cmd"], changed: ["edited-cmd"] }

if (isDiffEmpty(diff)) {
  // nothing to deploy
}
```

| Export | Type | Description |
|---|---|---|
| `diffCommandBodies(prev, next)` | `CommandsDiff` | Named commands added / removed / changed between two deployments |
| `isDiffEmpty(diff)` | `boolean` | True when nothing changed |
| `CommandsDiff` | `{ added: string[]; removed: string[]; changed: string[] }` | The diff shape |

## Module helpers

Lower-level pieces of the [Module SDK](/api-reference/define-module), useful for building custom tooling around modules.

| Export | Description |
|---|---|
| `isModuleDefinition(value)` | Type guard — true when `value` is a branded `defineModule()` result. The loader uses it to validate default exports |
| `resolveLoadOrder(definitions)` | Topologically sorts module definitions by `dependsOn`. Returns `{ order, failed }` where `failed` lists modules with missing dependencies or cycles (and why) |
| `LoadedModule` *(type)* | A module's runtime record inside `ModuleManager`: `definition`, `status`, `api`, `context`, `errorCount`, `statusReason` |
| `CommandGuards` *(type)* | The declarative guard shape attached to command handlers: `{ cooldown?, permissions?, ownerOnly? }` — set via [`setCooldown` / `setPermissions` / `setOwnerOnly`](/api-reference/glyria-command) |

```ts
import { resolveLoadOrder } from "@glyria/bot"

const { order, failed } = resolveLoadOrder(definitions)
// order: dependency-safe load order
// failed: [{ name: "shop", reason: 'missing dependency "economy"' }]
```
